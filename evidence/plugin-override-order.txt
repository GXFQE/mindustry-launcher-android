# 第 134 轮证据：多个插件的覆盖顺序（真机两遍，顺序对调）

问题（用户 2026-10-12）：「多个插件覆盖顺序怎么计算，按照禁用顺序反过来吗？」

**先给结论（都有真机观测）**：
1. **跟"禁用顺序"没有任何关系** —— 停用只是把某个 id 从 `active.txt` 里抽掉；顺序只由**登记表的文件顺序**决定。
2. **注入顺序 = `active.txt` 的文件顺序**（`stateIds` 保序、不排序），而每个插件都是**前插**
   （`Reflect.injectDex(..., prepend=true)` 把新 elements 拷到 `dexElements` 头部）
   ⇒ 数组里**"文件里靠后的"排在前面**。
3. **谁赢 = 那个类名第一次被解析的那一刻，数组里最前的那个插件**。于是**同一个进程里两套类可以分属两个插件**：
   - **入口类**（`io.mdt.plugtest.PlugPage`）：注入循环里那句自查 `host.loadClass(ENTRY)` **当场就把它定义掉了**
     ⇒ 永远归**文件里第一个**插件；**后面的插件点「打开」渲染的是第一个插件的页**（真机拍到）。
   - **其它同名类**（注入循环之后才第一次被用到，如 `io.mdt.launcher.PluginProbe`）⇒ 归**文件里最后一个**插件。

## 夹具（本轮给入口页加了编译期 tag，才让它"看得见"）

`tools/plugtest/src/io/mdt/plugtest/PlugPage.java` 新增 `tag()`（`build.sh` 把 `__TAGPAGE__` 按变体替换），
`createView` 把 tag 打补进页面文字 ⇒ 页面上直接读得出"这个类是哪个变体渲染的"。
（原来只能靠 `PluginProbe` 那对同名宿主类的 tag，而它只能证明"某个类归谁"，证明不了**入口页**。）

## 两遍实验（同一套夹具，只把安装顺序对调）

| 观测量 | 第一遍：`aa`=v1 先装、`bb`=v2 后装 | 第二遍：`q1`=v2 先装、`q2`=v1 后装 |
|---|---|---|
| `active.txt` | `aa=1 bb=1` | `q1=1 q2=1` |
| `PluginProbe`（注入**之后**才解析） | **`PLUGIN-v2`**（= 后装那个） | **`PLUGIN-v1`**（= 后装那个） |
| 入口类 —— 点**文件里靠前**那个 | 点 `aa`(v1) ⇒ 页面 `[PLUGIN-v1]` = **它自己** | 点 `q1`(v2) ⇒ 页面 `[PLUGIN-v2]` = **它自己** |
| 入口类 —— 点**文件里靠后**那个 | （未测） | 点 `q2`(v1) ⇒ 页面 **`[PLUGIN-v2]`** = **q1 的类** ⇒ 🔴 点 q2 开的是 q1 |

```
host tag Probe 实测（两遍方向相反 ⇒ 不是偶然）:
  [aa(v1) 在前, bb(v2) 在后] host tag PluginProbe  = PLUGIN-v2   (shell's own = SHELL)
  [q1(v2) 在前, q2(v1) 在后] host tag PluginProbe  = PLUGIN-v1   (shell's own = SHELL)
启动报告（第一遍）: active = aa=1 bb=1 → 两个都 INJECTED entry=OK api=1
```

## 这推翻了什么（本工程那条规矩的又一例）

上一轮我**按源码外推**说："装两个插件时点 B 的「打开」会渲染 A 的页（B 是后装的）" ——
**方向和机制都错了**。真实情况是：
- 入口类**在注入循环里就被第一个插件定义掉**（那句自查 `loadClass` 就是"第一次解析"），
  ⇒ 吃亏的是**后面**那些插件（点 q2 开 q1）；
- 而且 `entry=OK api=<n>` 这行报告在多插件下**不保证是"这个插件自己的"**（同一个 FQN 只会定义一次）。
⇒ 与 `ref/29` 里"按源码判定必须再补一次真机实验"完全同型。

## 顺带说明（现状有多"没设计"）

- 没有任何**显式优先级**字段；自检里**没有**一条断言钉住注入顺序（我查过）⇒ 顺序是隐式的、没人守。
- **官方/第三方（第 133 轮那套信任模型）完全不参与"谁能盖谁"** —— 第三方只要后装就能盖掉官方。
- `statePut` 是**原地替换、保序**；新 id **追加到末尾** ⇒
  「新装的优先级最高」·「给已有插件换版本不改位置」·「停用/删除不打乱其余相对顺序」·「回滚按同顺序重写」。
- 所有插件的入口类是**同一个 FQN**（`PluginHost.ENTRY`）⇒ **"多插件"目前只是名义上的**：
  只有文件里第一个插件的入口真正生效。
