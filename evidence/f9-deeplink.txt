--- 1. 编译后的清单（aapt2 dump xmltree，与官方逐条对照）---
我们 MainActivity 的两组 filter（编译产物）：
  content 组：scheme=content + mimeType=application/octet-stream / application/x-msav / application/zip
  file    组：scheme=file + mimeType=*/* + pathPattern=.*\.msav / .*\.msch / .*\.zip
官方 [Android][v160]Mindustry.apk 的 mindustry.android.AndroidLauncher：
  scheme=mindustry · scheme=content + octet-stream / x-msav · scheme=file + */* + pathPattern=.*\.msav
★ 本轮真踩的坑：源里写 `.*\.msav`（**一个**反斜杠）时，aapt2 把它编译成 `.*.msav`（反斜杠被当转义吃掉），
  而官方 dump 是 `.*\.msav` ⇒ 源里必须写 `\\.`。aapt2 / 编译器对此**一声不响**。
  ⇒ 自检用 `xmsav` / `xXmsav` 两条反方向当尺子（写坏成 `.*.msav` 时这两条会被匹配上 ⇒ 判死）。

--- 2. 清单匹配（cmd package query-activities —— 问的是**装在这台机器上**的那一份）---
content://x/y        + application/octet-stream → Activity #16，含 io.mdt.launcher.MainActivity
file:///sdcard/x.msav + */*                    → Activity #91，含我们
file:///sdcard/x.txt  + */*                    → 不含我们（反方向）
file:///sdcard/xXmsav + */*                    → 不含我们（pathPattern 的尺子）
★ 系统实际会开谁（cmd package resolve-activity --brief）：
  content://… + octet-stream → com.hihonor.android.internal.app/.HwResolverActivity（选择器）
  file://…    + */*          → com.hihonor.fileservice/.filepreview.view.PreviewActivity（isDefault=true，ROM 自带预览）

--- 3. pathPattern 的第二个坑（本机 ROM；三方对照）---
file:///sdcard/x.msav          → 我们 ✓ · 官方 Mindustry ✓ · MindustryX ✓
file:///sdcard/x.y.msav        → 三者全 ✗
file:///sdcard/foo.bar/x.msav  → 三者全 ✗
file:///storage/emulated/0/Android/data/io.mdt.launcher/hub/dl/sample.msav → 我们 ✗（路径里有 `io.mdt.launcher` 的两个点）
⇒ **路径里多一个点就不匹配**；官方那两个包（同一形状的 filter）表现与我们**完全一致**
  ⇒ 这是系统的 `pathPattern` 行为，不是我们清单抄错。
