■ 结论（一句话）
`mod-<名字>-failed` **不是"这个模组崩了"**，而是「**上次启动没跑完、游戏把整槽模组关掉时，
它本来是开着的**」——槽级事件的副产品；真正发生的事是 `mod-<名字>-enabled` 被写成 **false**
（模组被关掉），用户得重新启用。

■ 证据 ①（源码）`素材\Mindustry本体\Mindustry-master.zip` → core/src/mindustry/Vars.java
    public static void checkLaunch(){                        // 启动最早调用
        launchIDFile = settings.getDataDirectory().child("launchid.dat");
        if(launchIDFile.exists()) failedToLaunch = true;     // 上次没删掉 ⇒ 上次没跑完
        else { failedToLaunch = false; launchIDFile.writeString("go away"); }
    }
    public static void finishLaunch(){                       // 只有这次真跑起来才删
        ... if(launchIDFile != null) launchIDFile.delete();
    }

■ 由机制推出的四条（这次文案全按它们改）
 1. `-failed` 不是按模组归因 ⇒ 列表**不许**按行显示"它出过错"（§85.16 的根因）；门的说明也不许说
    "游戏把它标成失败"。
 2. 真正的后果是「**整槽模组被关掉**」⇒ 摘要卡改成「下次启动游戏会把整槽模组都关掉」；
    跳过已发生那支给出动作「点「启用」可以重新打开」。
 3. 游戏自己的开关**只在状态变化时**才清标记 ⇒「已启用 + 带标记」时点启用是**空操作**
    （用户正是这个状态）⇒ 我们**成对写**（`-enabled` + `-failed=false`），且"已启用但带标记"
    **不算空操作**。
 4. 跳过前提 = `launchid.dat` 在 **且** `modcrashdisable` 开（默认 true）⇒ 门的三支建议：
    还会跳 ⇒ 关掉点名那个模组 / 关掉跳过开关；关着 ⇒ 点启用；开着且不会再跳 ⇒ 会再试它。

■ 追加：详情页那个 **null** 是哪来的（2026-10-08，用户真机截图：「这个null是哪来的，还有现在还是乱的」）
症状（模组被关掉时）：
    ❌ 游戏里是启用状态
        null
根因（`Mods.java` 原第 2061 行）：
    out.add(new Gate(..., m.enabled, m.settingsKnown ? null : <说明>));
  → **说明只跟着"设置读没读到"**，跟"这道门通没通过"无关 ⇒ 模组被关掉时不通过、原因却是 null，
    而详情页的格式是「❌ 标签 + 换行 + 原因」（`mods_detail_gate_fail_fmt`）⇒ 直接印出 null。
  ⚠️ 自检里那把"不通过必须给原因"的尺子**只喂了启用中的夹具**（`mkMod(..., true)`）⇒ 一直没抓到。
改法：
  · 「游戏里是启用状态」那道门按**通过 / 不通过**给原因，并把「点「启用」」这个动作**收在它这里**
    （它才是"这个模组开没开"的判据）：关掉的 ⇒「它被关掉了 —— 点「启用」就能打开」；
    设置没读到 ⇒「设置文件还没读出来，拿不到它的开关状态」（新键 `mods_gate_enabled_unknown`）。
  · 「上次启动」那道门**不再**说「点启用」（两处都说 = 同一屏重复，用户说的"乱"有一部分就是它），
    只说机制：还会再跳 ⇒「下次启动还会关掉整槽模组 —— 先关掉点名那个模组，或关掉「启动崩溃后禁用模组」」；
    否则 ⇒「那次游戏把整槽模组都关掉了（这条记录还在）」。
  · 删掉 `mods_gate_last_crash_off`（那个动作搬走了）。
自检新增（985 / 0 失败）：
  · ★★元断言：**六种状态**（启用/关掉/有记录/设置没读到/还会跳/最坏组合）下逐门检查 ——
    有标签、**不通过必有原因**、原因里**不许出现 null**、**说明 ≤ 40 字**（超了会把六道门挤成一屏）
  · ★★「上次启动」那道门**任何状态下**都不说「点启用」
  · ★动作落在**对的门**上（关掉的模组在"游戏里是启用状态"那道门拿到「启用」；开着的那道门通过）
真机复验（用户槽 `模组演示`，Dir Mod Demo 被关掉那个状态）：`null` 文本节点 = **0**；
