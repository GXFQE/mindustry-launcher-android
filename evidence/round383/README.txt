第 383 轮证据：把「可以清理的」并成一个动作
============================================

用户原话：
  「最底下那个可以清理的残留是什么鬼啊」
  「还有我们是不是应该把自动清理残留和这个合并」
  「反正这些都是可以自动清理的，不如合并到一起」

结论：存储占用卡上原来的「清理游戏缓存」「清理分享缓存」两个按钮 + 底部
「可以清理的残留」一段 + 设置页「自动清理残留 → 立即清理一次」，合成**一个「清理」**。
设置页只留「旧版本重复文件」的自动开关（并改名 + 加解释），手动清理跟着数字走。

改动
----
- 新增 `Cleanup`：一个动作 = 游戏缓存（`CacheClean`）+ 分享缓存（`ShareOut.prune`）+
  旧版本重复文件（`Data.autoCleanRedundant`）。三样各自仍走原来的唯一实现，本类只编排与计数；
  游戏在跑时只跳过游戏缓存，分享 / 重复文件照清。
- `Storage`：不再调 `healthScan`、不再有 `redundantPlaces/Bytes`、不再列「可以清理的残留」
  （存储页只回答"空间被什么占了"；顺带少一次全盘扫描）。
- `SettingsActivity`：存储卡只留「清理 / 关闭」；设置行改名「旧版本重复文件」，
  点击弹解释 + 自动开关（不再有「立即清理一次」）。
- `PluginData.storage()`：插件 API 的 `redundant` 键保留，改为按需现算（storage() 本来就是重接口）。
- 删掉 19 个只服务于旧两个按钮 / 旧残留行的字符串；新增 9 个。

自检
----
`selftest-383.txt` = **2306 项通过 / 0 失败**（第 382 轮基线 2304；
+统一清理 3 条 +文案 1 条，-旧的分享按钮断言 1 条 -残留行断言 1 条）。
新增：
  ✅ ① 一个动作跑完三样（缓存 / 分享 / 重复文件），并合计释放量
  ✅ ② 游戏在跑 ⇒ 只跳过游戏缓存，分享 / 重复文件照清
  ✅ ③ 没东西可清时 any()=false（界面说「没有可清理的」）
  ✅ ★第 383 轮：一个「清理」的确认文案说清三样 + 不动的数据

真机验收（详见 `cleanup.txt`）
-----------------------------
- 假 `files/config.json`（HUB 配置键）→ 清理 → `dup=1/21B`，文件消失。
- 假 `files/import/fake.apk`（1 B）→ 清理 → `dup=1/1B`，整个 import 目录消失。
- Toast 实拼：「已清理，释放约 1 B（缓存 0 项 · 分享 0 份 · 重复文件 1 处）」。
- 存储卡只剩「清理 / 关闭」，没有「可以清理的残留」一段。
- 设置行「旧版本重复文件 / 自动清理：开」，点开有解释与「关掉自动清理 / 关闭」。
