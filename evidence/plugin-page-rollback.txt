## 1) 回滚 —— 用**真实失败形态**走一遍（不是手写 guard）

```
[1] 装 v1（好插件，立刻生效） ⇒ 重开 ⇒ 注入成功、启动走完
    active.txt = probe=1     known.txt = probe=1     injected.txt = probe=1

[2] 装 v2（会崩的那一版）⇒ 写 pending.txt = probe=2

[3] 重开 ⇒ pending 提升成 active=probe=2 → 注入 v2 → api() 杀进程
    （进程死、界面没起来 ⇒ guard.txt 留着）

[4] 再重开（系统按原任务又拉了一次）⇒ 安全阀拦下 + 回滚：

report-plugin-boot.txt:
  == plugin early inject ==
  time     = Mon Oct 12 17:25:27 GMT+08:00 2026
  SKIPPED: previous launch with plugins did not finish
  active was = probe=2
  -> nothing injected; rolled back to probe=1

lastskip.txt（结构化：id ⇥ 失败版本 ⇥ 回滚到 ⇥ rollback|disable）:
  probe	2	1	rollback

lastfail.txt（现场原文）:
  == plugin skip (previous launch did not finish) ==
  time      = Mon Oct 12 17:25:27 GMT+08:00 2026
  guard     = == plugin early inject == time = ... pid = 2232 active = probe=2
  active    = probe=2
  known     = probe=1
  rollback  = probe=1
  -> rolled back to the last known-good version

active.txt = probe=1

[5] 再重开 ⇒ 回滚回去的那一版**真的能用**：
  == plugin early inject ==
  time   = Mon Oct 12 17:25:48 GMT+08:00 2026
  pid    = 2550
  active = probe=1
  - probe=1 file=1.apk INJECTED elems=2 [...] entry=OK api=1
  injected = 1 / 1
  pidof = 2550（3/6/9/12 秒四次采样都是它 ⇒ 没有再死）
```

保留策略（成功启动后 prune）：`app_hub/plugins/probe/` 里留着 `1.apk`（已知可用）+ `2.apk`（失败现场，
界面的「把插件重新启用」要能再试一次）。

## 3) 三个状态 + 动作（都在界面上点过）

```
点那一行 ⇒ 弹窗：[160,906] probe ｜ 打开 ｜ 启用（退出重开生效）｜ 停用（退出重开生效）｜ 删除 ｜ 取消
「打开」 ⇒ 页面变成：
   返回
   已加载 1.apk（接口版本 1）
   来自插件的字符串          ← 插件**自己的资源**真的挂上了
「停用」 ⇒ 该行 = probe · 已停用（上次生效 v1）（active/pending 都清空）
「启用」 ⇒ 该行 = probe · 退出重开生效 v2（pending.txt = probe=2）
「删除」 ⇒ 该行消失，页面显示"还没有装插件。"，app_hub/plugins/probe/ 整个没了
```
