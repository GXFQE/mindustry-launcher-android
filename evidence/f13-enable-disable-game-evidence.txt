判据 = 游戏自己写的 <数据根>/last_log.txt 里有没有这一行：
        [I] Loading mod: Demo Mod
   （`Mods.java:1210` 的 `Log.info("Loading mod: @", meta.name)` —— 它只取决于
     `skipModLoading()` 与 `mod-<内部名>-enabled` 这个键，**不取决于版本门/类加载**，
     所以它是"游戏读到的开关值"的**直接读出**。每次启动前都删掉 launchid.dat，
     否则 `skipModLoading()` 会把所有模组一起跳掉、把这条判据毁掉。）

── 三步对照 ────────────────────────────────────────────────────────────
① 基线（键不存在 ⇒ 默认 true）
   grep 'Loading mod' last_log.txt  →  命中：`[I] Loading mod: Demo Mod`
② App 写入 `mod-demo-mod-enabled = false`
   dev 口：--es dev_mods_toggle f13-write --es dev_mods_name demo-mod -e dev_mods_on false

         体积：482 → 506 B（差 25 字节 = 追加键 23 B + count 字段变 1 B + 长度差）
         键数：24（未知键原样保留）· 写后自检：通过（恰好 EOF + 所有键逐条比对一致）
         改前备份：hub/settings-backups/slot-f13-write/20261002-212219.bin（482 B）
   grep 'Loading mod' last_log.txt  →  **0 命中**（游戏确实把它关掉了）
③ 再写回 true
   报告：✅ 已启用模组「demo-mod」 —— mod-demo-mod-enabled: false → true
         体积：506 → 506 B（**差 1 字节**）· 自检通过
   grep 'Loading mod' last_log.txt  →  命中：`[I] Loading mod: Demo Mod`（又回来了）

── 神谕闭环（arc 自己的 Settings 读**设备上**那份文件）────────────────────
把设备上的 slot-f13-write/settings.bin（506 B，md5 acf75f2429bd2b79bbbb0007399af53e）
拉到 PC，用 `_lab/hjson/out159` 的 `SettingsOracle` 读：

  KEY  mod-demo-mod-enabled   bool=false        ← 我们写的值（游戏自己的读取器认了）
  KEY  lastBuild              int=159           ← 游戏在 finishLaunch 里加的键

★ `lastBuild` 的出现说明这份文件**已经被游戏自己整份重写过**（`finishLaunch` 会写它），
  而我们的键**存活了下来、值也没变** ⇒ 「我们写 → 游戏读 → 游戏整份重写 → 我们/神谕再读」
  这条完整环路是通的。
