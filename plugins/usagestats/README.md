# usagestats（官方插件，v13，第 254~256 轮；第 384 轮改宿主时钟；第 388 轮分开补丁；
# 第 396 轮记每局流水；第 400/401 轮统计面板）

游戏**前台时长**：宿主在 `:game` 里用 `SessionClock` 记这一局（前台累计），退出时通过
`game-exit` 事件交一次；插件只负责把 `activeMs` 追加进自己的账本，数据落在插件自己的 `data/`。
展示放在宿主页面里：

> ★ 第 396 轮起另记一份**每局流水**（`sessions.tsv`，一行一局、带起止时刻）：账本只有累计值，
> 按天 / 单日分析要从起止时刻现算。
> ★ 第 400 轮起**统计面板进插件页**（宿主已有的 `PluginsActivity` 直达）：主界面「游戏时长」行尾
> 的 inline 按钮「统计」点进去，`api.page()` = `"panel"`。

> ⚠️ 接口版本 **47**：本插件用了 v46 的 `slot: inline`（行内插入）与 v47 的 `pickDate`
> （宿主代弹日期选择器；插件自己 `new DatePickerDialog` 会崩）。旧宿主会明确拒绝，
> 而不是静默不显示入口；`plugin.json` 的 `"api": 47` 也会让宿主自动更新在**下载前**就跳过这一版。

- **槽页**（`slot: section` + `page: slot`）：一张「游玩时长」卡 —— 本槽合计 + **按游戏版本**分列；
  ★ 2026-11-11 起它在**所有动作行之后**（用户：「槽页面那个游玩时长建议放在所有按钮的下面」）；
  已装游戏原地更新后，更新前后是**两行**（老版本的时间不会被新版本顶走）；
  ★ 第 388 轮起**本体 + 补丁 ≠ 本体**：带补丁的一局单独一行，行名是
  带补丁行：`版本 · 半改端 · 版本号 · 补丁名`（补丁名用 ref 的 id（如 `mdtx-1607`，不是 manifest 的展示名）；快照丢了就只留 `半改端`）；
- **主界面摘要卡**：总时长一行（`plugin.json` 的 `playtimeTotal` 声明一个整数文件，宿主只排版）。
- **主界面「游戏时长」行尾**：v46 inline 按钮「统计」→ 宿主插件页（`page = "panel"`）。
- **插件页统计面板**（第 400/401 轮）：**范围 × 粒度**的热力图 ——
  - 范围：1 / 7 / 30 / 90 / 365 天 / 全部 / 自定义（系统日期选择器选起止）；
  - 粒度：**时**（24 列）/ **日**（7 列）/ **周**（13 列）/ **月**（12 列）；
  - 对齐：日档从起点所在周的**周一**、时档从**范围起点当天 0 点**（1 天 = 1 行，不补周一的空行）、
    周档从**季度首周**、月档从**1 月**；
    对齐空位与「记录起点之前」**不画**，统计范围内每格都画（没玩过 = 最浅底 + **描边**）；
  - **横纵轴**：顶部列标签（时 0/6/12/18、日 一~日、周 1/7/13、月 1/4/7/10），
    左侧行标签（日期 / 年份，行多时隔行标）；
  - 行数 = ceil(格数 / 列数)，**上限 366 行**；超了**拒绝并提示**（不自动降档）；
  - **范围比粒度还短 ⇒ 拒绝并提示**（如「月档 + 7 天」），不会只画一格；
  - 范围边界按墙钟比例**裁剪**（周 / 月档的格被范围截断时只算范围内那部分，误差 ≤ 1ms）；
  - **颜色档位可自定义**：每个粒度 4 个分钟阈值（第 2/3/4/5 档下界），存 `data/levels.txt`；
    默认都**不超过一格**（时 10/20/40/55、日 30/60/120/240、周 60/180/420/840、月 120/360/900/1800），
    自定义超过一格（如时档填 120）会被拒绝并提示 —— 否则最高档永远到不了；
  - **只有图区滚动**（固定高度约 420dp，默认滚到最新）；头部 / 合计 / 档位固定；
  - **按实例筛选（多选）**（第 401 轮）：一行「全部 / 已选 N 个 ▾」按钮，点开在页面里展开勾选列表
    （每个 `版本 · 槽` 一行，**默认全勾**；点一下 = 取消该实例，再点恢复；全部勾上时显示「全部」）；
    合计与热力图只算没被取消的实例；实例列表从 `sessions.tsv` 的 `(key, slot)` 去重来，
    版本名反查 `api.versions()`；
  - 范围 / 粒度**不持久化**：每次进页面回到「近 30 天 · 日」（实例筛选同样默认「全部」）。

## 组成

| 文件 | 作用 |
|---|---|
| `UsageStats.onEvent` | `game-exit` 条目：收宿主给的 `activeMs` + `key`，追加**账本**与总数；第 396 轮起再追加一行**流水** |
| `UsageStats.createView` | 槽页的 section（本槽合计 + 按版本分列，同名版本显示层合并；默认全部收起，可展开 / 收起）；同时是插件自述的默认入口（插件页长按「打开」看总计 + 按槽分列） |
| `core/Playtime` | 纯函数：账本解析 / 写回 / 求和 / 按槽分组 / 显示层同名合并 / 毫秒→时分（PC 侧可测） |
| `core/Sessions` | 纯函数：每局流水解析 / 落盘 / **按天** / **按小时**切分（第 396 轮；PC 侧可测） |
| `core/Heat` | 纯函数：**范围 × 粒度**网格 / 对齐 / 裁剪 / 档位（可自定义）/ 精度拒绝 / 合计（第 400/401 轮；PC 侧可测） |
| `HeatView` | 热力图：rows × cols 正方形格 + 横纵轴标签 + 每格描边（第 400/401 轮） |
| `tools/Check.java` | PC 侧判据自检（`build.sh check`；覆盖 10 列 / 旧 8 列 / 补丁分行 / 每局流水 / 热力网格） |

## 数据（都在 `<插件>/data/`，`api.dataDir()`）

```
ledger.tsv   10 列 TSV，一行一个「槽 + key + 版本号 + 补丁身份」（累计毫秒）
sessions.tsv 9 列 TSV，一行一局（起止时刻 + 前台毫秒 + 身份）—— 第 396 轮
total.txt    一个整数毫秒（所有槽合计；主界面摘要卡读它）
```

`sessions.tsv` 每行：

```
started \t ended \t activeMs \t wallMs \t exit \t slot \t key \t tag \t patch
```

| 列 | 内容 |
|---|---|
| started | 这一局的**开始墙钟**毫秒（宿主 `SessionClock`；没有就不记 —— 归不到「哪一天」） |
| ended | 最后一拍墙钟（最多早 20 秒；`ended < started` 按同一刻算，防改系统时间） |
| activeMs | 这一局游戏 activity 在**前台**的累计（与账本同一口径） |
| wallMs | ended - started（冗余；解析时以 ended - started 为准） |
| exit | `clean` / `crash` / `unclean` / `launch-failed`（第 394 轮起；拿不准为空，**不是**「正常」） |
| slot / key / tag / patch | 这一局的身份与版本快照（与账本同源；patch 为空 = 本体） |

- **一行一局、只追加**（不读改写）：一年几千局 ≈ 几十 KB；坏行解析时跳过。
- **去重**：最后一行的核心字段（started / ended / activeMs / key）与本次完全一致 ⇒ 视为宿主
  重复派发，跳过（`exit` 不同也算同一局 —— 补报可能不带这个键）。
- **按天 / 按小时**：`core/Sessions` 从流水现算 —— 一局跨零点（或挂机跨好几天）按**墙钟
  区间比例**摊 `activeMs`，最后一段补余数 ⇒ 各段之和**恒等于** `activeMs`（Check 钉住）。
  日期 / 小时一律按**设备本地时区**切；「会话数」按**开始时刻**归日（跨天不重复计）。
- 老的 `ledger.tsv` 不动：总时长 / 按版本分列仍读它；流水只服务按天 / 单日分析。

`ledger.tsv` 每行：

```
槽 \t key \t tag \t 毫秒 \t 更新时间 \t title \t rawName \t upstream \t patch \t patchLabel
```

| 列 | 内容 |
|---|---|
| 槽 | 槽名（控制字符写入时换空格） |
| key | **身份**：已装 = 包名；导入 = `import:<文件名>` |
| tag | **版本号**（`displayVersion`，如 159.7 / 2026.09.X37）—— 也参与行身份 |
| 毫秒 | 该槽里这个版本累计的**游戏前台**毫秒（单调时钟） |
| 更新时间 | 墙钟毫秒（只诊断） |
| title | 显示名快照（如 `MindustryX  改端  2026.09.X37`） |
| rawName | 原始 versionName（如 `8-official-2026.09.X37`） |
| upstream | 上游版本号（fork 才有，如 `160.1`；官方为空） |
| patch | **补丁身份**：这一局实际注入的 refs（排序后逗号拼接，如 `mdtx@1607`；没有 = 空）—— 也参与行身份 |
| patchLabel | 补丁名快照（`、` 拼接；补丁删了也还看得出当时带了什么） |

- `ledger.tsv` / `total.txt` 走「临时文件 + 改名」（读到的永远是完整文件），`total.txt` 与账本
  同一次写入刷新；`sessions.tsv` 是**追加**（一行一局，坏行解析时跳过）。
- **一份账只由 `game-exit` 加一次**：宿主每局派发一次事件（派发后清 `sSessions` / pending）；
  没有 `activeMs`（启动即崩 / 宿主没量到）的事件不记账。
- **行身份 = 槽 + key + tag + patch**：已安装的游戏更新时包名不变、版本号会变 ⇒ 新建一行，老行保留自己的快照；
  **本体与带补丁的局绝不合并**（同一版本、同一补丁身份才覆盖毫秒数）；`key` / 快照由宿主事件 +
  `versions()` 的 extra 给，`patch` / `patchLabel` 由 `game-exit` 的补丁键给。
- 旧格式照读（第 255 轮的 4 列 / 5 列 / 第 385 轮前的 8 列）：4 列 tag 为空、5 列末列当 tag、
  8 列没有 patch（当本体）；下一次写入时补成新格式，老时间不丢。
- 旧版（第 254 轮）的"每局一个 `playtime.txt` 再求和"已废弃：读一次账本是 O(1)，主界面那一行
  才能在 UI 线程上读。

### 槽页列表：同名合并 + 折叠

- **显示层合并**：同一个槽里，如果同一个游戏版本因为「已装包 + 导入的同版本 APK / 换过包名」出现
  多行，页面按**显示名**（名字里已含版本号）合并成一行、时长相加；账本仍保留分行（原始记录不丢）。
  官方 / fork 同号但名字不同 ⇒ 不会误合。
- **默认全部收起**：只显示「本槽累计」；点「展开（N 个版本）」才画版本行，展开后出现「收起」。
  这样版本多了槽页不会被顶得太高（收起状态不持久化，重新进页面还是收起）。

## 口径

- 只算**游戏 activity 在前台**的时间（主菜单 / 暂停 / 编辑器都算，切到别的 App 不算）；
- 宿主时钟最多丢一拍（20 秒），`activeMs` 只少不多；
- 不读存档的 `playtime`（那个是"存档内已保存时长"，回档/删档/复制都会乱）；
- 按天 / 按小时：**设备本地时区**；跨零点的一局按墙钟占比摊（边界那一小段最多差一局的时长）。

## 已知边界

- **历史累计没有日期**：`ledger.tsv` 只有「最后写入时刻」，无法重建每天玩了多久 ⇒
  `sessions.tsv` 只从**第 396 轮之后的第一局**开始记；按天图表的覆盖范围不是总时长（界面上
  必须分开说，别让用户以为丢数据）；
- **没有 `started` 的局不记流水**（启动即崩 / 宿主没量到时钟）：账本同样不记这种局；
- **槽改名**：账本里记的是槽名，改名后旧数字留在旧名下（总数仍对，那个槽的分项会断）；
- 槽删除后它的数字仍在总数里（"总游玩时长"不因删档回落）；
- 只有**装了本插件之后**启动的游戏才有数据（宿主的 `UsageLog` 已在第 252 轮删掉，没有旧流水可回填）；
- 同一个版本号但内容不同的包（重打包 / 换签名）会合并成一行（版本号是给人看的号，不是文件哈希）；
- 版本被卸载后槽页仍能显示它（用账本里的 title/tag 快照）。
