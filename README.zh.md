# MDT 启动器 —— Mindustry（像素工厂）安卓多版本启动器

官方的 Mindustry 安卓版**一次只能装一个版本**，装第二个就把第一个覆盖掉；存档也只有一份，
换版本玩就等于把旧存档顶掉。这个启动器给每个版本一个**独立的「存档槽」** —— 多个版本同时装着，
各自的**存档 / 地图 / 蓝图 / 模组**互不干扰。

> ⚠️ **目前只有预览版（Pre-release），功能还没做完** —— APK 挂在
> [Releases](https://github.com/GXFQE/mindustry-launcher-android/releases)
> （标着 Pre-release 的那个），也可以自己构建，见 [构建](docs/DEVELOPING.md#构建)。
> 预览版意味着：界面、数据格式、功能都还可能变，**别拿它当稳定版用**。
>
> 下面那份功能列表说的是**当前源码**，最新的预览版 APK 可能落后一点。

## 它解决什么

| 直接用官方安卓版 | 用这个启动器 |
|---|---|
| 一次只能装一个版本，装第二个 = 覆盖第一个 | 多个版本同时装（159.7 / 160.4 / MindustryX X37 …），互不覆盖 |
| 所有版本共用一份存档，切版本 = 存档被顶掉 | 每个版本分配到一个**槽**，存档 / 地图 / 蓝图 / 模组全独立 |
| 想回老版本玩老存档，得手动来回倒文件 | 点一下切版本；「继续上次」直接接上上次启动的那个版本 |
| 「这个模组为什么没生效」查不出来 | 逐个模组说明会不会加载、为什么（类型 / 依赖 / 版本门槛 / 黑名单）；模组间冲突逐条列出来 |
| 备份攒多了很占地方 | 备份按内容去重、跨槽共用 —— 真机实测 3 个槽各 20 份备份，9.1 GB 的数据在盘上只占 **448 MB** |
| 手一抖，地图 / 模组 / 整个槽就没了 | 删这些**先挪进中转站**，能放回来 |

**它是怎么做到的**：把官方 APK **原样当插件加载** —— 不重打包、不重签名、不改游戏包名。
游戏自身的校验、存档格式、模组生态都不受影响；启动器这边只负责给每个版本安排一个
独立的数据根，并在启动时把游戏引到那个目录去。

## 怎么用

1. **自己准备游戏 APK** —— 本仓库**不包含**游戏本体，请从官方渠道获取官方 Mindustry，
   或 MindustryX 等构建的 APK。（魔改过的包不一定能加载。）
2. **装上启动器** —— 目前要自己构建（见 [构建](docs/DEVELOPING.md#构建)）。要求
   **Android 8.0（API 26）** 及以上；开发期间在 **Android 16（API 36）** 真机上验证过。
3. **导入并开玩**：
   - 打开启动器 → 「添加游戏」点开二选一：「导入 APK」选你那份 APK
     （会复制一份到应用私有目录），或用「添加包名」扫描已经装在手机上的游戏；
   - 给它分配一个**槽**（不同版本用不同的槽，存档就不会互相覆盖）；
   - 点那个版本启动。「继续上次」直接回到上次启动的那个版本。

界面**跟随系统语言**：中文手机上是简体中文，其它语言显示英文（目前只有中文 / 英文两套翻译）。
**顶栏右上角的齿轮（设置）→ 界面语言**可以覆盖它，也能切回跟随系统。

## 能做什么

### 版本
- 扫描**已装**的 Mindustry / MindustryX，或**导入** APK 副本（流式拷贝，落地前先预检）
- 一个版本一行：点整行启动，点右边「槽」按钮换槽（那个弹窗里也有「看详情…」），**长按整行**看详情
  —— 来源路径、大小、校验值、原始版本名、基础版本、ABI、构建号，还有「这个槽里有 N 份存档」
  与「上次启动」（导入的那份副本也在这里删）
- 每个版本分配一个槽；**版本号相同**才算「同一个槽的同一批」，版本号不同会在那一行提醒
  「与某某共用此槽，存档会互相覆盖」
- **拒跑不了的包**：导入时 + 启动前各探一次，查的是**能力而不是版本号** —— 游戏的入口类在不在
  dex 里、arc 的 native 库在不在、包里的 ABI 和设备有没有交集、库的加载页对齐够不够这台设备
- 「继续上次」：记住上次启动的版本，下次直接接上
- 每行还会写上**这个版本的槽里有几份存档**

### 存档槽
- 每个版本指向一个槽；一个槽就是**一整套**游戏数据（`saves` / `maps` / `blueprints` / `mods` / 设置）
- **新建 / 改名 / 克隆 / 删除**。克隆会把一个槽复制成新槽（先给源槽备份一份，源槽本身不动）；
  删掉的槽连同**它的备份**一起进中转站，可以再放回来，名字撞车时可以**换个名字放回去**
- 点进一个槽，里面的东西各占一行：**模组**、**存档**、**地图**、**蓝图**、
  **备份与恢复**、**整槽导入导出**

### 存档与数据
- **存档列表带缩略图**：每份存档旁边画一张它那张图的小图（这一项需要该槽已分配版本）
- **看每份存档**：它是哪张图、多大、第几波、玩了多久、作者、什么时候存的；
  读不出来的文件会单独列一行并说明原因，而不是悄悄消失（存档页是**只读**的 ——
  删存档留在游戏自己的界面里）
- **存档列表能搜能排**：搜存档名；按名称 / **最新在前** / 体积排（这一页没有「只看有问题的」——
  「读不出来」已经有专门那一行了）
- **导入 / 导出 `.msav`** 存档，一次一份
- **备份列表**：一份份列出来（时间 / 几个文件 / 多大 / 里面那份主存档是什么图），
  点一份即可**恢复**或**删掉这一份**
- **自动备份，逐槽设置**：可以开关、设「最少玩多少分钟」（更短的一局直接跳过）、设「最多留几份」
  （超出自动删最旧的）；无论开关怎么设，**动手覆盖之前都会先备份一份**
- **CAS 存档对象池**：多份备份之间相同的文件走一个全局对象池 —— 真机实测
  3 个槽各 20 份备份，9.1 GB 的数据在盘上只占 **448 MB**
- **整槽导出 / 导入成一个 zip**（含地图 / 蓝图 / 模组 / 设置）—— 换手机 / 换槽都能整包搬。
  整槽导入与「恢复备份」都能选**三种合并方式**：**更新**（两边都有的用新的盖）/
  **补齐**（两边都有的保留现在的，只补缺的）/ **覆盖**（先清空再整份换成包里的）——
  而且**动手前一律自动备份一份**，选错了能退回来
- **自动清理**数据根里的冗余残留（可开关；关掉之后仍留着一个「立即清理一次」的手动入口）

### 地图
- 地图列表（卡片 + **预览图**，来自本槽 / 游戏自带 / 模组自带）与独立详情页
- **地图资源统计**：地矿 / 墙矿 / 可采地板 / 加成地板 —— 首屏只报「能采到」的数字
  （墙矿只报总格数，因为它长在墙里、要用墙钻才采得到），依据（哪些方块、多少格、
  有多少格被建筑或石头压着）可以展开看
- **导入 `.msav`**；**导出不限来源** —— 游戏自带 / 模组自带的图在 APK 里面，也能直接导出来
  （导出的文件与源逐字节一致）
- **把存档变成地图**：从本槽的存档里挑一份，起个名，还能选一张**源图**
  （本槽 / 游戏自带 114 张 / 模组自带）来补上生成器设置
- 删除走中转站（挪走而不是硬删）；同名会先问，旧的那份也挪进中转站
- **搜索 / 排序**：搜地图名或文件名；按名称 / **有问题的在前** / 体积排；
  「只看有问题的」= 元数据读不出来的那几张

### 蓝图
- **列表缩略图 + 详情整图预览**：列表里画真贴图，详情页把整份蓝图**逐格**画出来（用的是游戏自己
  那套贴图）。两者都需要**给这个槽分配了版本** —— 贴图是从那个版本的 APK 里读的
  （没有版本时宁可什么都不画，也不拿别的画法凑）
- 蓝图列表（本槽 + **模组自带**）与独立详情页：用到的方块、缺哪些方块、**技术细节**
- **缺件提醒**：游戏遇到认不出的方块会**静默**把那格丢掉 —— 列表行上会写明缺了几种，
  详情里逐个列出来（通常是因为带它的模组没启用）
- **拿不准的时候它会自己说明**：用**代码或脚本**加方块的模组，启动器看不见那些方块
  （它读的是模组包里带的方块数据）—— 有这种模组的槽里，提示会变成「有 N 种我们**没认出来**……
  **可能认错**」，详情页上有显眼的「可能认错」标记，依据也放在一层里能点到
- **导入 `.msch`**（先校验再落位；同名先问，旧的那份挪进中转站）；**导出不限来源**；
  删除走中转站，能在中转站里**放回去**
- 详情页的「技术细节」里能看见依据：文件自带的名字表内容、带朝向的方块格数、换算过名字的方块、
  声明尺寸与实际铺开的格数
- **搜索 / 排序**：搜蓝图名或文件名；按名称 / **有问题的在前** / 体积排；
  「只看有问题的」= **缺件或读不出来**的那些（拿不准的「可能认错」也算在内）

### 模组
- 模组住在**槽的二级页面**里（主界面 → 「存档与备份」→ 点一个槽 → 「模组」），
  这一页也能直接切到别的槽看，不用退回去
- 逐个或**批量启停**（改的是游戏自己的开关：改前备份 + 原子写 + 写后自检；游戏在跑时拒绝改）
- **每个模组说明能不能加载、为什么**：类型（Java / 脚本 / 资源）、形态（jar / zip / 目录）、
  依赖（必需 / 软依赖 / 循环）、版本门槛、游戏黑名单、有没有被关掉，以及上次启动是不是崩过
  （崩过之后游戏可能一次跳过所有模组）
- **冲突体检**：两个模组重复实现同一个东西、同一个模组的两份副本、说明文件根本读不了的包、
  以及包已经不在设置里却还留着的旧开关 —— 逐条列出来，还会说清谁依赖谁
- **搜索 / 筛选 / 排序**：按名称 / 有问题的排前面 / 体积；「只看有问题的」；按类型筛。
  混合模组会在几类里都出现 —— 那是事实，不是重复
- 导入模组包；把本槽的模组**复制到别的槽**

### 中转站
- 删掉的地图、存档、**整个槽**、**蓝图**，以及被替换掉的模组，都先挪到这里，不会直接消失
- 列表里能看到它是什么（地图 / 存档 / 模组 / 蓝图 / 整个槽 / 其它）、来自哪个槽、多大、
  什么时候挪进来的；可以**放回去**（默认选中来源槽）
- 删掉的槽连同**它的备份**一起进站，放回来时一起回来；名字撞车时可以**换个名字放回去**
- 也可以**彻底删除**或**清空**（都会再问一次，并说清份数与体积）；站里最多留 20 份
  （整个槽是 3 个），超出会自动顶掉最早的那份

### 日志与设置
- **运行日志页**（主界面 → 运行日志）：启动器日志 / 游戏日志 / 崩溃堆栈分成几段，各带时间与大小；
  崩溃报告可以在那里删掉最旧的几份；「导出全部日志」会把它们写进一个文件
- **中转站**（主界面 → 中转站）：删掉的地图 / 模组 / 槽 / 蓝图先挪进去，能再放回来
- **深浅色**：跟随系统 / 浅色 / 深色；**界面语言**：跟随系统 / English / 简体中文 ——
  都在应用内切换，不动系统设置
- **设置页**（**顶栏右上角的齿轮**；只放"能被改的项"）：新发现的版本默认用哪个槽、崩溃报告保留几份、
  **自动清理**（带「立即清理一次」）、**存储占用**（各槽 / 备份 / 中转站各占多少、CAS 对象池省了多少）

## 现在还没有的

- **只有一个预览版（Pre-release），事情还没做完** —— 界面、数据格式、功能都可能变；
  稳定版还没出。要稳定就等，或者自己构建
- **启动器本身没有任何联网功能**：地图下载、论坛嵌入、检查更新、启动器自更新**都还没做**
  （v1 的定位就是「只在本地：扫描已装的 + 自己导入」）。这**不影响游戏本身** ——
  Internet 权限是声明了的，联机、服务器列表、游戏内下载照常能用
- **不上架 Google Play**：把别的 APK 当插件加载本身不符合它的政策，只能侧载分发
- **没有内置文件管理器**：导入导出一律走系统的文件选择器；它也不是通用存档管理器 ——
  删存档仍然是游戏自己的事
- **本仓库不含游戏本体**：Mindustry 与 MindustryX 等第三方构建的版权归各自作者所有，
  遵循各自的许可协议
