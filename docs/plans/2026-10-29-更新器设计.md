# 更新器设计（APK 自更新）—— 2026-10-29

> **性质：设计定稿，未实现。** 实施前读这里。
> 上游：`2026-10-29-自更新-热更与APK结合.md`（可行性验证）。
> **范围已定**（用户 2026-10-29）：「启动器挺轻量的，也没必要啥都热更新」⇒
> **只做 APK 自更新**；不做 core 热更、不做插件在线更新（插件仍走现有导入）。

---

## 0. 一句话

启动器启动时静默拉一个 ~300 B 的 `update.json`，版本号更大就提示；用户点下载 → 校验两道
（sha256 + 证书指纹）→ 交 `PackageInstaller` 装；**不做任何静默安装**（Android 不允许）。

## 2. 版本源：`update.json`

发布时作为 release 资产上传（与 `mdt-launcher.apk` 同 release）。**故意做得极小**：
检查更新只下它，不碰 APK。

```json
{
  "schema": 1,
  "versionCode": 8,
  "versionName": "0.8.0-preview",
  "size": 826655,
  "sha256": "527341d6ff…ad0a8",
  "url": "https://github.com/GXFQE/mindustry-launcher-android/releases/download/v0.8.0-preview/mdt-launcher.apk",
  "publishedAt": "2026-11-02",
  "notes": "一行说明这次更新了什么"
}
```

判据（客户端只认这些）：

| 字段 | 要求 | 缺了怎么办 |
|---|---|---|
| `schema` | 必须是 1 | 不认识 ⇒ **不提示**、只记日志（否则将来改格式会把老客户端锁死） |
| `versionCode` | 正整数 | 缺 / 非法 ⇒ 整份视为坏数据 |
| `sha256` | 64 位小写十六进制 | 缺 / 非法 ⇒ 整份视为坏数据 |
| `url` | 下载地址 | 缺 ⇒ 这一版不能更新（不猜默认地址）；**只认 https**，例外只有回环（本地夹具） |
| `size` | 正整数（字节） | 缺 ⇒ 下载后按实际长度校验 sha256 |
| 其余 | 只用于显示 | 缺了就不显示那一行 |

**向后兼容纪律**：只加字段、不改语义。这是"壳冻结"问题的迷你版 —— 老客户端不会因为
新格式而失去更新能力。

### 客户端怎么找到它（Releases 列表）

```
GET https://api.github.com/repos/GXFQE/mindustry-launcher-android/releases?per_page=10
  → GitHubReleases.parse          （org.json；数组，最新在前）
  → GitHubReleases.pick(allowPreview)
        allowPreview=true  ⇒ 取第一个（稳定版 / 预览版都要）
        allowPreview=false ⇒ 取第一个 prerelease==false 的（只要稳定版）
  → asset(r, "update.json")       （从它的 assets[] 里找清单）
  → GET 那个 asset                （带 Accept: application/octet-stream）
  → UpdateManifest.parse
```

**为什么不用 `releases/latest`**：那个接口**只返回非 prerelease**。1.0 之前每版都勾
`--prerelease` ⇒ 它永远 404（`api.github.com/…/releases/latest` 在本仓库实测就是 404）。

> 🔴 **第 310~316 轮曾经走过弯路**：为了绕开"嵌套 JSON 解析"造了一条**固定通道**
> （一个只放 `update.json` 的 tag `update-channel-preview`）。那是坏设计 —— 多一个 release
> 要维护、还要一条 404 回退，而且"通道"这个概念本身不是用户需要的东西。
> 2026-10-29 用户点破「为啥不能正常查 Prerelease」之后改成直查列表：能查，只是要点开嵌套。

> ⚠️ **每一版都必须带 `update.json` 资产**。缺了它的 release，对更新器等于不存在
> （客户端报 `no update.json in release v…`）。

> 🔴 **`Accept` 要按接口给**（第 317 轮真机踩的）：`/releases` 只认 `application/json`，
> asset API 反过来只认 `application/octet-stream`。一刀切发 octet-stream ⇒ **415**，
> 而我们的 catch 会把它折成"连不上服务器"——最容易误判成网络问题的一种。

> ⚠️ **`api.github.com` 在手机上实测可达**（ping 133 ms，真机请求到达服务端）。
> 速率限制：未认证 60 次/小时/IP —— 每个用户自己的 IP 独立计，24 h 一次的检查远远够。

### 为什么清单里要带 `url`

发布时 `update.json` 与 APK 在**同一个 release**，但下载链接里的 tag 是发布时才知道的，
客户端拼不出来 ⇒ 由发布脚本写死在清单里，客户端只认清单。

## 3. 流程

```
MainActivity 首次 onResume ──┐
设置页「检查更新」──────────┴─→ 后台线程：拉 latest → 找 update.json → 读 versionCode
                                    │
                    ┌───────────────┼────────────────┐
                远端更旧/相等      远端更大          网络/解析失败
                    │               │                 │
              「已是最新」      弹卡片（§5）      静默：不提示，只记日志
                                │                 手动：提示「检查失败」
                                ▼
                          用户点「下载」→ Work 前台服务 + 进度
                                │
                         写 <hub>/update/<code>.apk.part → 完成 rename
                                │
                         sha256 校验 ── 不过 ⇒ 删包 + 提示
                                │
                         证书指纹校验 ── 不过 ⇒ 删包 + 提示（不提供安装）
                                │
                          卡片变「安装」→ 用户点 → PackageInstaller 会话
                                │
                          系统安装界面 → 用户点确认 → 进程重启
```

**不自动下载**（用户选的）：静默只检查，下载必须用户点。

## 4. 存储

| 路径 | 内容 | 备注 |
|---|---|---|
| `<hub>/update/<versionCode>.apk.part` | 下载中 | 失败即删 |
| `<hub>/update/<versionCode>.apk` | 校验通过的成品 | 装完 / 用户放弃后删 |
| `app_hub/update-check.txt` | 上次检查时间（epoch 秒） | 静默 24 h 内不重复 |
| `app_hub/update-skip.txt` | 用户点「稍后」时记下的 versionCode | 同一版不再静默提醒（手动仍可查） |

⚠️ 更新包**放外部 hub**（不参与 dex 加载，不需要内部存储）；但**安装前要能被 `PackageInstaller`
读到** —— 走 session 写入时由我们自己读文件，所以位置无所谓。

## 6. 校验（两道，缺一不可）

1. **sha256**：`PluginTrust.sha256File(File)` 现成；对不上 ⇒ 删包，**不提供安装**
2. **证书指纹**：`PluginTrust.apkFingerprint(ctx, File)` 与 `PluginTrust.selfFingerprint(ctx)`
   比 —— 对不上 ⇒ 删包，**不提供安装**（这是防"被换包"的唯一一道）；两个方法都已存在，直接复用

⚠️ 不要只验 sha256：`update.json` 是从网上拿的，能改 sha256 的人也能改包。
**证书指纹是根**，它绑在壳里（改不了）。

## 7. 发布流程与防呆

### 发布时

```bash
VER_CODE=8 VER_NAME=0.8.0-preview \
KEYSTORE=~/.android/mdt-launcher-release.jks KS_ALIAS=mdt KS_PASS=… KEY_PASS=… \
  bash ./build.sh
```

然后生成 `update.json` 并上传两个资产。

### 防呆（**本轮要改 `build.sh`**）

现在的默认值会造出"装不上的包"：debug 签名 + `VER_CODE=1`。加一条：

> **`VER_CODE != 1` 且 `KEYSTORE` 仍是默认的 `debug.keystore` ⇒ 直接报错退出。**

理由：任何"要发出去的包"都必然 `VER_CODE > 1`，而它必须用正式签名。
自测包保持 `VER_CODE=1` 不受影响。

### 第一次自更新的过渡

v0.7.0 **没有更新器** ⇒ v0.8.0 仍然要**手动发一次**（用户手动下载安装）；
**从 v0.8.0 起**才真正自更新。这个过渡躲不掉，发版说明里要写清楚。

## 8. 实现顺序（5 轮，每轮都能单独验）

| 轮 | 做什么 | 判据（能算出 false 的） | 状态 |
|---|---|---|---|
| 1 | `UpdateManifest` 解析 + 版本比较 + 24 h 去重（**纯逻辑，无网络**） | 自检：缺字段/类型错/超长/相等/更大/更小/24h 内不重复 | ✅ 第 305 轮 |
| 2 | `UpdateClient` 拉 `update.json` + 网络失败降级 | 真机：飞行模式 → 静默不提示、手动提示失败；正常 → 读到清单 | ✅ 第 306 轮 |
| 3 | 下载 + 两道校验 + 清理 | 真机：正常下载 1.09 MB；sha 错 ⇒ 拒；签名不符 ⇒ 拒；失败 `leftovers=0` | ✅ 第 307 轮 |
| 4 | `PackageInstaller` 提交 + 结果广播 + 未知来源检查 | 真机：未授权时**不提交**；提交后 `PENDING_USER_ACTION`；用户确认后 `SUCCESS` | ✅ 第 308 轮 |
| 5 | **界面**：设置页一行 + 卡片 + 进度 + 静默检查去重 | 真机：整条路点得动；「已是最新」只说一次；卡片字数预算 | ✅ 第 309 轮 |

### 第 4 轮实测（2026-10-29，HONOR ELP-AN00 / MagicOS 10）

| 阶段 | 证据 |
|---|---|
| 未授权（`appops` 默认） | `precheck = no-permission` / `canRequestPackageInstalls=false` / **`result = not submitted`** |
| `appops set … REQUEST_INSTALL_PACKAGES allow` 后 | `precheck = ok`（`apkVersionCode=2` / `curVersionCode=2`） |
| 提交 | `submit = ok (waiting for system confirm)` |
| 结果 1 | `status = PENDING_USER_ACTION`（系统确认界面，由 receiver 转发 `startActivity` 拉起） |
| 结果 2（用户点完） | **`status = SUCCESS`** / `INSTALL_SUCCEEDED` / `lastUpdateTime = 20:15:11` |

⚠️ **荣耀 ROM 在这中间还有一道自有的"安全模式"底部弹窗**（`SafeModeBottomSheetActivity`，
按钮「取消安装 / 知道了」）。那是 ROM 行为、不是我们的流程 —— 自动化点安装会撞到，
脚本要么先点掉、要么循环处理。

⚠️ **`packageinstaller` 的勾选框默认就是勾上的**：第一次 `input tap` 反而把它**取消**了。
GUI 自动化的老坑（与 `ref/29` §90.6「`AlertDialog` 按钮编号不可信」同族）——
点之前先读 `checked`，别假设默认值。

> ⚠️ **最后那一步（勾选 + 继续安装 + 知道了）是用户点的，不是自动化**。
> 自动化能把流程推到 `PENDING_USER_ACTION`（确认界面被拉起），剩下的必须真人点 ——
> 这本来就是 Android 的设计（不允许静默安装）。

## 9. 自检清单（约 30 条）

**解析**：正常 / 缺 `versionCode` / `versionCode` 是字符串 / `sha256` 长度不对 / `schema` 不是 1 /
空文件 / 10 KB 垃圾 / JSON 截断

**比较**：>`= <`、0、负数、超大数（`Integer.MAX_VALUE`）

**去重**：24 h 内不重复 / 跨天后重复 / `update-skip` 命中后静默不提示但手动可查

**下载**：正常 / 网络断 / 长度不足 / 长度超出 / 写到一半取消

**校验**：sha256 对 / 错 / 空文件；签名对 / 错 / 拿不到签名

**安装前置**：`canRequestPackageInstalls()` false 时的分支

**结果广播**：`STATUS_SUCCESS` / `STATUS_FAILURE` / `STATUS_FAILURE_ABORTED` / `STATUS_FAILURE_BLOCKED`

**文案**：卡片标题不超字数；"已是最新"只说一次

## 11. 本地验证（三层，都不赌外网）

| 层 | 跑在哪 | 夹具 | 条数 | 能验什么 |
|---|---|---|---|---|
| 纯逻辑 | PC | `PcCheck.java`（无网络） | **59** | 解析 / 比较 / 截断 / URL 准入 / 去重 |
| HTTP | PC | `PcNetCheck.java` + JDK `HttpServer` | **10** | 状态码 / 超长 / 重定向 / 长度不符 |
| 下载 | PC | `PcDownloadCheck.java` + JDK `HttpServer` | **16** | `.part` → 校验 → 改名 / 残骸清理 / 旧包覆盖 |
| 端到端 | 真机 | `adb reverse` + `fake_github.py` | **6** | Android 网络栈 + 明文策略 + **证书** |
| **安装** | **真机** | 同上 + `dev_update_install` | **3** | 四道门 / 会话提交 / 结果广播 |

判据只有一份：`UpdateManifestCheck.run()`（PC 与设备共用；`PcCheck` 只打印，
`SelfTest` 只并进总报告）。

### 为什么不用"手机能不能上外网"当判据

不可复现、依赖代理/302、还测不到失败分支。桌面版当年的做法是本地起服务伪装远端；
这里同样 —— 且 `UpdateClient` 只用 `java.net`（不 import android），所以**连 `adb reverse`
都不需要就能测 HTTP 层**（客户端和服务在同一个 JVM 里）。

### 复现

```bash
# 1) 纯逻辑

  app/src/io/mdt/launcher/FlatJson.java app/src/io/mdt/launcher/UpdateManifest.java \
  app/src/io/mdt/launcher/UpdateManifestCheck.java \
  .dsh/research/2026-10-29-selfupdate/PcCheck.java
java -cp /tmp/pc io.mdt.launcher.PcCheck

# 2) HTTP 层（PC 上起真服务，客户端真的走 socket）
javac --release 8 -encoding UTF-8 -d /tmp/pc \
  app/src/io/mdt/launcher/FlatJson.java app/src/io/mdt/launcher/UpdateManifest.java \
  app/src/io/mdt/launcher/UpdateClient.java
javac -cp /tmp/pc -d /tmp/pc .dsh/research/2026-10-29-selfupdate/PcNetCheck.java
java -cp /tmp/pc io.mdt.launcher.PcNetCheck

# 3) 真机端到端（不碰外网）
python .dsh/research/2026-10-29-selfupdate/fake_github.py 8080 &
adb reverse tcp:8080 tcp:8080
adb shell am force-stop io.mdt.launcher
adb shell am start -n io.mdt.launcher/.MainActivity --es dev_update_fetch http://127.0.0.1:8080/ok
adb pull /storage/emulated/0/Android/data/io.mdt.launcher/hub/report-update.txt
```

### 实测（2026-10-29，dev 版 HONOR ELP-AN00）

**HTTP 探针**（`dev_update_fetch`）：

| 路径 | 结果 |
|---|---|
| `/ok` | `ok=true`, 22 chars, **25 ms** |
| `/404` | `ok=false`, `http 404 @ …` |
| `/big`（200 KiB） | `ok=false`, `body too big (> 65536)` |

**完整链路**（`dev_update_run`：拉清单 → 判 URL → 下载 → sha256 → 证书）：

| 场景 | `step` | `leftovers` |
|---|---|---|
| 好清单 + 同签名包（1.09 MB） | **`ok`**（121 ms） | 1（成品） |
| `sha256` 故意错 | `sha` | **0** |
| `size` 比真实小 100 | `size` | **0** |
| `url` 是 `http://evil.example/…` | `url` | **0** |
| 清单 404 | `network` | **0** |
| 包是**正式签名**、app 是 debug 签名 | `sign`（`self=2cb7c419… got=b64cd9af…`） | **0** |

最后一行是这套东西的核心判据：**sha256 只证明"没被改坏"，证明不了"是谁签的"**。
本机构建默认是 `debug.keystore`（`CN=Android Debug`），所以 self 与 fake 同签名时会通过 ——
验"拒绝"必须拿**正式签名**的包（这里用的是已发布的 `v0.7.0-preview`）。

**明文策略**：Android 9+ 默认禁明文 HTTP ⇒ `app/res/xml/network_security_config.xml`
对 `127.0.0.1` / `localhost` 单独放行（其余域名仍然禁）。这是第 3 轮下载能走本地夹具的前提；
不先验这一条，等写完下载器才发现"连不上 127.0.0.1"就白跑一轮。

### 适用范围

- **能**：解析 / 比较 / 截断 / 时间去重（纯函数）；HTTP 语义（`UpdateClient` 用 `java.net`）。
- **不能**：任何要 `Context` 的东西 —— 落盘路径、`PackageInstaller`、SAF、界面。那些只能上设备。

> 这条不是为更新器临时造的：**以后新增的纯逻辑类都该按这个形状写**
> （不 import android ⇒ 天生可以在 PC 上验）。凡是要 Context 的，把判据抽成纯函数再包一层。
