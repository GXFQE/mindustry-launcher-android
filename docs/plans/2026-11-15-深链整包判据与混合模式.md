# 深链整包判据（整槽 > 模组 > 混合 > 蓝图/地图）与「混合包」实现

> 2026-11-15 第 379~380 轮。**本文件记录判据与"哪些包我们明说不支持"**；混合包已经实现（第 380 轮）。
> 触发：用户报「从深链导入一个模组，识别成蓝图了」→ 三轮定案（引号内是用户原话）。

## 一、用户定过的四条

1. 「**感觉模组才应该是最优先的**」
2. 「**整个槽的优先级最高吧**，毕竟整个槽里什么都有，但是可能需要**严格检查格式**」
3. 「注意检测到 mod.hjson 以后**不要继续往深检测**了，毕竟可能**有些模组本身就是嵌套的**」
4. 「**不允许一个文件里放两个整个槽**（这个行为目前认为是未定义的，或者把整个槽和其他东西混一起）」
5. 「**整槽 + 根级散图/散蓝图，我们就不应该允许这种东西吧**」
6. 「我想说**混合模式是把模组/地图/蓝图/存档混一起放文件里**」

## 二、最终判据（`BatchIo.guessKind`）

按顺序，**命中即停**：

| # | 包长什么样 | 判成 | 去哪儿 |
|---|---|---|---|
| 1 | 根上/唯一一层包裹目录有 `settings.bin`，**恰好一个整槽、形状干净** | `KIND_SLOT` | 槽页「导入整槽」 |
| 2 | 同上但 **≥2 个 `settings.bin` 根** / 包裹外面还有条目 / 根级散图散蓝图 / 包根整槽又带一级模组夹 | `KIND_SLOT_AMBIGUOUS`（**明说不支持**） | 一句「先分开打包」 |
| 3 | 包根 `mod.json` / `mod.hjson` | `KIND_MODS`（**到这儿就停**） | 模组页 |
| 4 | 一级目录里有 `mod.json`（模组夹），且夹子**外面**只有一类东西 | 那一类 | 对应页 |
| 5 | 模组夹外面有 **≥2 类**（模组 / 蓝图 / 地图·存档） | `KIND_MIXED`（**混合包**） | 槽页「四类各进各的目录」 |
| 6 | 只剩一类 | `kindOfMask`：`.jar`/`.zip` > `.msch` > `.msav`（`.msav` 再看整包名） | 对应页 |
| 7 | 一类都没有 | `-1` | 「这个压缩包里没有能导入的东西」 |

★ **为什么整槽判据这么严**：整槽包里本来就有 `mods/` `saves/` `maps/` `schematics/`
⇒ 拿"有 mods 目录"当判据会把任何模组整包判成整槽**写入**（破坏性）。
判据只认 **`settings.bin`** —— 我们「导出整槽」、脱敏分享包、游戏原生「导出数据」三种来源都带它
（与 `SlotZip.Info.nativeFormat` 同一标志）。

★ **为什么"整槽 + 根级散图/散蓝图"不许**：槽根不是游戏读的目录（游戏只读 `saves/` / `schematics/`），
根上散着 `.msav` / `.msch` 说明那是"整槽 + 批量导出的包"拼一起 ⇒ **两样东西**，怎么导没定义。
（`SlotZip.routeLoose` 会把根级散图改道进 `saves/`，那是给**纯批量包**用的，不是给整槽包用的。）

## 三、混合包（已实现，第 380 轮）

**定义**（用户第 6 条）：一个 zip 里同时装着**两类以上**的 模组 / 地图 / 存档 / 蓝图，
没有整槽、包根也不是一个模组。

**规则**：
- 落点 = **槽页**（目标槽由用户当场选，深链照旧先问槽）。
- 四类**各进各的目录**：`mods/` · `schematics/` · `maps/` · `saves/`。
- `.msav` 在混合包里按 **meta 里有没有 `name`** 分到 `maps/` 还是 `saves/`
  （同一个容器；与 `MapFiles` 的 `saveNoName` 同源）。
- 模组夹（一级目录有 `mod.json`）⇒ 整个夹子打成一个 zip 当**一个**模组，**夹子里的条目不再单独导**
  （用户第 3 条）；夹子里的 `.jar` 同理（那时嵌套模组 / 库）。
- 同名 ⇒ 与批量导入同一条：**写盘之前问一次**（更新 / 跳过），四类共用一张报告，
  报告第一行点明「混合包：模组 N · 蓝图 N · 地图 N · 存档 N」。
- 走写门禁：槽里有游戏在跑 ⇒ 直接拒（`WriteGate` / `SlotIo.blockedByGame`）。

**为什么不做"整槽 + 其它"的混合**（曾经考虑过，否掉）：整槽导入是**整槽写入**，
把"另外那些东西"混进同一个动作里，失败无法分区回滚、用户也看不出到底写了什么。
两个整槽更是没定义 —— 一个目标槽只能落一个整槽。

## 四、不做（明确）

- 不自动挑一个整槽（多个整槽时不许"取第一个"）。
- 不把"整槽 + 别的东西"静默降级成"只导整槽"或"只导别的"。
- 不在"模组夹"里面继续深挖（夹子里的蓝图 / 地图属于那个模组）。

## 五、观测点（都有自检钉着）

- `settings.bin + saves/ + mods/ + schematics/` ⇒ 整槽（槽页确认框如实列出四项）。
- 同上一份 + 根级 `散图.msav` ⇒ `KIND_SLOT_AMBIGUOUS`。
- `A/settings.bin + B/settings.bin` ⇒ `KIND_SLOT_AMBIGUOUS`。
- `a.msch + b.msav` ⇒ `KIND_MIXED`。
- 混合包（模组 + 蓝图 + 地图 + 存档）⇒ 四份分别落在四个目录，报告「混合包：1 · 1 · 1 · 1」。
