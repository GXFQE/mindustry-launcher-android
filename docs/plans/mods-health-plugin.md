# 模组体检全部搬进一个插件（宿主只给事实与插槽）

> 2026-10-24 第 229 轮，用户：「我觉得可以把所有关于模组存在问题（含模组冲突，结构不对，文件错误，
> 是否开关等各种情况）相关的东西都放一个插件里，宿主只给接口」。
> 状态：**设计待确认**（本文只落到"怎么做/分几步"，未开工）。

## 一、目标与边界

**目标**：模组页上所有"这个包有没有问题 / 为什么 / 该怎么办"的**判断与文案**，都在**一个**
官方插件里；宿主只负责**事实**（扫盘、解析、读写设置）与**插槽**（把插件给的东西画到该画的地方）。

**判据（什么算"事实"、什么算"判断"）**：

| 事实（宿主给） | 判断（插件给） |
|---|---|
| 包/目录的路径、大小、容器形态 | 这个包能不能被游戏加载 |
| `mod.json` / `mod.hjson` 里的字段（name/version/main/deps/…） | 为什么不能（缺依赖 / 版本过低 / 黑名单 / 没有 dex…） |
| 解析失败时的**错误码**（不是错误原文） | 这条错误对用户意味着什么、怎么修 |
| `settings.bin` 里 `-enabled` / `-failed` 的值 | "下次启动会不会加载"、要不要建议用户开/关 |
| 有没有 `classes.dex` / `scripts/*.js` / `content/*` | 声明了 Java 却没 dex ⇒ 整个包会被跳过；有 js 没 main.js ⇒ 脚本不生效 |
| 同 `internalName` 出现两次（可以只给名字） | 这是"同一个模组装了两份"，会互相覆盖 |
| 游戏日志（行）、`launchid.dat` 是否存在 | 上次崩了是不是模组的事、整槽跳过意味着什么 |

## 二、现状（要搬的东西在哪）

宿主 `Mods` / `ModsText` / `ModsActivity` 里现有的判断（都要搬走）：

1. `Mods.Scan.problems`（重复包）、`ignored`（游戏不加载）、`orphanKeys`（孤儿开关）；
2. `Mods.Info` 的派生：`willFailJavaLoad`、`jsCount`/`hasScripts`、`hidden`、`minGameVersion` 比较、依赖解析 `states`；
3. `ModsText`：`stateLabel` / `badgeSaysIt` / `cardNote` / `infoMetaReason` / 各种 warn 行；
4. `ModsActivity` 详情里的**六道门**（`Mods.gates`）与依赖链文案；
5. 「只看有问题的」筛选（判据 = `Mods.isProblem`）；
6. 冲突检查（已搬，见 `plugins/conflict`）。

宿主要**保留**的：包发现 / 排序 / 搜索 / 大小与类型、启停写盘（含"游戏在跑就拒写"等安全门限）、
导入 / 导出 / 删除 / 中转站、页面骨架。

## 三、接口设计（v25 草案）

复用现有的 `analyzer`（v24）而不是新插槽 —— 它本来就是"逐项回调 + 宿主渲染"，只是**渲染位置不够**：

1. `Finding` 加一个可选字段 **`anchor`（item 的 `path`）**：
   - 有 anchor ⇒ 宿主画在**那一行**（`⚠ 短标签`，最多一条；多条时取最严重那条，其余进详情）；
   - 无 anchor ⇒ 画进现在的「插件」卡（整槽结论，与今天的行为一致）。
2. 宿主在**扫描之后、渲染之前**调一次插件（逐项），把结果缓存在 item 上：
   - 行徽标、「只看有问题的」筛选、详情页的"问题"小节都读这份缓存；
   - 插件不在 / 崩了 ⇒ 这份缓存为空（**降级为"没有体检"**，见五）。
3. 每项要给的字段（都用现有 `Finding` 的三个字段 + anchor）：
   - `severity`：`ERROR`（不会加载）/ `WARN`（会加载但有坑）/ `INFO`（提示）；
   - `title`：行上那一行短标签（≤ 12 字，**不是整句**）；
   - `detail`：详情页那一段（为什么 + 该怎么办）。
4. 槽级结论（重复包、孤儿键、整槽跳过、崩溃记录）仍走"第一项那一次回调"的约定（`anchor=null`）。
5. `ItemInfo.extra` 要补齐的事实：`deps`/`softDeps`（现在只有拼好的字符串？）、`blacklisted`、
   `metaErrorCode`、`duplicated`、`ignored`、`failedRecord`、`slotProblem`……（逐项核一遍再定）。

## 四、分步

| 步 | 内容 | 判据（算什么完成） |
|---|---|---|
| P1 | 单插件成形：把 `plugins/conflict` 改名为 `plugins/mods-health`（id 一起改），先只承载"冲突 + 结构三类"（会不会加载 / 脚本不生效 / 解析失败） | 真机上模组行不再由宿主画这三类徽标；插件停用后这三类消失（预期降级） |
| P2 | `anchor` 机制 + 宿主渲染改造（行徽标 / 详情 / 筛选都读插件结果） | 「只看有问题的」勾上与插件给的 ERROR/WARN 一致；自检钉住"筛选结果 == 插件说的问题项" |
| P3 | 依赖链 / 缺依赖 / 版本过低 / 黑名单 / 重复包 / 孤儿键 / 整槽跳过 / 崩溃记录 全搬 | 宿主 `ModsText` 那几条判断与文案删除；两种构建都过 |
| P4 | 详情页六道门结构化（插件给 `List<Gate{ok,label,detail}>`） | 六道门逐条与今天逐字一致（报告对照） |
| P5 | 导入前的"这包有没有问题"也走同一套判据（导入校验的**文案**归插件，**拦截**仍在宿主） | 导入失败原因与体检结论不再各写一套 |

⚠️ **P2 是硬门槛**：没有 `anchor`，插件给的东西只能进卡片，搬多少判断都没意义。

## 五、三个必须先定的问题

1. **插件不在时怎么办？**（最关键）
   - A. 彻底降级：没装插件 = 模组页没有任何体检（干净，但产品风险大 —— 现在插件**没有分发渠道**）；
   - B. 宿主保留"事实级"兜底：只留一条最硬的、能直接从 `Info` 读出来的（"包里没有说明文件"），
     其余（为什么 / 怎么修 / 依赖 / 冲突）全归插件。
   - **建议 B**，并在插件不在时于页面顶部说一句「没装体检插件」（可点去插件页）。
2. **插件 id 改不改？** `conflict` 这个名字装不下"结构 / 依赖 / 启停"，建议改成 `mods-health`
   （dev 口重装一次即可；产品上还没有分发，改名成本≈0）。若不改，就地把 `conflict` 长大。
3. **快慢**：analyzer 现在是"进页面才跑"。体检结果要在**渲染前**拿到（徽标/筛选都要），
   ⇒ P2 必须把插件调用挪到扫描之后、且**同一份结果**给三处用（别调三次）。

## 六、不做什么

- 不把**列表页**整个交给插件（分页 / 排序 / 搜索 / 导入导出 / 删除 / 启停写盘留在宿主）——
  那需要插件重写一个页面且把宿主的安全门限丢在插件里，得不偿失；
- 不让插件写 `settings.bin`（**写侧永远是宿主**：现在有备份 / 原子写 / 读回自检 / 失败还原）；
- 不做"插件给类名、宿主按类名判语义"这类硬编码（第 229 轮刚删掉一层，见 `ref/43` 第 77 条）。
