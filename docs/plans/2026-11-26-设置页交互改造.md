> 状态：**已实现（2026-11-28，第 435 轮）**；真机验收记录见 `.dsh/memory/next/190`。三条口径由用户 2026-11-26 定（§1），落地前的验收与边界见 §11 / §12。

## 1. 用户定的规则（原话要点）

1. **需要确认的也能做成开关**，只是加个确认弹窗；用户 2026-11-26：**「其实可以回弹，毕竟用户不是瞬间点击取消，并不会闪一下，不过肯定需要确认以后才能实际操作」** ⇒ 点下去开关**先翻**、确认后才干活、取消就从 `Config` 回读翻回去。

3. **「翻译文件」本来就该和「语言」合在一起**（用户：「就跟更新线路自定义那样」）⇒ 语言改成下拉，列表末项是「翻译文件…」，点它进现有的管理弹窗；外观卡 4 行 → 3 行。
4. 数字类设置改成**行内输入框**（用户 m00233：「设置数字类的也能插入输入框吧」）——数字弹窗全删，不留"精确输入"的备用入口（双入口 = 两套交互）。

### 2.1 卡片顺序

```
外观与语言 → 启动与存储 → 通知与日志 → 安全 → 下载 → 实验性功能 → 版本与更新
```

「实验性功能」放**倒数第二**（`版本与更新` 里的「关于」仍是全页最末一项）：它按"靠不靠谱"分组，不按主题分组，所以不能塞进启动与存储；但也不该比"关于"还靠后 —— 用户翻到底先看到它，再看到关于。

**为什么 CAS 要单独成卡**（用户 2026-11-26 定）：它动的是**游戏包本体**（开=删原始 APK、关=逐包重拼），失败面比"改个设置值"大得多；和它同一类的是**存档守护**（会改写游戏的文件访问层，见 `docs/plans/2026-11-26-存档实时保护.md`）。既然后面还要加，不如现在就把卡建好，避免它落地时又要在启动与存储里挤一行、再搬一次家。

### 2.2 副标题的四种口径（这是"别扭"的两个来源之一，必须一次定死）

| 控件 | 状态/值由谁表达 | 副标题写什么 | 例 |
|---|---|---|---|
| `>` 卡片 / 页面 | 目标页 | 不变：`查看<它能做什么>` / 静态说明 | 存储占用「备份省了多少、各类数据各占多少」 |
| `▾` 下拉 | **只有副标题**（行上看不到当前值） | **保留「当前：<值>」**，补充用「 · 」 | 深浅色「当前：跟随系统」 |
| `⏻` 开关 | **开关自己** | **只写解释**（什么时候、有什么副作用） | 崩溃提示「崩溃时主动提示 · 报告仍保存」 |
| `▤` 行内输入 | **输入框自己** | **只写单位 / 超出怎么办** | 日志份数「超出后丢最旧的」 |

判据来自既有规矩：**同一屏同一件事只说一次**、**徽标说完正文别重复**（`ModsText.badgeSaysIt` 那一族）。开关行写「当前：开」就是同一个错。

## 4. `Util` 两个 helper（`app/src/io/mdt/launcher/Util.java`）

```java
// 行 + 图标 + 标题 + 整行点击；返回 Switch（fillValues 里 setChecked 用）
static android.widget.Switch bindSwitchRow(View root, int rowId, int iconRes, int titleRes,
                                           View.OnClickListener onClick)

// 下拉：候选每次点击现取（槽列表 / 语言种类会变），别缓存
interface DropdownSource { DropdownSpec get(); }
final class DropdownSpec { CharSequence[] labels; int checked; }
static void bindDropdownRow(View root, int rowId, int iconRes, int titleRes,
                            DropdownSource src, OnPick onPick)
interface OnPick { void onPick(int index); }
```

要点：

- **不挂 `OnCheckedChangeListener`**：所有提交只走"行点击"，`setChecked` 永远不触发写盘（否则 `fillValues`/`onResume` 会误写 config、CAS 还会误弹确认）。
- 下拉内部：`ListPopupWindow` 锚在**行**下方（`setAnchorView(row)`）、`setModal(true)`、`setWidth(row.getWidth())`、`setBackgroundDrawable(ctx.getDrawable(R.drawable.popup_bg))`（复用顶栏 ⋮ 那份圆角描边，别让弹层像贴纸）、`setElevation(8dp)`。
- 当前项高亮：自建 `BaseAdapter`（`getView` 里 `if (i == checked) text.setTextColor(accent)`），**不用** `simple_list_item_single_choice`（那是弹窗长相，且带单选圈）。
- 箭头：打开时 `chevron.setRotation(90f)`，`setOnDismissListener` 里 `setRotation(0f)`。
- 候选为空（如一个槽都没有）⇒ 不弹、不崩。
- 选中：**先 `dismiss()` 再回调**（沿用 `pickTheme()` 的既有纪律：别让弹层挂到 Activity 被销毁之后）。

### 6.2 CAS 时序与四条硬规矩

```
点行/开关
  ├─ ① WriteGate.blockedSlotOrGlobal(this, null) 为真
  │     ⇒ Toast(cas_busy)，**开关不翻**，结束
  ├─ ② 开关立刻翻到目标态（回弹版）
  ├─ ③ mCasConfirming = true；确认弹窗（沿用 cas_on/off_confirm_title + body）
  │     取消 / 返回键 / 点窗外面 ⇒ mCasConfirming = false；fillValues() 从 Config 回读（翻回去）
  │     确认 ⇒ mCasConfirming = false；开关 setEnabled(false)；applyCasGame(target)
  └─ ④ 结束（成功 / 失败 / 异常）⇒ fillValues() 从 Config 回读；setEnabled(true)
```

必须遵守的四条：

1. **回弹要"从 Config 回读"，不要 `!desired` 取反**：config 才是真值（开启分支先写 config 再收包，关闭分支全部拼回成功才写）。取反在"部分失败"时会把开关翻错。
2. **防连点**：`mCasConfirming` 标志（`dismiss` 回调里清），否则快速两下能叠出两个确认窗。
3. **开关 = 配置值，不是"操作结果"**：`applyCasGame` 开启失败时 `Config.casGameEnabled` 已经是 `true`（`SettingsActivity.java:512-514` 注释「先进池模式再收包」），所以开关**停在开**、由 Toast（`cas_failed_fmt`）说清哪个包没收进去；关闭失败（`PkgAdmin.disable` 返回 -1）时 config 仍是 `true`，开关**停在开**。这个不对称是既有语义，文档里要写明，别让后人以为是 bug。
4. 进度卡仍不可取消；收尾仍走 `Util.dead` + `prog.isShowing()` 判过再 dismiss。

## 8. 行内数字输入（6 行）

### 8.1 提交时机（三条，幂等）

1. **失焦**：`OnFocusChangeListener`（有焦点 → 无焦点时提交）
2. **IME 完成**：`setOnEditorActionListener`（`IME_ACTION_DONE` → 提交 + `clearFocus()`）
3. **兜底**：`SettingsActivity.onPause()` 里把所有输入行提交一次（按返回键时焦点不一定掉）

提交实现必须是**幂等**的：解析出值 → 与当前 `Config` 比较 → 相同就什么都不做（否则 `onPause` 会反复写盘；下载限速还会每字符重设带宽）。

**绝对不要** `TextWatcher` 逐字符提交。

### 8.2 校验与还原

| 行 | 区间 | 错误文案 | 提交 |
|---|---|---|---|
| 日志份数 | `LOG_MIN..LOG_MAX`（1..999） | `set_logs_bad` | `setMaxLogFiles` |
| 临时文件上限 | 1..10240 | `set_tmp_cap_bad` | `setHubTmpCapMb` |
| 下载限速 | 0..`DownloadLimit.MAX/KB`（0..102400） | `set_download_limit_bad` | `setDownloadLimit(bps)` + `Bandwidth.set(bps)` |
| 中转站普通条目 | 1..999 | `set_trash_bad` | `setTrashKeep` |
| 中转站整槽/版本 | 1..999 | `set_trash_bad` | `setTrashKeepSlots` |
| 中转站天数 | 1..3650 | `set_trash_days_bad` | `setTrashKeepDays` |

- 非法（非空且越界/解析失败）：Toast 现有 `_bad` 文案 + 回读 config 还原。
- **空串 = 放弃修改**（不 Toast，直接还原）——用户清空后又点别处，不该挨一句骂。
- 下载限速显示按 `cur<=0 ? 0 : max(1,(cur+KB/2)/KB)` 换算，与现有 `pickDownloadLimit` 一致（`DownloadLimit.KB = 1024`）。

### 8.3 键盘与滚动（本批唯一真风险）

- 输入框拿到焦点 → 把**那一行滚到视口顶部**：`rowRoot.post(() -> scrollView.smoothScrollTo(0, row.getTop()))`（`activity_settings.xml` 根是 `ScrollView @+id/root`，内层只有一层 LinearLayout，`row.getTop()` 就是内容坐标）。
- 目标 SDK ≥ 35 强制 edge-to-edge ⇒ `adjustResize` 不再靠窗口缩放；现有 `Util.applySystemInsets` 只吃系统栏 inset（`Util.java:121`，API 30+ 不含 IME）。
- **先做便宜方案**（滚到顶部），真机不够再补：`applySystemInsets` 里加 IME 底部 inset（`WindowInsets.Type.ime()`，API 30+），且与系统栏取 **max** 不是相加（否则多算一条导航栏高）。
- 横屏可用高只有 **376dp**（`activity_settings.xml:13` 注释），键盘一弹更挤 —— 只能真机看，横屏验收必做。
- `fillValues()` 里对**正在聚焦**的输入框跳过 `setText`（否则会把用户正敲的内容冲掉）。

## 14. 附：与既有规矩的对应

- 「设置页只放能被改的项」→ `update` / `storage` / `sig_trust` / `about` 仍留（它们要么改状态、要么是这一屏的账）。
- 「主界面一行 = 一件独立的事」→ 中转站拆三行正是这条的执行（一件事一行）。

- **分组按「靠不靠谱」，不按主题** → 实验性功能卡单独存在：动了游戏包、存档层的东西不混进日常设置里；以后加实验功能照这个分。
