# 本体 CAS 实施设计（2026-11-22）

> 上游：`docs/plans/2026-11-20-游戏载荷与发布方向.md` 附录 E/H（方案 + spike 实测）。
> 本文只讲**怎么实现**：类、文件、数据格式、改哪几处、分几期、验收什么。
> 已验证的前提（真机，v160.7）：同名 `AndroidFi` 覆盖成立；`AndroidFiles.get(internal)` 返回我们的类；
> `read/list/map/openFd` 全对；34 个 arc 版本 ABI 全一致；dexPath 前置即可，不需要 `injectDex`；
> 真机已进主菜单（`launch ok in 114 ms`，池 680 路径，fd 214 且 0 个常驻池文件）。

## 0. 一句话

CAS 开启后 `app_hub/import/*.apk` **不再保留**：条目进对象池，启动时 dex 从池、native 从池、
assets 由同名 `AndroidFi` 直读池；启动器自己那些「顺手读 APK」的界面（地图预览、基础 bundle、
蓝图缩略图…）改读池。设置里一个开关（**默认关**）负责开/关与双向迁移。

## 1. 存储布局与清单格式

```
app_hub/
  pkgs/
    objects/<sha[0:2]>/<sha[2:]>    只读、不可变（0622 也不行：ART 只吃只读 dex）
    manifests/<vkey>.json           vkey 清洗后：import:v1607.apk → import_v1607.apk.json
    tmp/                            入库中的 .part
    override.dex                    6.4 KB，同名类覆盖的 dex（构建产物）
  import/                           开启 CAS 后为空（目录保留，回收逻辑不变）
```

清单（`org.json`，UTF-8，无 BOM）：

```json
{
  "format": 1,
  "vkey": "import:v1607.apk",
  "file": "v1607.apk",
  "label": "v160.7",
  "version": "160.7",
  "size": 78237736,
  "added": 1763800000000,
  "md5": "…",
  "apkSha256": "…",
  "arc": { "fingerprint": "1c2914d5ac42", "androidFi": 16, "fi": 69, "eligible": true },
  "entries": [
    { "p": "assets/sprites/sprites.png", "s": "<sha256>", "n": 4303916, "c": 123456789, "t": 1690000000 },
    { "p": "lib/arm64-v8a/libarc.so",     "s": "<sha256>", "n": 753520,  "c": 123456789, "t": 1690000000 }
  ]
}
```

- 路径按 **APK 里的原样**（带 `assets/` 前缀）。`AndroidFi` 建池时自己剥前缀，另一处不重复存。
- `lib/**` 必须收（native 从这里出）；`META-INF/**` 不收（签名在导入时已校验，运行期不用）。
- `c`/`t` 只为重建 APK 用（STORED 需要对 CRC 与时间）。
- 清单是**唯一事实来源**：`Storage` 口径、GC 引用集、补丁的 `targets/<apk sha>`（用 `apkSha256`）都读它。

## 2. 为什么不能只改启动链路

启动本身已经验证过了，但**启动器自己的界面**还会把游戏包当 zip 读。清单（全部在 `app/src/io/mdt/launcher/`）：

| 文件 | 读什么 | 频次 |
|---|---|---|
| `BaseBundles.java:73` | `assets/bundles/bundle.properties` | 进设置/语言时 |
| `BundleNames.java:168` | 多个 `assets/bundles/bundle_*.properties` | 语言列表 |
| `MapLoad.java:113` | `assets/sprites/block_colors.png` | 地图列表（每次刷新） |
| `MapLoad.java:318` | 地图文件里的缩略图（`it.entry`） | 地图列表 |
| `MapStats.java:912/1024` | 地图统计用的图集 | 地图统计页 |
| `MschSheet.java:88/259` | 蓝图预览图集 | 蓝图页 |
| `GameAssets.java:138` | 游戏包里的素材（分享/预览） | 分享相关 |
| `InjectionSources.java:105` | 补丁归因读 `classes*.dex` | 启动记录 |
| `Injector.java:612` | `loadNatives` 抽 `.so` | 每次启动 |
| `Compat.java:135` | 导入时能力探测 | 仅导入 |

⇒ 需要一层 **Pkg（虚拟包）**：`getEntry/inflate/entries` 等价于 `ZipFile`，数据来自清单 + 对象池。
不改这层，开 CAS 后地图页、模组页、蓝图页会直接报错。

> 反过来说：这些读点都只取**几个小条目**（几百 KB 级），虚拟包不需要支持流式大文件，实现很薄。

## 3. 组件

### 3.1 `Pkgs.java`（对象池服务，新文件 ~350 行）

```java
final class Pkgs {
    static Pkgs get(Context ctx);                       // app_hub/pkgs
    File root(), objectsDir(), manifestsDir();
    Manifest ingest(File apk, String vkey, String label, String version) throws IOException;
    Manifest load(String vkey);                          // null = 没有/坏了
    void write(Manifest m);
    void remove(String vkey);                            // 删清单（对象交给 GC）
    int gc(Set<String> referencedObjects);               // 复用 Cas 的宽限期语义
    Pool stats();                                        // 对象数 / 实际占用 / 孤儿
}
```

- 对象路径与 `Cas` 完全一致（`<2>/<62>`），**复用 `Cas` 的 GC 宽限期**（`GC_GRACE_MS`）与 `BULK_LOCK` 思路；
  但对象**必须 `setReadOnly()`**——`Cas.put` 不设只读，所以入库写成 `Pkgs` 自己的流式实现
  （读 zip 条目 → 写 `tmp/*.part` + 喂 sha256 → rename → `setReadOnly`）。
- 入库吞吐已实测：单包 739 条目 / 856 ms（含解压）；4 线程 239 ms/包；7 包串行 2.2 s。

### 3.2 `PkgVersion`（清单句柄，`Pkgs` 内部类）

```java
File[] dexObjects();                       // classes.dex, classes2.dex…（顺序即 dexPath 顺序）
File assetObject(String pathNoAssetsPrefix);
File nativeObject(String abi, String name); // lib/<abi>/<name>
void fillAssetMap(Map<String,File> out);    // 给 AndroidFi.init 用（键 = 剥掉 assets/）
byte[] read(String apkPath);                // 虚拟包用
```

### 3.3 `ArcAbi.java`（导入时判定，新文件 ~250 行）

设备端解析 `classes*.dex` 的 `class_defs`（`PatchDex` 已有 dex 头/class_defs 解析可复用，补上
`class_data` 的 method 列表即可），对 `Larc/backend/android/AndroidFi;` 与 `Larc/files/Fi;` 取声明方法集：

1. `AndroidFi` 父类必须是 `Fi`；
2. 该版本 `AndroidFi` 声明的**每个**方法，要么我们覆盖了，要么同版本 `Fi` 里有（否则运行期 `NoSuchMethodError`）；
3. 我们 `super.*` 调用的 12 个 `Fi` 方法该版本必须都有。

三条全过 ⇒ `eligible=true` 并记录 `fingerprint`（AndroidFi 方法集的 sha1 前 12 位）。
常量表（`OVERRIDE_ANDROIDFI` 24 条、`SUPER_FI` 12 条）由 `tools/abi-scan` 的输出生成，
写死进代码，并用 `SelfTest` 校验「与 override.dex 一致」。
**未知指纹 ⇒ 不可用 ⇒ 该版本走原 APK**（退化方向安全）。

### 3.4 `Importer` 改造（`importApk0`）

现有顺序保持：`.part` 拷贝 → 大小/dex/Compat → 签名询问 → `setReadOnly` → 预热 → rename → config。
只在**预热通过之后**插一个分支：

```
if (Config.get().casEnabled() && abi.eligible) {
    manifest = Pkgs.get(ctx).ingest(tmp, "import:"+base, label, version);
    Pkgs.write(manifest);
    cleanup(tmp);                       // 不 rename 到 import/
    config 条目加 "cas": true, "apkSha256": …, "abi": fingerprint
} else {
    走老路（rename 到 import/<base>）
}
```

- 入库失败 ⇒ `cleanup(tmp)` + 删半截 manifest，报错；**不动**已在库里的同版本（与现在的「旧副本留到最后」语义一致）。
- `tryLoadClass` 预热仍读 tmp APK（导入时一次性成本，可接受）。

### 3.5 `Injector` 改造

`Plan` 增加 `public PkgVersion cas;`（null = 老路）。四处：

| 处 | CAS 分支 |
|---|---|
| `prewarm`（`:434-449`） | `dexPath = override.dex + File.pathSeparator + cas.dexObjects()`，仍重试 3 次 |
| `injectDex`（`:457-467`） | 同上；`appendDexElements` 之后调 `AndroidFi.init(cas.fillAssetMap())` |
| `loadNatives`（`:610`） | 从 `cas.nativeObject(abi, name)` 拷到 `natives/<abi>/<tag>/` 再 `System.load`（现成的落盘与预热逻辑不变） |
| `mountAssets`（`:784`） | **跳过 `addAssetPath`**，日志写「未挂载 APK，走同名类覆盖」；`probeAsset` 只在 dev 打点 |

`AndroidFi.init` 必须在**游戏类初始化之前**完成（现在 `injectDex` 之后就是 `loadNatives`/`startGame`，
顺序天然满足；但 `Compat`/`GameAssets` 之类如果提前摸 `Core.files` 要留意）。

### 3.6 `GameSlot` 改造

`Versions.Entry` 增加 `boolean cas; String apkSha;`（`scanImported` 从 config 条目读）。
`GameSlot`：`plan.apk` 仍可为 null；`if (e.cas) plan.cas = Pkgs.get(this).open(e.key());`

### 3.7 虚拟包 `Pkg` + 8 处读点适配

```java
final class Pkg {                    // 只读视图，可复用
    static Pkg open(Context ctx, Versions.Entry e);   // CAS → 清单；老路 → 真 ZipFile 适配
    boolean has(String name);                         // 自动兼容带/不带 assets/ 前缀
    long size(String name);
    byte[] read(String name);
    InputStream stream(String name);
    List<String> list(String prefix);
    void close();
}
```

8 处改成 `Pkg p = Pkg.open(...)` + `p.stream(name)`：`BaseBundles`、`BundleNames`、`MapLoad`、
`MapStats`、`MschSheet`、`GameAssets`、`InjectionSources`、`Blueprints`（容器可能是地图文件，保持 ZipFile）。
**不动** `Compat`（只在导入时读 APK）、`Exporter`/`MapStats` 里读**地图/存档**的地方。

### 3.8 设置项（用户明确要求）

- `Config`：`casEnabled()` / `setCasEnabled(boolean)`，key `cas_game`，`DEF_CAS = false`（默认关）。
- 设置页：**设置 → 存储 → 「游戏包去重（CAS）」**，副标题动态显示「已导入 N 个版本，可省约 X」；
  点一下弹 `CardStack` 确认（说明会删原包、可关闭后重建）。
- **开启**（后台 + `Work` 前台服务）：空间预检 → 逐包 `Pkgs.ingest`（7 包 2.2 s）→ 校验清单 →
  删 `import/*.apk` → `Config` 置位 → 通知刷新。
- **关闭**：逐版本重建 APK（按清单 STORED + `lib/**` 全收）→ 预热校验 → 写回 `import/<file>` →
  更新 config → 删池。重建**不保证与原包字节一致**（zip 元数据变了），所以校验口径是
  「条目 sha 全对 + 能预热出入口类」，并且要提示「已重建」。
- 运行中禁止切换（`WriteGate`）；分身/平行空间各自独立（各有一份 `app_hub`）。

### 3.9 GC 与多实例

- 引用集 = **全部清单**的 sha 并集（不是"正在跑的"——启动不再 materialize，运行期不占临时文件）。
- 对象被任何清单引用即留；`GC_GRACE_MS` 内不删；`BULK_LOCK` 期间不删。
- 删版本：`WriteGate.blockedVersion` 拦住"在跑"的；删清单 → 触发一次增量 GC。
- 多实例共享对象池：对象只读、按 sha 寻址，天然安全；`AndroidFi.init` 用的是**每个进程自己的** Map。
- 稳态占用：7 版本 ≈ 208 MB（实测 216,962 KB），单版本 ≈ 85.6 MB。

### 3.10 存储口径（`Storage.Report`）

新增 `gamePoolBytes/gamePoolObjects`（`Pkgs.stats()`），CAS 开启时 `importBytes` 归零；
`text()` 的「游戏包」一行改成「游戏包（去重后）」，与备份池分开写，不混进 `otherBytes` 的减法里。

### 3.11 补丁 / 缓存 / 启动记录

- `apkSha256` 进清单 ⇒ 补丁 `targets/<apk sha256>` 语义不变（`Patches` 读 manifest 而不是重算 APK）。
- `CacheEpoch.sig()` 里的 `apkSha` 用 manifest 的值。
- `Patches.writeLaunchRecord` 的载体路径：CAS 版本没有 APK 路径 ⇒ 记 `""` + `vkey`（崩溃归因改读池）。

## 4. 分期与验收

| 期 | 内容 | 工期 | 验收（真机） |
|---|---|---|---|
| **P0** | 实验：跳过 `mountAssets`，dex/native 全从池，启动一次 | 0.5 天 | 进主菜单；`report-launch.txt` 无资产挂载行；`MDT-PoolFi` HIT 正常 |
| **P1** | `Pkgs`+清单+`ArcAbi`+`Importer`+`Injector`+`GameSlot`+override.dex 打进 assets（构建步骤） | 2 天 | 开 CAS 导入 v160.7 → 删原包 → 启动进主菜单；`Storage` 数字与 `du` 对得上 |
| **P2** | `Pkg` 虚拟包 + 8 处读点 | 1.5 天 | 地图列表有缩略图、模组页、蓝图预览、语言列表全正常 |
| **P3** | 设置项 + 双向迁移 + GC + 多实例 + 文案 | 1 天 | 开关来回切两次不丢包；两实例并行；删版本被拦 |

**P0 先做**：它是唯一还没被验证的假设（不挂 APK 时资产链是否干净）。半天就能出结论，
失败的话整套 P1 的设计要改（要保留 `addAssetPath` 但换成物化包——回退到旧方案）。

## 5. 风险

1. **`addAssetPath` 缺失**（P0 验证）：任何绕过 `AndroidFi` 的 `AssetManager` 直读会炸。
   已知唯一风险点：游戏内第三方代码（模组/扩展）直接用 `getAssets()`。
2. **ABI 漂移**：新版本方法集变化 ⇒ 判据拒绝 ⇒ 走原 APK（安全退化），但用户会发现"这版不省空间"。
3. **重建 APK 字节不一致**：会改 md5；补丁的 `targets/<sha>` 必须改用清单里的 `apkSha256`（原始值）。
4. **导入变慢**：多 ~0.5 s/包；70 个包 35 s，需要进度显示。
5. **开关误操作**：关闭时重建失败 ⇒ 保留 CAS 状态并报错，不允许"半开半关"。
6. **存储碎片**：对象池 1147 个文件 / 7 版本，`du` 块开销 +3.7 MB（已实测，可接受）。

## 6. 已定的取舍

- **不做**物化包（P0 后如果 `addAssetPath` 必须要有，再回退到物化方案，代价 83 MB 常驻）。
- **不做**按"版本对版本"的差分（按条目 CAS 已覆盖）。
- **不碰**存档备份那套 CAS（`Cas`/`Backup` 继续独立）。
- 默认关：不开开关的路径**一行都不变**，风险面为 0。
