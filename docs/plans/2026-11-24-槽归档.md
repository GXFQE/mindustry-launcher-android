# 槽归档（2026-11-24）

> 状态：**设计定案，未开工**。规则由用户 2026-11-24 定的（§1），动手前先读 §8 的边界。
> 一句话：**归档 = 存一份「不计入备份数量」的快照 + 把槽清空 + 打标；这个槽从此「等于没玩过」，绑它的实例一律不能启动；解除归档 = 恢复快照 → 删快照 → 删标记。**

## 1. 用户定下的规则（原话要点）

1. 归档 = 创建一份归档备份（**不计入备份数量**），然后清空该槽；归档后该槽「等于没玩过」。
2. **关联此槽的实例禁止启动**（按槽判，不挑行）。
3. **默认槽不能归档，当前槽可以归档**。默认槽 = 设置页「默认槽」那一项（`Config.defaultSlot()`，空串 ⇒ 回落 `default`）。当前槽恰好是默认槽 ⇒ 归档按钮**灰掉**（附一句「默认槽不能归档 —— 先在设置里换一个默认槽」）。
4. **已归档的槽不能再归档**（入口不出现 + 代码里也要校验）。
5. **解除归档 = 恢复快照 → 删快照 → 删标记**；恢复成功才删快照（失败保留，可重试）。
6. 入口放**槽页右上角 ⋮**（与 改名 / 克隆 / 复制设置 / 删除 同层）；已归档时该项变成「解除归档」。
7. 归档槽上原来那行「整槽导出」变成「**导出归档备份**」：导出快照内容，zip 结构与整槽导出一致（`saves/`、`mods/`、`settings.bin`… 原相对路径），导出来能直接「整槽导入」放回去。
8. 归档槽**只留归档备份本身**：槽页四行内容（模组 / 存档 / 地图 / 蓝图）与「复制设置」**全部变灰、点不动**；能用的只有 ⋮ 里的「解除归档 / 删除」和「导出归档备份」。**读也要拦**（不是只拦写）—— 槽本体已经没了，任何"看一眼内容"的入口都不许把空当成"这个槽是空的"。
9. 归档快照**每槽至多一份**，不累积；备份列表里**不计入「N 份」**，那一行的动作只有「解除归档 / 删除」。
10. 删槽时归档快照跟着 `Backup.deleteSlotBackups` 一起进中转站（不丢）。
11. **别的槽不能从归档槽复制设置**：复制设置的「源槽」候选里排除归档槽；目标槽是归档槽时直接拒绝（与 §8 写门禁同一份判据）。
12. **主页上绑这个槽的实例行要变灰**：行变暗、点行不启动；挂「已归档」徽标（槽页 ⋮ 才有解除入口）。
13. **归档槽恰好是当前槽时，顶栏「继续上次」快捷启动直接消失**（不是变灰 —— 没有东西可继续）。

## 2. 状态位：槽目录里的 `.archived`

```
slot-<名>/.archived     一行 JSON：{"at":<毫秒>,"snapshot":"<快照目录名>"}
```

**为什么不是写进 `config.json`**（`Config` 里再开一个「已归档槽」集合）：

- 改名 / 删槽**自动跟随目录**，不用去 `Config.retargetSlots` 里加第六处（那里已经五处，漏一处就是悬空归档）。
- 点开头文件本来就不算「槽内容」：`Data.contentSkipped` 会把 `.` 开头的排除在 `contentRootsOf` 之外
  ⇒ 它**不进备份、不进整槽导出、也不会被 `SlotWrite.wipeSlot` 删掉**（清空正好要留着它）。
- `Backup.cloneSlot` 是「备份源槽 + 恢复进新槽」，恢复只写清单里的文件 ⇒ 标记**不会**被克隆带过去。
- 缺少目录 / 标记解析失败 ⇒ 一律按「未归档」处理（宁可多让玩一次，也不要误锁）。

新增 `app/src/io/mdt/launcher/SlotArchive.java`（纯静态）：

- `Marker read(Context, String slot)`（`null` = 未归档 / 坏标记）
- `boolean isArchived(Context, String slot)`
- `boolean write(Context, String slot, String snapshotDirName)`
- `boolean clear(Context, String slot)`
- `boolean canArchive(Context, String slot, String[] why)` —— 纯判据，自检直接调：
  ① 槽存在；② 未归档；③ 不是默认槽（`Config.defaultSlot()` 空 ⇒ `default`）；④ `!WriteGate.blockedSlot(ctx, slot)`。

## 3. 归档快照：`Backup.Snapshot.kind`

清单头多一个键（`Backup.writeManifestTo` 在六键之后写、`readManifest` 未知键本来就忽略，旧快照读回来 `kind=0`）：

```
kind=archive        # 0/缺省 = 普通备份；1/archive = 归档
```

- `Snapshot` 加 `public final int kind;`（`KIND_NORMAL = 0`、`KIND_ARCHIVE = 1`）。
- `Backup.create(ctx, slot, label, kind)`；原三参 `create` 委派 `kind = KIND_NORMAL`。
- 供界面的过滤 helper（别让每个调用点自己写 `if`）：
  - `static List<Snapshot> normal(Context, String slot)`
  - `static List<Snapshot> archives(Context, String slot)`
  - `static Snapshot archiveOf(Context, String slot)`（至多一份；按 `created` 取最新兜底）
- 归档快照的 `label` 固定写 `slot_archive_label`（「归档」，走 `Trans`），`source` 记 `archive`。

## 4. 归档流程（`SlotOps.archiveSlot`）

```
① SlotArchive.canArchive(...) 不通过 ⇒ 弹提示，返回
② 用户确认（卡片：会清空这个槽、保留一份归档备份、关联版本将不能启动）
③ Backup.create(ctx, slot, 归档, KIND_ARCHIVE)      ← 先存；失败就什么都没发生
④ SlotWrite.wipeSlot(ctx, slotDir)                  ← 已有唯一实现（写门禁也在里面）
   失败 ⇒ Backup.delete(刚建的那份) + 报错返回（不能留下「有归档、槽却没清」的半成品）
⑤ SlotArchive.write(ctx, slot, 快照目录名)
```

为什么要 ③ 在 ④ 前：**先有退路再动刀**。若先清后存，存失败就是「数据没了、归档也没有」。

## 5. 解除归档流程（`SlotOps.unarchiveSlot`）

```
① 读标记 ⇒ 快照目录名；找不到快照（被手动删了）⇒ 提示「归档快照已不在」，给一个「只解除标记」的出口
② Backup.restore(ctx, slot, ss, MODE_MERGE)  ← 现有实现是「只增不删的合并」，正好用于空槽
③ 成功 ⇒ Backup.delete(ss) + SlotArchive.clear(...)
   失败 ⇒ 保留快照与标记，报错（可重试）
```

槽在归档期间应当一直为空（§8 会把写入也拦掉），所以「合并」等价于「整体恢复」。

## 6. 启动拦截：两层

| 层 | 位置 | 行为 |
|---|---|---|
| 界面（好说话、能弹卡） | `MainActivity.startVersion(...)` 一进来，按 `Versions.slotFor(e)` 算槽 | 归档 ⇒ 弹卡「这个槽已归档」+ 按钮「去解除归档」（进 `SlotActivity`）/「取消」；`cb.state(BLOCKED, "archived")` |
| `:game`（权威，覆盖 dev / 插件入口） | `GameSlot.handle`，`provSlot` 解析之后、`Data.prepareSlot` **之前** | `fail(step_prepare, R.string.slot_archived_fmt)` |

两层都用 `SlotArchive.isArchived(...)`（同一份判据，不各写一遍）。

## 7. 导出归档备份

入口：`SlotActivity` 的「整槽导出」那一行在归档状态下改成「导出归档备份」。

实现（**直接从 CAS 流进 zip，不落临时目录、不走 restore**）：

- `Backup` 暴露 `static void zipSnapshot(Context ctx, Snapshot ss, ZipOutputStream out, ...)`：
  读清单 `hash\tsize\trel`，逐行 `cas(ctx).objectPath(hash)` ⇒ `Exporter.Src.ofFile(obj, rel)`
  ⇒ 交给现有的 `Exporter.zipSourcesTo(...)`（它已带 SAF 目标、失败只删「写入前 SIZE==0 的新目标」的纪律）。
- 条目名 = 清单里的 `rel`（磁盘相对路径，正斜杠），与整槽导出完全同构 ⇒ 能被整槽导入吃回去。
- 写后校验沿用 A14：zip 逐条 CRC32（`ZipFile` 读 EOF 不校验 CRC）。

## 8. 边界与风险：**读与写都要拦**

用户 2026-11-24 追加的硬要求：**「因为只剩下归档备份，槽本体已经没了，所以一定要拦截所有读取和写入。」**
判据只有一份：`SlotArchive.isArchived(ctx, slot)`；下面每一层都调它，**不许各写一份 if**。

| 面 | 位置（示例） | 归档槽上的行为 |
|---|---|---|
| 槽页内容行 | `SlotActivity` 的模组 / 存档 / 地图 / 蓝图 / 复制设置 | **灰掉、点不动**（不隐藏：让用户看见"这里本来有东西，现在在归档里"） |
| 槽页 ⋮ | `app/res/menu/slot.xml` | 归档项变「解除归档」；默认槽 / 已归档时灰 |
| 整槽导出 | `SlotActivity` 导出那一行 | 换成「导出归档备份」（走 §7），不导出空槽 |
| 备份与恢复 | `SlotOps.backups(...)` / `Backup.list` | 只列归档快照那一行；普通备份按空槽处理（本来也没有） |
| 主界面实例行 | `MainActivity` 的行渲染 | 绑归档槽的行**变灰**、点行不启动、挂「已归档」徽标（`管理` / 长按仍进版本页，方便换槽） |
| 顶栏快捷启动 | `MainActivity` 的 `btn_continue` | 当前槽已归档 ⇒ **GONE**（不是变灰） |
| 复制设置 | `SettingsCopyUi` 的源槽候选 / 目标槽校验 | 源槽排除归档槽；目标是归档槽 ⇒ 拒绝 |
| 主界面启动 | `MainActivity.startVersion` | 拦（§6） |
| `:game` 启动 | `GameSlot.handle` | 拦（§6，权威） |
| 主界面行上的数据 | `MainActivity.fillSlotBackupCounts` / `VersionOps.backupCountIn` | 归档快照**不计入**；行上挂「已归档」 |
| 槽列表 | `SlotsActivity` / `Data.contentCounts` | 计数为 0 + 徽标；不读目录 |
| 换槽 / 默认槽 / 深链落点 | `VersionOps.slotList` / `SettingsActivity.pickDefaultSlot` / `DeepLink.askSlot` | **从候选里排除**归档槽 |
| 导入（整槽 / 存档 / 模组 / 批量） | `SlotIo.importSlotDoc` / `BatchIo` / `Exporter` | 目标槽归档 ⇒ 拒绝并提示「已归档，先解除归档」 |
| 宿主写口 | `WriteGate` 之外新增：凡是拿槽名直接写盘的入口 | 归档 ⇒ 拒绝 |
| 插件 API（读） | `PluginHost.slots()` / `PluginData.slots` | **不列出**归档槽 |
| 插件 API（按槽读写） | `PluginHost.resolveSlot(...)`（设置读写、加条目、删条目都过它） | 归档 ⇒ `null` ⇒ 插件侧 `not-found`（不崩） |
| 插件 API（原始目录） | `PluginHost.slotDir()` / `savesDir()` / `modsDir()` / `mapsDir()` / `blueprintsDir()` | 归档 ⇒ 抛 `IllegalStateException("slot archived: <名>")`（不给文件句柄，否则读写都绕过去了） |
| 自动备份 | `AutoBackup.settle` | 跳过归档槽（防给空槽造普通备份） |

其余风险：

1. **恢复是合并语义** ⇒ 只有在「归档期间一直是空的」前提下才等价于整体恢复；这就是上表必须把读写都堵死的原因。
2. **默认槽候选**：`SettingsActivity.pickDefaultSlot` 排除归档槽；外部把归档槽设成默认槽 ⇒ 不崩，但启动仍被拦，归档入口按「默认槽不能归档」优先报错。
3. **未结算会话**：归档动作前先结算该槽，`AutoBackup.settle` 也跳过归档槽。
4. **当前槽被归档**：指针不动（用户要的「等于没玩过」），主界面「继续上次」若指向它 ⇒ §6 拦下并给解除入口。
5. **插件接口**：`api/SlotInfo` 不加 `archived` 字段（`DOC_VERSION=52` 不动）——归档槽直接**从 `slots()` 里消失**，插件看到的是"没有这个槽"。

## 11. 自检断言（都能在宿主时钟 / 临时槽里跑，不碰真机数据）

1. `SlotArchive` 标记读写 round-trip；坏 JSON / 缺目录 ⇒ `null`。
2. `canArchive` 四态：默认槽拒绝、已归档拒绝、游戏在跑拒绝（`WriteGate` 用假实例）、正常通过。
3. 清单 `kind=` round-trip；**旧清单（没有该键）读回来 `KIND_NORMAL`**（向后兼容断言）。
4. `AutoBackup.trim`：普通备份到上限会淘汰、归档快照**不占名额**（造 1 归档 + max 份普通，断言归档还在）。
5. `VersionOps.backupCountIn` 不含归档。
6. 归档 → 解除归档：快照被删、标记被清、内容回来（用临时槽 + 小文件）。
7. 归档失败路径：让 `wipeSlot` 失败 ⇒ 快照被回滚删除（造只读文件或假 root）。
8. 启动判据：`isArchived` 为真 ⇒ `startVersion` 的门与 `GameSlot` 的门都返回 BLOCKED（纯判据层）。
9. **读拦截**：`PluginHost.slots()` 不列归档槽、`resolveSlot` 返回 null、五个目录 getter 抛异常（用假槽 + 自检里构造的 `Context` 不可行时，把判据抽成 `SlotArchive.gateForPlugin(slot)` 纯函数单独断言）。
10. **候选排除**：`VersionOps.slotList` / `SettingsActivity` 默认槽候选 / `DeepLink` 落点列表都不含归档槽（把"挑候选"抽成纯函数后断言）。
11. 导出归档备份：清单 → zip 的条目名与清单 `rel` 一致、CRC32 校验通过。
12. UI 判据抽纯函数各断言两态：实例行是否变灰 / 顶栏快捷启动是否显示（当前槽归档 ⇒ 不显示）/ 复制设置源槽候选是否排除归档槽。

## 12. 不做

- 每槽多份归档（用户要「不能把已经归档的再归档」⇒ 一份，解除即删）。
- 归档后保留 `settings.bin`（用户要「清空」；快照里有）。
- 插件接口暴露 `archived`（要暴露再抬 `DOC_VERSION`）。
- 把归档槽从「存档与备份」页隐藏（用户要看得到、也才有地方解除）。
