## 二、批次

### 批 1：两个解析器的「读不出来」原因（约 80 条）

> ✅ **2026-10-25 第 240 轮已核对**：`MsavMeta` / `Msch` **早就**是「码 + 参数 + `MsavText` / `MschText` 映射」，
>   界面调用点全走映射（`Maps` / `Blueprints` / `MapFiles` / `BlueprintDetailActivity` / `BatchIo` / `PluginData`）；
>   `error` 里的中文只剩**报告 / 异常兜底**，不进第一层 ⇒ **不翻**。
>   真正缺的是**尺子**：两个 `*Text` 的注释都写「自检遍历所有码」，实际只有 `SettingsBin` 那段在遍历 ——
>   本轮补了 3 条断言（存档 8 个码逐个非兜底 + 不同码不同话；蓝图 14 个码逐个非兜底），
>   自检 1594 → **1597 / 0**。
>   ⇒ 本节剩下的约 80 条**不是待搬**，是报告类（B）；台账数字保留，不再当 P3 进度。

- `MsavMeta`（32）：`m.error = "…"` → `m.errCode` + `Object[]` 参数；`MsavText` 加 `reason(ctx, meta)` 映射；
  存档列表/详情调用点改用它。
- `Msch`（46）：同上，`MschText` 已有 22 处资源，按同一形状补。
- `MapStats` 里「地图读不出来 / 内容定义表读不出来」2 条（地图详情）。
- 自检：把断言从「比中文串」改成「比错误码」（`SelfTest` 现有 14 条级 A 断言，见可行性 §7.7）。
- 判据：`SRC-02` 台账 `MsavMeta` / `Msch` 两行降；`SRC-01` 仍 0；自检 zh / en 两遍都全绿。

### 批 2：模组 / 设置的失败原因（约 60 条）

- `SettingsBin.Result` **已经有码**（`E_NO_SLOT_DIR` / `E_GAME_RUNNING` / …）——只是 `fail()` 同时塞了一句中文。
  ⇒ `SettingsText.userReason()` 补齐这些码的映射，中文降级成 fallback（`report()` 仍可原样打印）。
- `Mods` 的 `fail()` 复用 / 新增码；`ModsText` 补映射。
- 判据同上；另加一条元断言：**每个 `E_*` 码都有资源**（漏一个就会静默回落中文）。

### 批 3（可选）：A′ 层

决定**不翻** `report()` / `changeDesc` —— 它们是「技术细节」层，用户点开是为了贴给维护者。
写进 `docs/DEVELOPING.md`，并让 `SRC-02` 台账把这几行标成「有意保留」。

## 三、每批的固定动作

1. 先加码/参数，**保留旧中文作 fallback**（分两步走，别一把删）；
2. 调用点传 `ctx`（`*Text` 映射层已有，别在静态层碰 `android.*`）；
3. `SelfTest` 断言改成判码；跑 **zh / en 两遍**（P1-B，见可行性 §7.7）；
4. 台账只许降；`SRC-01` 仍须 0；
5. 真机看一屏（错误路径至少造一次：坏存档 / 坏蓝图 / 游戏在跑时改模组）。
