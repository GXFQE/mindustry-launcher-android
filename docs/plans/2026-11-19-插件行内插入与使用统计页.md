# 插件行内插入（inline）与「使用统计」页 —— 设计草案

> 2026-11-19 第 398 轮。**未实现，先落文档。**
> 用户原话：「宿主这个接口能不能给所有可文本插入部分都加上，比如允许加入一个小的按钮」→
> 「直接给个预设类型就行，大小做过防呆限制就行，不用搞得很死」→「其实应该都用百分数吧」→「先进文档」。

## 1. 目标与边界

- 插件能在宿主**文本行的尾部**插入一个预设小控件（按钮 / 徽标 / 短文字），宿主统一排版，插件不碰尺寸。
- **不做**任意 View、任意尺寸、任意图标：只给三种预设，宿主做防呆。
- 首批只开两个锚点（主界面「游戏时长」行尾、槽页「游玩时长」卡头），跑通再扩。
- 同时新增宿主「使用统计」页（`usage`），给热力图一个落脚点；内容由插件 `page: usage` 的 section 提供。

## 2. inline 声明（`plugin.json`）

```json
{
  "id": "usage-open",
  "entry": "io.mdt.plugins.usagestats.UsageStats",
  "slot": "inline",
  "place": "main.playtime",
  "kind": "button",
  "title": "统计"
}
```

| 字段 | 说明 |
|---|---|
| `slot` | 固定 `inline` |
| `place` | 锚点名，白名单见 §3；认不出的锚点 ⇒ **不画、不回落**（inline 是行内装饰，不是独立行） |
| `kind` | `button` / `chip` / `text`，只认这三种；别的值当未知 ⇒ 不画（日志一行） |
| `title` | 显示文字；短（建议 ≤ 8 个字符），超长由宿主 ellipsize |

- **点击**：宿主调用插件的 `run(PluginApi)`（与 `action` 同一套），插件自己决定开哪页。
- **同一锚点多个插件**：按扫描顺序，最多 2 个；第 3 个起不画（写一行日志）。
- **插件停用 / 加载失败**：不画；锚点所在的行照常显示，行本身不因插件变空。

## 3. 锚点（第一版）

| 锚点 | 位置 | 页面 |
|---|---|---|
| `main.playtime` | 主界面摘要卡「游玩时长」行尾 | `main` |

- 后续按需扩（`main.summary` 摘要卡其他行、`slot.total` 槽页合计行…），**不一次开满**。
- ⚠️ **槽页「游玩时长」卡头不开放**（原草案写过 `slot.playtime`，实现时发现不成立）：那张卡是
  `usagestats` 自己的 `section`（标题行在插件 View 内部），宿主插不进去。要在卡头放东西，
  只能插件自己在 `createView` 里画（那就不需要宿主接口）。
- 锚点认不出 ⇒ 不画（不回落「插件」卡）。

## 4. 防呆（宿主统一，全部用百分数）

- 高度 ≤ **行高的 80%**（随行高 / 字体缩放实时算）；
- 宽度 ≤ **行宽的 40%**，文字 ellipsize；
- 字号、内边距、圆角、颜色统一：`button` 用 accent 底 / `onAccent` 字，`chip` 用淡强调底，`text` 用 `textMuted`；
- 每个锚点最多 2 个；
- 超限（比如大字体下放不下）⇒ 缩字号；再放不下就不画（不撑破行）。

## 5. 「使用统计」页（`usage`）

- 宿主新增 `UsageActivity`，标题「使用统计」，布局照抄槽页骨架（ScrollView + 卡片 + `plugin_section`），`pluginPageId()` 返回 `usage`。
- `Extensions.PAGE_USAGE = "usage"`，加进 `knownPage` 白名单；`AndroidManifest` 注册（`exported=false`，与其他子页面一致）。
- **入口**：主界面「游戏时长」行尾的 inline `button`「统计」→ `startActivity(UsageActivity)`。
- 插件：`plugin.json` 加 `page: usage` 的 section；`createView` 按 `api.page()` 分支返回「热力图 + 范围/粒度选择」。
- 插件没启用 ⇒ 入口按钮不出现（inline 由插件声明）；「游戏时长」行照常显示，不因插件缺失而消失。

## 6. 接口版本

- `PluginHost.API` / `PluginApi.DOC_VERSION` / `docs/PLUGIN-API.md` 区间：45 → **46**（三个数一起改）。
- 用了 inline / `usage` 的插件在 `plugin.json` 写 `"api": 46`；usagestats 跟着升。

## 7. 改动面

**宿主**

- `Extensions`：`PAGE_USAGE`、`SLOT_INLINE`、两个锚点常量、`knownPage`、`forPlaced` 支持 inline。
- `PluginEntries`：inline 的收集 / 锚点定位 / 插入（参考现有 `attachPlacedAtRow`）。
- `UsageActivity` + 布局 + manifest。
- `MainActivity`：`main.playtime` 行尾容器（`LinearLayout` 包住文字 + inline 位）+ 挂载 + 点击启动统计页。
- `SlotActivity`：`slot.playtime` 锚点容器。
- `SelfTest`：白名单 / kind 白名单 / 尺寸上限 / 每锚点最多 2 个 / 停用不画 / `usage` 可挂 / 入口 Intent 目标。

**插件**

- `plugin.json`：inline 条目 + `page: usage` 的 section。
- `UsageStats`：`run()`（打开 usage 页）、`createView` 分支、热力图 + 范围/粒度选择。

## 8. 判据（自检要钉的）

- inline 只认 `button` / `chip` / `text`；未知 kind 不画（日志一行）。
- 锚点白名单外的 `place` 不画。
- 同一锚点第 3 个不画。
- 插件停用 ⇒ 不画，行本身不变。
- 尺寸：高度 ≤ 行高 80%、宽度 ≤ 行宽 40%（夹具给不同行高 / 行宽，钉「不超」）。
- `usage` 在 `knownPage` 里；`page: usage` 的 section 能挂上（与 `forPage` 同口径）。
- 「游戏时长」行尾按钮点击拉起 `UsageActivity`（参考 `VersionActivity.slotIntent` 那条：抽出来钉 Intent 目标，不靠真机点）。

## 9. 未定 / 后续

- 锚点命名要不要带版本（`main.playtime` vs `main.playtime.v1`）。
- 多插件同一锚点的排序：扫描顺序 / 插件 id。
- RTL 与横屏的按钮位置。
- `chip` / `text` 第一版真的会有人用吗？可能只实现 `button`，另两种留在协议里。
- 点击是否允许「默认打开插件页」（省得每个插件写 `run`）。

## 10. 实施顺序（建议）

1. 宿主 inline 骨架 + `main.playtime` 锚点 + 自检（不依赖插件，可先验）。
2. 宿主 `usage` 页 + 入口按钮。
3. 插件 `usage` section（热力图 + 范围/粒度选择 + 纵向滚动 + 对齐）。
4. 真机：主界面行尾按钮 → 统计页 → 图 / 范围切换 / 自定义日期。
