# 插件行内插入（inline）与「使用统计」页 —— 设计草案

> 2026-11-19 第 398 轮。**未实现，先落文档。**
> 用户原话：「宿主这个接口能不能给所有可文本插入部分都加上，比如允许加入一个小的按钮」→
> 「直接给个预设类型就行，大小做过防呆限制就行，不用搞得很死」→「其实应该都用百分数吧」→「先进文档」。

## 1. 目标与边界

- 插件能在宿主**文本行的尾部**插入一个预设小控件（按钮 / 徽标 / 短文字），宿主统一排版，插件不碰尺寸。
- **不做**任意 View、任意尺寸、任意图标：只给三种预设，宿主做防呆。
- 首批只开两个锚点（主界面「游戏时长」行尾、槽页「游玩时长」卡头），跑通再扩。
- 同时新增宿主「使用统计」页（`usage`），给热力图一个落脚点；内容由插件 `page: usage` 的 section 提供。

## 2. inline 声明（`plugin.json`）

```json
{
  "id": "usage-open",
  "entry": "io.mdt.plugins.usagestats.UsageStats",
  "slot": "inline",
  "place": "main.playtime",
  "kind": "button",
  "title": "统计"
}
```

| 字段 | 说明 |
|---|---|
| `slot` | 固定 `inline` |
| `place` | 锚点名，白名单见 §3；认不出的锚点 ⇒ **不画、不回落**（inline 是行内装饰，不是独立行） |
| `kind` | `button` / `chip` / `text`，只认这三种；别的值当未知 ⇒ 不画（日志一行） |
| `title` | 显示文字；短（建议 ≤ 8 个字符），超长由宿主 ellipsize |

- **点击**：宿主**打开该插件的插件页**（`PluginsActivity` 直达模式，page 参数固定 `"panel"`），
  不是跑插件的 `run()`。理由（用户 2026-11-19）：「官方插件可以这么折腾，但第三方没法折腾」——
  插件页直达是宿主已有的通用机制，第三方插件零宿主改动也能有整页；每次给插件加页面都要求
  宿主加 Activity 对第三方不成立。
- **同一锚点多个插件**：按扫描顺序，最多 2 个；第 3 个起不画（写一行日志）。
- **插件停用 / 加载失败**：不画；锚点所在的行照常显示，行本身不因插件变空。

## 3. 锚点（第一版）

| 锚点 | 位置 | 页面 |
|---|---|---|
| `main.playtime` | 主界面摘要卡「游玩时长」行尾 | `main` |

- 后续按需扩（`main.summary` 摘要卡其他行、`slot.total` 槽页合计行…），**不一次开满**。
- ⚠️ **槽页「游玩时长」卡头不开放**（原草案写过 `slot.playtime`，实现时发现不成立）：那张卡是
  `usagestats` 自己的 `section`（标题行在插件 View 内部），宿主插不进去。要在卡头放东西，
  只能插件自己在 `createView` 里画（那就不需要宿主接口）。
- 锚点认不出 ⇒ 不画（不回落「插件」卡）。

## 4. 防呆（宿主统一，全部用百分数）

- 高度 ≤ **行高的 80%**（随行高 / 字体缩放实时算）；
- 宽度 ≤ **行宽的 40%**，文字 ellipsize；
- 字号、内边距、圆角、颜色统一：`button` 用 accent 底 / `onAccent` 字，`chip` 用淡强调底，`text` 用 `textMuted`；
- 每个锚点最多 2 个；
- 超限（比如大字体下放不下）⇒ 缩字号；再放不下就不画（不撑破行）。

## 5. 插件页（`panel`）：**不新建宿主 Activity**

- 复用宿主已有的**插件页直达**：`PluginsActivity.start(a, id, ver, entry, page, slot, label)`。
  - 页面内容 = 插件 `createView` 画什么就是什么；返回键回上一页（`mDirect` 已处理）；
  - `page` 参数原样给插件（`api.page()`），本方案固定传 `"panel"`；
  - **不需要**新 Activity、**不需要** `knownPage`（插件页不经过 `section` 收集）。
- 插件在 `createView` 里按 `api.page()` 分支：`slot` = 槽页卡，`panel` = 统计页（热力图 + 范围/粒度）。
- 入口：主界面「游戏时长」行尾的 inline `button`「统计」→ 宿主打开插件页（page=panel）。
- 插件没启用 ⇒ 入口按钮不出现（inline 由插件声明）；「游戏时长」行照常显示。

## 6. 接口版本

- `PluginHost.API` / `PluginApi.DOC_VERSION` / `docs/PLUGIN-API.md` 区间：45 → **46**（三个数一起改）。
- 用了 inline 的插件在 `plugin.json` 写 `"api": 46`；usagestats 跟着升。
- 点击打开插件页用的是现成的 `PluginsActivity` 直达，**不是**新 API 方法。

## 7. 改动面

**宿主**

- `Extensions`：`SLOT_INLINE`、锚点常量、`PAGE_PANEL`（插件页参数）、`forInline` / `knownKind`；
  **不新增** `usage` 页与 Activity（`PAGE_USAGE` 删掉，这轮刚加、还没发布）。
- `PluginEntries`：inline 的收集 / 插入 / 点击（点击 = `PluginsActivity.start(..., page="panel")`）。
- `MainActivity`：`main.playtime` 行尾容器 + 挂载（已完成）。
- `SelfTest`：kind 白名单 / 每锚点最多 2 个 / 锚点过滤 / 布局 id / 点击目标。

**插件**

- `plugin.json`：inline 条目（`place: main.playtime` / `kind: button` / `title: 统计`）。
- `UsageStats`：`createView` 按 `api.page()` 分支，`"panel"` ⇒ 统计页（热力图 + 范围/粒度选择）。

## 8. 判据（自检要钉的）

- inline 只认 `button` / `chip` / `text`；未知 kind 不画（日志一行）。
- 锚点白名单外的 `place` 不画。
- 同一锚点第 3 个不画。
- 插件停用 ⇒ 不画，行本身不变。
- 尺寸：高度 ≤ 行高、宽度 ≤ 行宽 40%（夹具给不同行高 / 行宽，钉「不超」）。
- `panel` 是插件页参数，**不是** `knownPage`；点击目标 = `PluginsActivity` 且 page extra = "panel"
  （抽成函数钉 Intent，不靠真机点）。
- 主界面「游戏时长」行 + inline 容器在布局里。

## 9. 未定 / 后续

- 锚点命名要不要带版本（`main.playtime` vs `main.playtime.v1`）。
- 多插件同一锚点的排序：扫描顺序 / 插件 id。
- RTL 与横屏的按钮位置。
- `chip` / `text` 第一版真的会有人用吗？可能只实现 `button`，另两种留在协议里。
- 一个插件要多个面板时，用 `panel:xxx` 前缀扩展（第一版只有 `panel`）。

## 10. 实施顺序（建议）

1. 宿主 inline 骨架 + `main.playtime` 锚点 + 自检（已完成）。

3. 插件 `panel` 视图（热力图 + 范围/粒度选择 + 纵向滚动 + 对齐）。
4. 真机：主界面行尾按钮 → 插件页 → 图 / 范围切换 / 自定义日期。
