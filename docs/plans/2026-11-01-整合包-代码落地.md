## 0. v1 的边界（先说死，免得越做越大）

| 做 | 不做（v2+） |
|---|---|
| 本地文件导入 / 导出（SAF） | 在线一键（mdtbbs `Pack`） |
| **只装进新建槽或空槽** | 合并进已有槽（`settings.bin` 合并语义会变成第二个"整槽覆盖"） |
| 薄包（清单 + 模组 + 内容，不含 APK） | 厚包（包内 APK）—— 先把 `Importer` 的 File 入口留好 |
| 一个槽一个包记录 | 一个槽多个包（要改成 `mdtpacks/<id>.json`） |
| 整包开关 / 删除 / 对账 | 整包更新（diff 清单）—— 先"导入新包到新槽" |
| **包不锁游戏版本**（`game` 只当提示；装的时候按已装版本选） | 版本矩阵 / 按游戏版本分的包库（MC 的旧版断代生态不适用，见可行性 §3.6） |

## 2. 清单 `mdtpack.json`

包根一份、槽根一份（**同一个文件名**）：`SlotZip.extract` 会把它原样写进槽根，于是它**同时是记录**。

```json
{
  "schema": 1,
  "name": "XX 整合包",
  "version": "1.0",
  "author": "",
  "note": "",
  "game": { "variant": "official", "version": "159.7", "build": 159, "revision": 7 },
  "mods": [
    { "file": "mods/xxx.jar", "name": "XXX", "internal": "xxx",
      "sha256": "…64 hex…", "size": 123456, "minGameVersion": "146",
      "dependencies": ["yyy"], "softDependencies": [] }
  ],
  "content": { "saves": 3, "maps": 2, "schematics": 1, "mods": 1 },
  "settings": "mods-only",
  "scrubbed": false,
  "created": "2026-11-01T12:00:00+08:00"
}
```

★ **`game` 可省略；有它也只是提示**（预选目标版本 / 诊断"包是在哪一版上做的"），**不是门禁** ——
  没装它说的那一版照样能装、能绑别的版本（MDT 没有 MC 那种旧版断代生态，见可行性 §3.6）。

校验规则（`PackManifest.read`）：

- `schema` 必须是 `1`；未知版本**拒绝**（不猜）；
- `name` 非空；
- `mods[].file` 必须是**相对路径**：无前导 `/`、无盘符 `X:`、无 `..` 段（与 `SlotZip.cleanPath` 同一套语义，别另写）；
- `sha256` 可缺省（目录形态的模组没法算单文件哈希）；有则必须是 64 位十六进制；
- `game` **可整块省略**；有则 `game.version` 用**格式版本**（`Versions.Entry#formatVersion()`），不是显示版本；
  `game.build` / `revision` 可直接读 JSON 里的数字（**不调 `Versions.parseBuild`** —— `Versions` 带 android，会把本类拖出"PC 可编"的范围）；
  缺 `build`/`revision` 时由 `PackIo` 用 `Versions.parseBuild(game.version)` 现算（只在设备侧跑）；
- 读的时候先按 `SlotZip.Info.strip` 找 `<strip>mdtpack.json`；没有 `strip` 但全包只有一个顶层目录且其中有清单 ⇒ **自己找出这个前缀并写回 `Info.strip`**（否则解包不剥、清单落错层）。

★ **没有清单 = 普通整槽 zip**：老流程一个字都不变（这是向后兼容的判据）。

### 2.1 内容命名空间：为什么「包不能改名」

> 用户 2026-11-01：「模组的建筑会自动重命名，整合包内两个模组互相访问也是个麻烦事」—— 两件事同源，先把机制钉死。

**游戏口径**（`Mods.java:1253` + `ContentLoader.transformName()`，证据见 `ref/23` §77）：

```java
internalName = meta.name.toLowerCase(Locale.ROOT).replace(" ", "-");
content.name = internalName + "-" + <content 文件名>;   // content/blocks/wall2.json ⇒ "mymod-wall2"
```

⇒ 三件事跟着这条公式走：

| 事实 | 后果 |
|---|---|
| 内容 ID = **内部名 + "-" + 文件名**，游戏自动加前缀 | 两个模组都叫 `wall` 也**不会撞**（`a-wall` / `b-wall`）—— 这是**扁平安装的优点**，不是要修的问题 |
| **改 `mod.hjson` 的 `name`** = 改命名空间 | 所有内容 ID 变 ⇒ 旧存档 / 蓝图 / 地图里引用的 `old-wall` 全部「丢内容」 |
| **两个成员内部名相同** | 游戏 `mapping.put()` 后写者覆盖前者（`Mods.java:538`）⇒ 只有一个生效；`Mods.scan` 已经用 `Info.duplicated` + `Scan.problems` 标出来 |

⇒ **包的三条硬规矩**：

1. **永不改写 `mod.hjson`**：文件按原字节安装（`sha256` 钉死），清单里的 `name` 只是显示/记录，**不参与任何重命名**；
2. **永不合并/拆分模组**：两个模组就是两个 `mods/` 条目；"合并"就是 §1.1 的嵌套（8 条边界全塌）；
3. **文件名可以改**（`mods/x.jar` → `mods/y.jar`）—— 内容 ID 与 `settings.bin` 的开关都认**内部名**，不认文件名；
   但改了就会让"同一份包的下一个版本"看起来像换了一个文件（更新 diff 会当删 + 加），所以**导出时不要主动改名**。

**跨模组访问**（内容 vs 类，两条完全不同的路）：

| 方式 | 能不能 | 怎么做 / 为什么 |
|---|---|---|
| **内容**（A 的建筑用 B 的物品/方块） | ✅ 能 | 两个模组都装 + 在 A 的 `dependencies` 里声明 `b` 的内部名；引用写 `b-item`（带前缀）。`Mods.resolveDependencies` 就是游戏那套判据的逐行复刻（缺依赖/不完整/循环都认） |
| **类**（A 的代码 `import b.Foo` / `new b.Foo()`） | ❌ 不行（直接引用） | 每个模组一个 `ClassLoader`（`AndroidLauncher.loadJar` = `new DexClassLoader(...)`，**child-first**）；`dependencies` 只管加载顺序/失效判据，**不合并 classpath** ⇒ 只能反射 / 共享 API / 把公共部分单独做成一个模组 |

⚠️ 所以「整合包里两个模组互相访问」的**正确姿势**不是把它们合成一个包，而是：
**两个都装 + 声明依赖 + 用前缀名引用**。启动器能做的只有三件：**别改名、查依赖、报同名**（下面 §3 第 5 步）。
「建筑显示成 `mod-wall`」是模组自己没写 `block.<name>` 的 bundle 键，**不是包该去改的**（改了就是改写模组）。

## 3. 导入流水线（数据层）

```
SlotZip.stage(uri)                       // 已有：落 app_hub/zip-import.tmp
SlotZip.inspect(tmp)                     // 已有：只读、单遍
PackManifest.read(tmp, inf.strip)        // 新：只读清单
  ├─ null  → 老 flow（SlotIo.confirmZipImport）
  └─ 有     → PackIo.confirmPack(...)
```

`PackIo.confirmPack`（预览卡 → 新槽名 → 执行）：

1. 卡片正文：包名/版本/作者、目标游戏版本、模组 N 个、内容统计（`inf.files/bytes/tops`）。
   **预检（只读清单，不写盘）**：内部名重复 / 必需依赖不在包里 / 目标版本不满足 ⇒ 卡上写清楚；
   - **内部名重复 = 包坏了**（游戏只会加载后一个）⇒ **拒绝**，不往下走；
   - **必需依赖不在包里** ⇒ 写「A 依赖 C，包里没有 ⇒ A 会被关掉」，**不阻断**（用户可能另有来源）。
2. 输入新槽名（默认 `Data.sanitizeSlot(清单 name)`；沿用 `VersionOps.newSlot` 那套 `CardStack` + `EditText`，不新建 layout）。
3. 后台线程：
   ```java
   String err = Data.createSlot(ctx, name);            // 当前槽返回 null 但不建目录 ⇒ 调用前先拒
   SlotZip.Imported im = SlotZip.importSlot(ctx, zip, inf, name, SlotWrite.REPLACE);
   // 新槽，REPLACE 的 wipe 是空操作；AutoBackup 会照常先快照
   ```
4. **选目标版本**（包**不锁**版本；`game` 只是提示 —— 可行性 §3.6）：
   - 候选 = `Versions.scanAll(ctx)` 的全部已装版本（**不按版本号过滤**）；
   - 预选：清单 `game` 里那一版已装 ⇒ 选它；否则选**最新已装**（官方优先，其次 fork）；
   - 列表里加一项「先不绑（稍后在版本页绑）」；
   - 选中 ⇒ `Config.get().addExtraSlot(e.key(), name)`（★ 不是 `setSlotOf`：不抢主槽，一个版本多一行启动项）；
   - 清单 `game` 与所选不一致 ⇒ 只提示「包是在 X 上做的」，**不阻断**；
   - 一个已装版本都没有 ⇒ 不绑，结果页给「导入 APK / 去版本页绑」的出口。
   `targetBuild` / `targetRev` 从**所选版本**取；没选 ⇒ 0（`stateOf` 的版本门自动放行，依赖门照查）。
5. **模组校验 / 关掉不兼容的**（**用 `stateOf`，不是 `compatOf`** —— 前者才是游戏口径）：
   ```java
   Mods.Scan scan = Mods.scan(ctx, name);
   Mods.Resolved res = Mods.resolveDependencies(scan.mods);   // 游戏那套判据的逐行复刻
   for (PackManifest.Member m : manifest.mods) {
       Mods.Info info = findByFileName(scan.mods, baseName(m.file));  // 按文件名，不按显示名
       if (info == null) { missing.add(m.file); continue; }
       if (m.internal != null && !m.internal.equals(info.internalName)) tampered.add(m.file);
       if (info.duplicated) { /* 预检漏了才会到这里：记下来，结果页如实说 */ }
       Mods.State st = Mods.stateOf(info, res, targetBuild, targetRev);
       if (st == Mods.State.MISSING_DEPENDENCIES || st == Mods.State.INCOMPLETE_DEPENDENCIES
               || st == Mods.State.CIRCULAR_DEPENDENCIES || st == Mods.State.UNSUPPORTED
               || info.willFailJavaLoad()) {
           disable(info);   // Mods.setEnabled(..., false)：成对写 -enabled/-failed，自带备份+读回
       }
   }
   ```
   - **缺依赖 / 循环依赖 / 版本不支持 / Java 包没有 dex** ⇒ 关掉**那一个成员**，不要让它把整槽拖下水；
     结果页逐条说「为什么关的」（`Mods.stateOf` 给的就是游戏口径的四种状态）。
   - **绝不替用户"打开"**：`stateOf` 返回 `DISABLED` 说明包里的 `settings.bin` 本来就是关的 —— 那是作者的意图。
   - `Mods.setEnabled` 在 `Data.gameAlive(ctx)` 时**拒绝** ⇒ 导入前先判，游戏在跑就提示先退出。
6. 结果卡：装了什么 / 跳了什么 / 关了哪些（带原因）/ 绑了哪个版本 / 清单与实物对不上的成员。
7. 失败收尸：**只清本轮新建的那个槽**，且不是当前槽：
   ```java
   if (created && !name.equals(Data.currentSlot(ctx)))
       Trash.trashSlot(ctx, name, Backup.rootDir(ctx));   // 走中转站，不 deleteSlotForever
   ```
   `SlotZip.importSlot` 已经写了 `Pending("slot.import")`，进程被杀后 `Recovery` 会清 `.part`。

⚠️ **拒绝当前槽**：`name.equals(Data.currentSlot(ctx))` 时直接拒绝（`Data.createSlot` 对当前槽返回 null 且不建目录，
照常往下走会把包解进**正在用的槽**）。

## 4. 导出流水线（数据层）

```
Data.contentRoots(ctx, slot)                  // 已有：槽内容 − 排除名单
PackSettings.plan(dir, scan, share)           // 新：settings.bin 的过滤 + 分享时丢 DROP_TOPS
PackManifest.forExport(ctx, slot, scan, ...)  // 新：模组逐个 sha256 + 内容计数 + 提示版本（不强制）
Exporter.zipTo(ctx, uri, dir, roots, xform, level, extras)
```

- `xform`（新 `PackXform`，放 `PackIo` 里）：
  - `drop(rel)` = `share ? SharePack.dropTop(rel) : false`；另外 **settings 过滤后为空 ⇒ `drop("settings.bin")`**；
  - `bytesOf(rel)` = `"settings.bin".equals(rel) ? plan.settings : null`。
- `extras` = 一条 `Extra("mdtpack.json", manifest.write())`。
- 压缩级别：本地自用 `BEST_SPEED`（与整槽导出同档）；分享 `BEST_COMPRESSION`（与分享包同档）。
- 文件名：`mdt-<槽>-pack-<日期>.zip`；分享 `mdt-<槽>-pack-share-<日期>.zip`。
- **老的「导出整槽」不动**：它仍是完整备份（含作者的键位/音量），不写清单。两个导出并存，各管一件事。

`PackSettings` 的判据：

```java
SettingsBin.Values v = SettingsBin.read(new File(dir, "settings.bin"));
if (share) v = SharePack.strip(v).values;          // 先剥身份（usid/uuid/ip/…）
Set<String> keep = internalNames(scan.mods);       // 本包成员
// 只留：mod-<成员 internal>-enabled；外加 modcrashdisable
v = filter(v, keep);
byte[] out = SettingsBin.encode(v);
return Arrays.equals(out, SettingsBin.readAllBytes(file)) ? null : out;
```

- **不能直接复用 `SharePack.Plan.settings`**：那是"剥身份后的字节"，不是"只留模组"；
  两个策略分开，判据也分开（`SharePack.isSensitive` 只回答"是不是身份"）。
- `mod-*-failed` **不带走**（那是作者机器的失败记录）；
- `settings.bin` 里模组自己的键（`mods/<名>/config.json` 那种在 `mods/` 目录里，不在 `settings.bin`）不在此列；
  `settings.bin` 只放行"本包成员的开关 + `modcrashdisable`"。

## 5. 对账 / 状态（`PackRecord`）

```java
final class PackRecord {
    PackManifest pack;
    List<Member> members;   // file / present / shaOk(ok|bad|unknown) / Info / enabled / failed / state
    Mods.Resolved resolved; // 依赖图（游戏口径，resolveDependencies 的逐行复刻）
    int missing, modified, duplicated, tampered;
    boolean allOn, allOff, partial;
    boolean slotSkipped;    // scan.skipModLoading（上次整槽被跳过）
}
```

- 匹配键 = **`Mods.Info.fileName`**（`mods/` 下的顶层条目名），不是显示名、不是 `internalName`；
- 成员状态 = `Mods.stateOf(info, resolved, target.build, target.revision)` —— **不要自己比 `minGameVersion`**
  （`stateOf` 还含 Java/脚本门槛、黑名单、依赖四种失效状态）；
- `shaOk`：有 `sha256` 且文件是普通文件 ⇒ 流式计算比对；目录形态 ⇒ `unknown`；
- `tampered`：清单里的 `internal` 与实物 `Info.internalName` 不符（清单被改过 / 文件被换过）；
- `duplicated`：两个成员 `internalName` 相同 ⇒ **包坏了**（游戏后写者覆盖前者），预检就拒；
- `enabled` 取 `Info.enabled`（`Mods.scan` 已经从 `settings.bin` 读好，缺省 true）；
- **不存"包开/关"**：`allOn/partial/allOff` 每次都从成员算（可行性文档 §3.4 那张表）；
- `slotSkipped` 单独一列，不要混进"包关了"（那是全槽级，`ref/29` §86.7）。

| 模组页（`ModsActivity.fillHeader`） | 摘要卡追加一行：`整合包：X · 5/6 启用 · 2 个被改过`；点它 → `CardStack`（全部开启/全部关闭/移除记录/导出） |
| 模组行（`bindRow`） | 副标题加「包：X」（`PackText`/`PackRecord` 查一次，别每行重算） |
| 现有「导入整槽（zip）」 | `readZipThenConfirm` 里先 `PackManifest.read`：有清单 ⇒ 转到 `PackIo.confirmPack`（并告诉用户"整合包会装进一个新槽，不覆盖当前槽"） |

**v1 不做**：按包分组/「按包排序」。`Mods.filterAndSort` 会按搜索/状态/大小重排，
分组头会失效（做的话要新增一档 `SORT_PACK`，并让筛选结果按包聚簇 —— 那是另一轮）。

## 7. 自检（能离线的那部分）

| 用例 | 判据 |
|---|---|
| `PackManifest` 往返 | 写→读字段一致；`schema=2` 拒；`../x` / `C:x` / `/x` 拒；缺 `name` 拒 |
| `PackManifest` 包裹前缀 | zip 里只有 `dir/mdtpack.json` + `dir/mods/a.jar` ⇒ 找到 `dir/`，并把 `Info.strip` 写对 |
| `PackSettings` | 只留成员 `-enabled` + `modcrashdisable`；`usid-*`/`-failed`/别人的键不在；字节相同 ⇒ `null` |
| `PackRecord` | 3 成员：2 在、1 缺、1 哈希不符 ⇒ `missing=1/modified=1`、`partial` 算对 |
| 依赖图 | A→B（都在）、A→C（C 不在）、D↔E（循环）⇒ `resolveDependencies` 给出 MISSING / CIRCULAR；`stateOf` 把 A/D/E 判成要关的那几个 |
| 同名成员 | 两个 zip 的 `mod.hjson` 都写 `name: same` ⇒ `Mods.scan` 标 `duplicated`；包预检必须**拒**（不是装完再说） |
| 命名空间被改 | 清单 `internal: x`、实物 `name: y` ⇒ `PackRecord.tampered=1`（正文说"清单与实物对不上"） |
| `Exporter.Extra` | 输出 zip 里恰好一条 `mdtpack.json`；槽根已有同名文件时**不重复**；`Result.files` 计数符合预期 |
| 端到端 | `zipMany` 造「清单 + 假模组」→ `SlotZip.importSlot` → `Mods.scan` 能读 → `setEnabled` 落盘 → 记录在；清理测试槽 |

自检里**不要**碰真机 SAF / 弹窗（那是"断言 + 看"那一档）；端到端只用数据层与临时文件。

★ **PC / 设备的分界**：能进 `PcCheck`（纯 JDK 编译）的只有 `PackSettings`；
`PackManifest`（`org.json`）与 `PackRecord`（`Mods.Info`）只能在设备 `SelfTest` 里跑 —— 与
`PluginUpdateManifest` / `UpdateManifestCheck` 的既有分界一致，别硬凑。

### 7.1 夹具矩阵（没有现成样本就自己造）

用户 2026-11-01：「好像没有」现成的嵌套包/互相依赖的模组样本 ⇒ **全部用夹具造**，覆盖判据即可；
真实模组只当最后的冒烟。造法：`SelfTest.zipMany(File, String[], String[])` + `Data.createSlot` + `Mods.scan`。

| # | 夹具 | 期望 |
|---|---|---|
| 1 | A（`dependencies: ["b"]`）+ B，都有效 | 两个都 `ENABLED`；A 的依赖解析到 B |
| 2 | A 依赖 `c`，包里只有 A | A 被关；结果页写「缺 c」 |
| 3 | A→B、B→A | 两个都 `CIRCULAR_DEPENDENCIES` ⇒ 都关 |
| 4 | 两个包都写 `name: same` | 预检**拒**，不写盘（不是装完才提示） |
| 5 | 清单 `internal: x`、实物 `name: y` | `tampered=1`，提示「清单与实物对不上」 |
| 6 | `java: true` 但没有 `classes.dex` | `willFailJavaLoad()` ⇒ 关 |
| 7 | `minGameVersion: 999` | `stateOf` = `UNSUPPORTED` ⇒ 关 |
| 8 | settings.bin 含成员 A、外来 C、`usid-*`、`mod-a-failed` | 过滤后只剩 `mod-a-enabled` + `modcrashdisable` |
| 9 | 槽根已有 `mdtpack.json` 再导出 | zip 里恰好一条，不抛 `duplicate entry` |
| 10 | zip 里只有 `dir/mdtpack.json` + `dir/mods/a.jar` | 找到 `dir/`，`Info.strip` 被写对 |
| 11 | 清单 `game` 写 159.7，本机只装 160.1 | **不阻断**；预选 160.1；卡上提示「包是在 159.7 上做的」 |
| 12 | 本机一个版本都没装 | 照常装进新槽；**不绑**；结果页给「导入 APK / 去版本页绑」 |

★ 这 12 条里，**1~5 是"整合包语义"的尺子**，6~8 是"装包不把槽拖坏"的尺子，9~12 是"文件层 / 版本提示"的尺子；
每条都要有**反方向断言**（比如 #2 里 B 必须仍是 `ENABLED`，证明不是"全关"蒙对的）。

## 8. 读代码读出来的坑（按严重度）

1. 🔴 **`Exporter` 没有"额外条目"钩子**，且槽根可能已经有 `mdtpack.json` ⇒ 不跳过就会 `ZipException: duplicate entry`。
2. 🔴 **`Config.setSlotOf` 会抢主槽**：一个版本只有一条主分配。包槽必须走 `addExtraSlot`。
3. 🔴 **`SlotZip` 直接写槽**：只能新槽/空槽；失败用 `Trash.trashSlot` 收尸（`deleteSlotForever` 只给自检）。
4. ⚠️ **`SlotZip.inspect` 的 strip 只认 `settings.bin`/`saves/`**：只有一层包裹目录的包可能剥不掉 ⇒ 清单读不到、解包落错层。
5. ⚠️ **`Importer` 只有 Uri 入口**：厚包要补 File 入口（抽 `importApk0` 的流参数）。
6. ⚠️ **`Mods.setEnabled` 在游戏运行时拒绝**；导入前判 `Data.gameAlive`。
7. ⚠️ **`Data.createSlot` 对当前槽返回 null 且不建目录**：必须自己拒。
8. ⚠️ **`settings.bin` 过滤要留 `modcrashdisable`**（缺省 true），不能把 `-failed` 带过去。
9. ⚠️ **`SharePack.Plan.settings` ≠ "只留模组"**：别复用错，两个策略两处实现（一个判"身份"，一个判"该不该进包"）。
10. ⚠️ **`ModsActivity` 列表会被搜索/排序打乱**：v1 用"包卡 + 行徽标"，别做分组头。
11. ⚠️ **`ZipEntry.setTime` 越界会抛**：`Exporter` 已经处理；Extra 条目用"当前时间"或干脆不设时间。
12. ⚠️ **`PackManifest` 用 `org.json`**：自检在设备上跑没问题；别把 `android.content.Context` 带进这个类。
13. 🔴 **内容 ID = 内部名 + "-" + 文件名**（`ContentLoader.transformName`）：**改 `mod.hjson` 的 `name` = 改所有内容 ID**
    ⇒ 存档/蓝图/地图"丢内容"。包**永不改写模组文件**（清单只记录，不重命名）。
14. 🔴 **`dependencies` 不是 classpath**：它只管加载顺序/失效判据；每个模组一个 `ClassLoader`（`AndroidLauncher.loadJar` = `DexClassLoader`，child-first）
    ⇒ 跨模组 **直接 import 类不成立**（只能反射 / 共享 API / 抽公共模组）。内容级互访可以（用前缀名 + 依赖声明）。
15. ⚠️ **内部名重复 = 包坏了**：游戏 `mapping.put()` 后写者覆盖前者；`Mods.scan` 的 `Info.duplicated` / `Scan.problems` 已经会报，
    包预检要**拒**（别装完才提示"有一个没生效"）。
16. ⚠️ **`Mods.stateOf` 与 `Mods.compatOf` 不是一回事**：装包判定用 `stateOf`（游戏口径，含依赖/黑名单/Java 门槛）；
    `compatOf` 只用于"模组 × 版本"三态矩阵（`UNKNOWN` 表示没声明，不是坏）。

## 9. 成本与顺序（按本仓"轮"）

| 段 | 内容 | 轮 |
|---|---|---|
| **A 数据层** | `PackManifest` / `PackSettings` / `PackRecord` + `Exporter.Extra` + `Importer` File 入口 + 自检 | **1.5~2** |
| **B 导入 UI** | 入口 / 预览卡 / 新槽名 / 选目标版本（提示 + 选择器，**不锁版本**）/ 结果 / 失败收尸 + 真机 | **2~2.5** |
| **C 导出 UI** | 导出菜单 / 分享·自用二选一 / SAF / 清单 / settings 过滤 + 真机 | **1~1.5** |
| **D 模组页整合** | 摘要行 + 行徽标 + 全部开/关 + 移除记录 | **1~2** |
| 合计 | | **5~7** |

**建议顺序**：A（纯逻辑 + 自检，不碰 UI）→ B（先能用）→ C（再能分享）→ D（最后做"管理器里的整合"）。
每段收尾都要过 `./build.sh` 与自检，不改变现有 `#` 行为（老 flow 一个字节都不动）。

★ **版本这块比原估小**：包不锁版本、不做矩阵（可行性 §3.6），B 段里只是"提示 + 一个选择器"，
少约 0.5 轮；省下的精力应放在依赖 / 命名空间 / 包记录对账上。
