## 0. 一句话

**补丁包就是一个 APK**（标准布局）**根上多一个 `patch.json`**。导入时校验、运行时：
**整包注入**（dex，ART 原生多 dex）· **整包挂资产**（`addAssetPath`，含素材；资源表也在包里）·
**从包里取 native**（`lib/<abi>/*.so`）。`v1 .mdp` 直接退役（没发布，不背兼容包袱）。

---

## 1. 为什么这条比自定义格式省事

| 要的能力 | APK 容器怎么给 | 现成原语 |
|---|---|---|
| 多 dex（真 fork 常是 2 份） | `classes.dex` / `classes2.dex` 标准布局，ART 原生展开 | `Injector.injectDex` 本来就吃 APK（游戏 APK 就是这么注入的） |
| native | `lib/<abi>/*.so` 标准布局 | `loadNatives` 现在就是按 `ZipFile(plan.apk)` 取 `lib/<abi>/` |
| 素材 + 资源表 | `assets/**`（+ 可选 `resources.arsc`） | `mountAssets` 现在就把**游戏 APK 本身**挂进链（含资源表） |
| 类清单（冲突检测） | 枚举包里所有 `classes*.dex` | `InjectionSources.classesOfApk` 已经会读多 dex APK（插件那条） |
| 产出 | aapt2 / d8 / apksigner，`build.sh` 都有 | 别人的构建产物（MDTX 的 APK）也能直接当补丁 |

顺带一个可能的白捡：注入的 APK 就是 dex 载体，ART 的 `DexPathList` 可能把 **zip 根条目**（`vfxshaders/`、
`rhino/`）暴露给 `ClassLoader.getResource*` —— 这是 v1 的死角，真机验一下（见 §8）。

## 2. 包格式

```
mdtx-1607.apk
├── patch.json            ← 根上（不在 assets/ 下，不会进游戏资产）
├── classes.dex           ← 全部游戏代码（可 classes2.dex…；多 dex 由 ART 展开）
├── lib/<abi>/*.so        ← 可选；仅 role=game（普通补丁不许带，见 §5）
└── assets/**             ← 可选；全量或差分；STORED 规矩不变（openFd 只认 stored）
```

```json
{
  "schema": 2,
  "id": "mdtx-1607",
  "name": "MindustryX",
  "version": "B509",
  "role": "game",
  "apkSha256": "<基座 APK 的 sha256，64 位小写 hex>",
  "gameVersion": "160.7",
  "author": "", "note": "", "tool": ""
}
```

- **不再有**：`targets/<sha>/` 嵌套、`assets.zip`、`lib.zip`、schema 1 的 `dex` 字符串数组、路径矩阵。
  一个 target 一个包 —— 要针对多个基座版本就出多个包（反正转换器是脚本）。
- `manifest` / `resources.arsc` / `META-INF/` **可以有，也可以没有**：
  有 ⇒ `getPackageArchiveInfo` 顺手读 APK 自己的 label / versionName 做显示；
  没有 ⇒ 加载完全不受影响（`addAssetPath` 对普通 zip 也认，2026-11-05 实测 cookie=11）。
- 校验（`PatchException` 码 → 人话仍在 `PatchText`）：
  - `patch.json` 在根上、字段合法；`id` / `version` 字符集沿用；
  - `classes*.dex` ≥1，每份过 dex 头校验（magic / file_size / Adler-32 / ≥1 类）；
  - `assets/` 条目安全（safeRel）、≤4096 条、≤128 MB；
  - `lib/<abi>/<name>.so` 三段、abi 白名单（`arm64-v8a/armeabi-v7a/x86/x86_64`）、≤256 条、≤64 MB；
  - 单 dex ≤64 MB、dex 合计 ≤128 MB、整包 ≤256 MB。
- `role`：`patch`（缺省）/ `game`；未知值按 `patch`（前向兼容）。

## 3. 存储与导入

```
app_hub/patches/<id>/<version>/
├── patch.apk                            ← 原样副本，只读（ART 硬要求）
└── patch.json                           ← 原字节副本（扫描/展示用；seal 认 .apk 与它）
```

- 导入：读**包内根 `patch.json`** → 校验 target/role/结构 → 枚举并校验 dex/assets/lib →
  复制成只读 → 原子 rename。失败清临时目录、**不留半条记录**（现有纪律）。
- 删除进中转站 / 放回 / 引用检查 / 按实例启用：全部沿用 v1（只换载体）。
- `v1 .mdp`：**不迁移、不读**（没发布）；碰见旧 `.mdp` 给一句"旧格式已停用"。

## 4. 运行时

- **dex**：`Injector.Patch` 从 `dex` 改成 `apk`；`at = patchInsertIndex(hostDex, inserted)`；
  `Reflect.injectDex(baseCl, patchApk, opt, at, notes)` **一次注入整包**（element +1，多 dex 由 ART 展开）。
  - 判据仍是 `after > before`（第 345 轮 B2）；多 dex 是否都可见，用"类只住在 classes2.dex 里"的夹具验。
  - 真机若发现只认第一份 ⇒ 退化为"从包里抽 `classes*.dex` 逐份注入"（**容器不变**，只换抽法）。
- **assets**：补丁 APK 直接进 `Plan` 的资产链（`mountAssets` 的 `File` 列表，`addAssetPath` 吃 APK），
  后挂覆盖先挂；只挂 `applied` 的补丁。
- **native**：`loadNatives` 每个 `NATIVE_LIBS` 先看补丁 APK 的 `lib/<abi>/<name>`，没有回基座；
  `Natives.publish` 的 tag = `Natives.tagOf(plan.tag + "+" + ref)`（不同内容不同目录，不覆盖基座那份）。
- **入口类验证**：仍在所有补丁注入之后。
- **报告**：`补丁[1] MindustryX … 注入 @1 elements 2→3`、`资产链 = 官方.apk + mdtx.apk`、
  `libarc.so 来自补丁`；`report-patch-launch.json` 记补丁 APK 路径（旧 `dex` 字段留作兼容读）。
- **资源表**：基座 APK 本来就挂着（含 `resources.arsc`），再加补丁的同类风险；真机若撞资源 ID
  再把补丁包里的 `resources.arsc`/`res/` 剥掉（剥了仍是合法 zip，`addAssetPath` 照挂）。

## 5. 语义（与上一版一致，只有承载变了）

| 处 | 规则 |
|---|---|
| **独占** | `role=game` 与任何补丁互斥（同一实例）。`enable` 先判（新码 `C_GAME_LAYER`）：已有补丁 ⇒ 拒；已有整端 ⇒ 拒开普通补丁。`resolve` 启动期再判（手改 config 时取第一条整端、其余跳过）。 |
| **类型词** | `Versions.typeFor(ctx, e, patchCount, gameLabel)`：有整端 ⇒「整端」；有普通补丁 ⇒「半改端」；否则原端/改端。 |
| **行显示** | 有整端时副标题显示**整端补丁名**（`Patches.gameLabel(ikey)`），不再只写"补丁 N"。 |
| **崩溃** | 整端 ⇒「已回退到官方本体」；普通 ⇒「已停用」。行为不变（自动停用 + 可再启用）。 |
| **首次启用** | 整端单独一张告知卡，不共用 `patch_warned`。 |
| **插件接口** | v50：`role`、`dexCount`、`libs` 条数/字节；`classes` = 全部 dex 合计；三处版本号一起改。 |
| **native 归属** | 只有 `role=game` 能带 `lib/`（普通补丁带 ⇒ 导入时 `C_FIELD`），避免"半个 native"与多补丁互覆盖。 |

## 6. 构建 / 转换

- **最小转换器**：给一份现成 APK **追加**根 `patch.json`（zip 里加一条，不改原条目）⇒ 立刻可当补丁导入。
  - 例：MDTX B509 的 APK（2 dex / 全量 assets / libs）+ `patch.json`（target = 官方 160.7 sha、role=game）。
  - 例：官方 APK 自己 + `patch.json` ⇒ 整端"什么都不换"的对照组。
- **差分包**（可选）：只放 `classes*.dex` + 变了的 `assets/` + `lib/`，manifest 留着（`getPackageArchiveInfo`
  仍能读名字/版本）；`assets/` 里 STORED 的保持 STORED、4 字节对齐。
- **自己的构建**：`build.sh` 出 APK 后追加 `patch.json`；工具放 `tools/mk_patch_apk.py`（Python，不进 APK）。
- 单位：**一个包 = 一个基座 sha**；多基座就多包（转换器批量出，不引入 targets 数组）。

## 8. 验收

**自检（约 20 条）**：

1. `patch.json` 矩阵：缺字段 / role 未知 / id 非法 / target 非 64 hex / schema 3。
2. APK 结构：没有 `classes*.dex`、dex 坏、`assets/` 里混根条目、`lib/` 路径非法、超限、重复条目。
3. 类并集：`classes2.dex` 独有的类出现在冲突检测与 `classes` 计数里。
4. 素材键：从 `assets/` 枚举、剥前缀；冲突命中。
5. 独占矩阵：整端→普通拒 / 普通→整端拒 / 两个整端互斥 / 手改 config 时 `resolve` 取谁。
6. 类型词三态 + 行副标题（整端名）。
7. 崩溃文案分岔（角色不同、行为相同）。
8. 插件数据：`role` / `dexCount` / `libs` / `classes` 合计。
9. 导入负例：旧 `.mdp` 明确拒绝；缺 `patch.json`；target 不匹配（`no_match`）；只读位。
10. 多 dex 注入的**下标数学**（纯函数）+ "整包 = 1 element"的假设（若退化抽 dex，则 N 份）。

**真机（HONOR ELP-AN00 / Android 16）**：

- 官方 160.7 基座 + **MDTX B509 APK 当补丁**（2 dex + 全量 assets + libs）→ 主菜单 / 载入框 / 开一局；
  报告：`补丁[1] … elements 2→3`、`资产链 = 官方.apk + mdtx.apk`、`libarc.so 来自补丁`。
- **多 dex 判据**：MDTX 的 `classes2.dex` 里挑一个类，启动后由游戏自己加载到（能进主菜单/开一局即证明）。
- **根资源实验**：改一个 `vfxshaders/*.frag` 放进补丁 APK，看游戏用的是补丁那份（成立 ⇒ v1 的根资源死角补上）。
- 停用 ⇒ 原版；造崩 ⇒ 自动停用 + 新文案 + 下次启动是官方本体。
- A/B：同一份 MDTX 当"版本导入" vs "当补丁叠在官方上"——行为 / 启动耗时 / 存储对照。
