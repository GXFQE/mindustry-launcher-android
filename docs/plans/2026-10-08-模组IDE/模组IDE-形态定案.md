## 0. 结论：先认清"半成品"的痛苦从哪来

★ **半成品的痛苦 90% 来自"改模型"，不来自"改界面"。**

- 改一个按钮的位置、换一个画布实现、把分栏换成两页 —— 这些**只动一层**，不痛苦；
- 痛苦的是：**"注册名怎么算"散在三个页面里**、**`size` 与贴图尺寸的判据写了两遍**、
  **写入纪律每个入口各写一套** —— 等到发现不一致时，要改的是**所有调用点**，
  而且**已经发布出去的键/行为还不敢改**（§84.8：随正式版发出去过的 key 不许删）。

⇒ 所以本稿只做一件事：**把"以后不许变"的那层挑出来、写死、钉住**；
**"以后可以随便换"的那层明确标注免责**。这样每一期做出来的东西**都是最终形态的一块**。

## 1. "IDE"在这里到底指什么（防止范围失控）

**是**：一个**模组工程** + **四个视图** + **一份一致性判据** + **一个写入口**。

| 视图 | 内容 | 读写 |
|---|---|---|
| **工程视图** | 这个模组的全貌：元数据 / 内容清单（类型、`size`、朝向）/ 贴图清单（注册名 ↔ PNG）/ **问题列表** | 只读 |
| **文本视图** | `mod.hjson` 与 `content/**` 的文本编辑（悬浮 / 诊断 / 补全） | 读写 |
| **贴图视图** | 像素画板：新建 / **从现有贴图起稿** / 保存 | 读写 |
| **预览视图** | 这些内容在游戏里长什么样（复用 §80 的像素级渲染 / 蓝图预览） | 只读 |

**不是**（明确划掉，否则一定烂尾）：多工程管理 · Git · 插件系统 · 脚本编辑器（JS/Java）·
通用"构建系统"（Mindustry 模组的"构建"= **打 zip**，`Mods.importPackage` 已经有了）。

★ 一句话：**这是"一个模组的 IDE"，不是"一个 IDE"。**

## 2. ★★ 冻结层（不可变契约 —— 以后改这里 = 一次显式决策 + 自检同步）

### 2.1 工程单位与定位

| 项 | 定案 | 依据 |
|---|---|---|
| 工程 = **一个模组条目** | 定位信息 = `(槽, 模组条目)`；跨页**只传这个** | §109（跨 Activity 只传定位信息，派生量本页重算） |
| 可写的形态 | **只支持目录形态**（`mods/<名>/`）；zip/jar **只读 + 导出** | 重写 zip 已否决；且真机实测：含 `classes.dex` 的模组解包成目录会**直接坏掉** |

### 2.2 模型：`ModProject`（只读地算"真实情况"）

它**只读**、**不碰 UI**、**不持有"用户正在编辑的文本"**（那是文本视图的事）：

| 能力 | 从哪来 |
|---|---|
| 元数据（name / displayName / version / minGameVersion / main / hidden…） | `Hjson`（宽容解析，**不许用严格 JSON**）+ 反射拿到的 `ModMeta` 键表 |
| **内容清单**：`content/<复数目录>/<名>.json` → {类型, 名字, `size`, `type`(朝向), 原始字段} | 复用 `MapStatsMods.contentFor` 的口径；目录**必须复数**（单数游戏不读，实测） |
| **贴图清单**：注册名 ↔ PNG 条目 + 尺寸 | 🔴 **复用 `ModSprites`**（`of(mods)` / `find(block)` / `rotates` / `typeOf` / `keys()`）—— **不要重写注册名规则** |
| ★ **一致性判据**：`issues()` | 见 2.3 |

### 2.3 ★ 一致性判据（**一份实现**，两个视图都调它）

| # | 判据 | 错了的后果 |
|---|---|---|
| **C1** | 内容名 ↔ 贴图注册名：注册名 = `internalNameOf(meta.name)` + `-` + 文件名主干 | 改内容名 ⇒ 贴图**失配**（静默） |
| **C2** | 方块贴图尺寸应当 `size×32`（**32 px = 1 格**） | `size` 与 PNG 不符 ⇒ 游戏**不报错**、画出来错位（已实测：游戏不校验尺寸） |
| **C3** | 缺贴图 / 孤立贴图（有 PNG 没有对应内容） | 游戏里显示成 `error` 花图（48×48，实测） |

★ **先例与依据**：`ListQuery`（§83）就是"**把判据收进一个类、四个列表页共用**"——
本工程已经吃过"判据两处实现"的亏（§77 / §111 / §115），这次**不重复**。
★ **行为口径定案：一期只"报"，不"自动改"** —— `size` 与贴图不符时**提示**，不自动改名/不自动缩放（自动改用户文件太危险）。
★ 报告格式沿用本工程既有习惯：**结论在前、依据在后**（§85 的两层）。

### 2.4 写入：**只有一个入口**

所有写操作（写 JSON / 写 PNG）都走同一套，**不许各视图自己写**：

```
改前确认 → 落 .part → 自证（用我们自己的解析器/解码器读回来）
        → 同名先问 → 就位（rename）→ 失败回滚且如实告知原件在哪
门禁：游戏在跑 ⇒ 先拦（Data.gameAlive）；旧件 ⇒ Trash.move（不是裸 renameTo）
```
（纪律来源：地图 / 蓝图 / 存档 / 整槽四条线已经这么做了；§51 那套"改前备份 + 原子写 + 写后自检"。）

### 2.5 口径冻结（这几条**永远**只有一种算法）

| 口径 | 定案值 | 出处 |
|---|---|---|
| 模组内部名 | `meta.name` **小写化 + 空格换 `-`**（照游戏 `Mods.java:1253`） | REF §77 |
| 贴图注册名 | 前缀（= internalName）+ **完整文件名主干**（**不是**第一个 `.` 之前那段） | REF §81.2（第一版就栽在这里，自检当场判死） |
| 目录层级 | **不进注册名** | REF §81.2 |
| 尺寸 | **32 px = 1 格**；方块贴图 = `size×32` | REF §81.3 |
| 内容目录名 | **复数**（`items/` `blocks/` `liquids/` `units/` `status/` `sectors/` `weathers/`） | 2026-10-06 实测（单数游戏不读） |

## 3. 免责层（**这些以后随便换，不算返工**）

| 层 | 为什么可以随便换 | 约束 |
|---|---|---|
| **文本视图的实现**（原生 `EditText`+`Spannable` ↔ WebView 跑 Anuken 内核） | 它只吃"文本 + 一个定位"，吐"文本 + 诊断列表" | 不许它自己算注册名/尺寸 |
| **画布实现**（`View` ↔ `SurfaceView`）与工具集 | 只吃"一张位图 + 尺寸" | 同上 |
| **布局**（同屏分栏 / 两页互跳 / 抽屉） | 只吃模型 | 同上 |
| **调色板 / 取色器细节** | 只吃"当前色" | —— |
| **预览实现**（复用 §80 渲染，还是别的方式） | 只读 | —— |

★ **判据（可当门禁）**：**视图层里不许出现"拼注册名"和"`×32`"这类派生量计算** ——
grep 得到就该红（照 `SRC-01/02` 那种门禁的写法）。这一条直接消灭"改起来麻烦"的最大来源。

## 4. ★ 建设顺序：每一步**都是最终形态的一块**（没有一步是要扔的）

| 步 | 交付 | 在最终形态里的位置 | 会不会扔 | 碰用户数据吗 |
|---|---|---|---|---|
| **1** | **`ModProject`**（只读模型 + `issues()` 一致性判据）+ 一节自检 | **地基** | ❌ 永不扔 | 只读 |
| **2** | **工程视图**（元数据 / 内容清单 / 贴图清单 / **问题列表**） | **IDE 的首页** | ❌ 永不扔 | 只读 |
| **3** | **贴图视图**：列出本模组贴图 → 打开现有贴图 → 改 → 存回 | 一个视图 | ❌ 只加不改 | **写**（走 2.4 那一个口） |
| **4** | **文本视图（只读）**：高亮 / 悬浮 / 诊断 | 一个视图 | ❌ | 只读 |
| **5** | **文本视图（可写）**：无损 AST 改一处 | 一个视图 | ❌ | **写** |
| **6** | **预览视图**（复用 §80 的像素渲染） | 一个视图 | ❌ | 只读 |

★ 注意**第 1、2 步零写入**，却已经交付了**独立可用**的东西：
"**这个模组有什么、哪里不对**"—— 这正是"修别人模组"时最需要的第一屏。
★ 而且第 1 步的模型**顺便服务已发布的功能**（蓝图缺件判定、地图统计都吃这套知识），
不是"为了将来"而写的空抽象。

★ 与 `像素画编辑器-嵌入与难度.md` §5 那条"最窄竖切"的关系：
**那条竖切 = 这里的第 1 步 + 第 3 步的一个缩小版**（先只支持"从现有贴图起稿"）。
两稿不冲突：**嵌入稿说的是"先验证什么"，本稿说的是"验证完往哪儿长"。**

## 5. 防止"做出一堆半成品"的三条硬规矩

| # | 规矩 | 怎么保证 |
|---|---|---|
| **1** | **模型冻结，只准加视图/加能力** | 改 `ModProject` 的公开形状 = 一次**显式决策**，并且**自检同步**（判据与模型同生命周期） |
| **2** | **写入口只有一份实现** | 视图里 grep 不到 `.part` / `renameTo` / `Bitmap.compress(…File` 这类落盘动作 |
| **3** | **派生量只许在模型层算** | 门禁：视图层出现拼注册名 / `*32` / `internalNameOf` ⇒ 判死（照 `SRC-01/02` 的写法） |

★ 这三条的作用：**将来换界面（甚至换整套 UI）时，模型与判据一行不用动**。

## 6. 明确不做（每条都写理由，避免以后反复讨论）

| 不做 | 理由 |
|---|---|
| 多工程 / 工程列表管理 | 槽里的模组列表**已经有了**（模组页）；再做一个"最近打开"是重复入口（§84：一行 = 一件独立的事） |
| Git 集成 | 与"给 MDT 用户造模组"这个场景无关 |
| 脚本编辑器（JS / Java） | JS 可以后加（就是文本视图换个后缀）；**Java 在手机端做不了**（要 d8 + 完整 SDK，社区路线是 Termux） |
| 通用构建系统 | 模组的"构建"= 打 zip，`Mods.importPackage` 已有 |
| 同屏分栏（文本 + 画布） | 手机竖屏上"看清 JSON"与"画准像素"互相打架（嵌入稿 §3 已定） |
| 自动改名 / 自动缩放（C1/C2 自动修） | 自动改用户文件的风险远大于收益；**一期只报不改** |

## 7. 要你拍板的

| # | 问题 | 我的建议 |
|---|---|---|
| **Q1** | 先做**第 1+2 步**（只读：模型 + 工程视图 + 问题列表）吗 | **是** —— 零写入、独立可用、永不返工，而且能顺手修既有功能的"两处判据" |
| **Q2** | 文本视图一期做**只读**还是直接可写 | **先只读**（高亮/悬浮/诊断）—— 可写要无损 AST，那是另一个量级的风险 |
| **Q3** | 文本视图**原生**还是 **WebView** | 先按原生做只读版；**这条在契约上属于"免责层"**，将来换 WebView 不算返工 |
| **Q4** | 工程单位只支持**目录形态**吗 | **是**（zip 只读 + 导出）；zip 可写要重写整个 zip，风险不成比例 |
| **Q5** | 三条硬规矩（§5）要不要做成**门禁**（像 `i18n-check.py` 那样） | **要** —— 这是"以后改起来不麻烦"的唯一机械保证 |

## 8. 现成零件清单（本稿的事实依据）

| 零件 | 规模 | 提供什么 | 用在哪 |
|---|---|---|---|
| `ModSprites` | 16.5 KB | `of(mods)` 建索引 · `find(block)`→`Hit` · `rotates/typeOf` · `keys()` · `classRotates`（生成表 136 类/32 转） | **贴图清单 + C1** |
| `MapStatsMods` | 16.9 KB | `contentFor(ctx, slot)` → `SlotContent`（原版+模组+patch 叠加） | **内容清单** |
| `ListQuery` | 8.8 KB | ★ **"判据收进一个类、多页共用"的先例** | **C1/C2 的组织方式** |
| `Msch*`（`Msch`/`MschSheet`/`MschSprite`/`MschPreview`/`MschAtlas`） | ~100 KB | 像素级渲染（蓝图预览，和游戏一样） | **预览视图** |
| `MapLoad` | 11.4 KB | APK 里取图 · `BitmapFactory` · **`bmp.compress(PNG)`** | **贴图视图**（编码已验证） |
| `Hjson` | 47 KB | 宽容解析（注释/无引号键/尾逗号…） | **文本视图（只读）** |
| `Mods` | 119 KB | `internalNameOf` · 扫描 · `importPackage`（打/解 zip）· 启停 | **模型 + 导出** |
| `Util` / `Trash` / `Data` | —— | `atomicWriteText` · `Trash.move` · `dirOf` / `gameAlive` | **2.4 写入纪律** |

★ 结论：**"IDE"不是从零造**，而是把这 8 样**装进一个模型 + 四个视图**。
真正全新的只有 **画布**（唯一无先例的部分，见嵌入稿 §1）与**视图层**。
