## 0. 三条实测先把"画布是什么"定下来

用 `Style.java` / `PerFile.java`（arc 自己的 `Pixmap` 解码）逐张量原版原始图。**结论比预想的"素"得多**：

| 目标 | 画布 | 实测颜色数 | alpha 档位 | 不透明占比 | 样本 |
|---|---|---|---|---|---|
| **物品 / 液体** | **32×32** | **2~3 色** | **1 档**（只有全透明 / 全不透明） | ~360~560‰（图形约占中央一半） | 33/33 张 |
| **方块本体**（炮塔） | **128×128**（= size 4 ×32） | **3~4 色** | **1 档** | 175~1000‰ | `blocks/turrets/*.png` |
| **状态效果图标** | **32×32** | 🔴 **1 色** | **1 档** | ~200~320‰ | `statuses/status-*.png` |
| `-heat` / `-glow` **叠加层** | 同本体 | 1 色 | ⚠️ **多档**（实测 238 档，渐变光晕） | 27~105‰ | `*-heat.png` |

⇒ 四条直接影响功能的东西：

1. ✅ **调色板很小就够**：原版一张图只用 **2~4 色** ⇒ 16 格色板绰绰有余；
2. ✅ **不需要 alpha 滑块**（一期）：基础贴图 **alpha 只有两档**，像素画风本来就是硬边；
   ⚠️ 唯一要 alpha 的是 `-heat`/`-glow` 叠加层（二期）；
3. 🔴 **状态图标是"单色蒙版"**：一张图只有 **1 种颜色** ⇒ 颜色是**游戏按 JSON 的 `color` 染上去的**
   ⇒ 画状态图标时要给**"蒙版模式"**（画布按灰度/白画，并明确告诉用户"颜色由游戏决定"）；
4. ✅ **物品图形约占画布中央 50%** ⇒ 画布上给一个**中央参考框**是"隐形但很有用"的辅助。

⚠️ 注意口径：`blocks/` 全量（1660 张）的"中位 3 色"里含 **643 张 `environment/`**（地板/矿脉/Autotile 碎片，非常简单）
⇒ 别拿那个中位数说"方块都很简单"；上面表里的炮塔是**逐张看过**的。

## 一、面板功能清单

优先级：**P0 = 一期必须有**（没有它就不是个画板）· **P1 = 一期最好有** · **P2 = 二期** · **❌ = 明确不做**

### A. 画布区

| # | 功能 | 级 | 依据 |
|---|---|---|---|
| A1 | **画布尺寸 = 内容约定尺寸**（物品/状态 32×32；方块 `size×32`），**不给自由改** | P0 | 游戏**不校验**尺寸（2026-10-06 实测：`size:2` 配 32×32 照收但画出来小一半）⇒ 尺寸只能我们自己锁死 |
| A2 | 双指缩放 / 平移（"画笔 / 移动"两种手势模型二选一，见 §三） | P0 | 多格方块最大 160×160，屏幕放不下；32×32 时单指就够 |
| A3 | 像素网格（1px 格线，可开关） | P0 | 没有格线在 30px/格 下也还行，但放大后必须有 |
| A4 | **每 32 px 的粗分界线**（= 世界格） | P1 | 只对多格方块有意义：`size×32` 的画布上，"第几格"是画建筑时的关键参考 |
| A5 | 透明棋盘底（区分"透明"与"白"） | P0 | 物品贴图 ~50% 是透明的（实测） |
| A6 | 当前像素坐标显示 | P2 | 调试用；正常画画不需要 |
| A7 | **中央参考框**（提示"原版图形大致占中间一半"） | P2 | 实测不透明率 ~50%；但**这只对物品类成立**，写成硬约束会限制创作 |
| A8 | 深浅两种底色切换预览 | P1 | 游戏里地图底色会变（§80 已知：非固体方块落到地板色） |

### B. 绘制工具

| # | 功能 | 级 | 依据 |
|---|---|---|---|
| B1 | 铅笔（单像素，拖动连续） | P0 | —— |
| B2 | 橡皮（擦成**透明**） | P0 | 物品/方块贴图都有透明区；"擦成透明"与"擦成背景色"是两件事，要分清 |
| B3 | 油漆桶（flood fill） | P0 | 像素画最常用的"铺底色" |
| B4 | 取色器（从画布取色） | P0 | 无它则改一处颜色必须手输 hex |
| B5 | **撤销 / 重做**（≥30 步） | P0 | 没有它手机上没法画 |
| B6 | 直线 / 矩形（描边 + 填充两种） | P1 | 画外框、建筑轮廓 |
| B7 | 椭圆 | P2 | 像素画画圆用手点也行；实现成本不低（像素圆算法） |
| B8 | **左右镜像绘制**（对称开关） | P2 | ⚠️ 实测：**物品 0% 对称、statuses 80% 对称、blocks 只有 23%** ⇒ 对**状态图标**有用，对物品没用。降级 |
| B9 | 颜色替换（把画布上某色全换掉） | P2 | 改配色时有用，但不常用 |

### C. 颜色

| # | 功能 | 级 | 依据 |
|---|---|---|---|
| C1 | 当前色 + **上一个色**（两点快速来回） | P0 | 像素画基本是"底色 / 高光 / 阴影"三点来回切 |
| C2 | **16 格色板**（可编辑） | P0 | 实测原版一张图只要 2~4 色 ⇒ 16 格远够 |
| C3 | hex 输入 | P1 | 精确复刻别人的配色 |
| C4 | **明度梯度一键生成**（选基色 → 自动出 N 档高光/阴影） | P1 | ★ 这是**最能降低门槛**的功能：原版画风就是"同色 3~4 档 + 硬边"，手工调 4 档很容易翻车 |
| C5 | **从贴图取色板**（打开的现有贴图 → 抽它的颜色） | P1 | 改别人模组的图时，能一键继承原配色；`ModSprites` 已经能取到 PNG 字节 |
| C6 | 游戏配色板（取自 APK 的 `sprites/block_colors.png`） | P2 | `BlockTable`/`MapLoad` 已经会读它 |
| C7 | alpha 滑块 | ❌ P0/P1 | 实测基础贴图 **alpha 只有 1 档**；等到做 `-heat`/`-glow` 叠加层（多档渐变）再上 |
| C8 | HSV 色轮 | P2 | 手机上色轮不如"色板 + hex"好用；先不做 |

### D. 元信息与校验（★ 本产品特有，别人家的像素画工具没有）

| # | 功能 | 级 | 依据 |
|---|---|---|---|
| D1 | **目标显示**：写到哪个槽 / 哪个模组 / **在游戏里叫什么名**（`模组名-文件名主干`） | P0 | 注册名规则是 `ModSprites` 现成的（`<模组名>-<主干>`）；不显示的话用户不知道画的是哪张图 |
| D2 | **尺寸 ↔ JSON `size` 一致性**：画布尺寸确定后，**写图时顺带写/校验方块 JSON 的 `size`** | P0 | 🔴 游戏不校验；两者不一致 = **静默画歪**（只有进游戏才看得出来） |
| D3 | 同名处置：**覆盖 / 换名 / 取消**（覆盖 ⇒ 旧的先进中转站） | P0 | §86 第一条：少一问就是静默覆盖用户的东西 |
| D4 | 起稿来源：**空白 / 从现有贴图**（模组里的 / 原版的） | P0 | 「修别人模组的贴图」是最现实的使用场景；而且 `ModSprites` 已经把"按注册名取 PNG 字节"做好了 |
| D5 | **模式提示**：状态图标是"单色蒙版"（颜色由游戏染） | P1 | 实测 status 贴图只有 1 色 ⇒ 用户画成彩色会白画 |
| D6 | 叠加层提示（这张方块有 `-top`/`-glow`） | P2 | 实测这类同尺寸叠加层存在；一期只画本体 |

### E. 预览（★ 差异化就在这一块）

| # | 功能 | 级 | 依据 |
|---|---|---|---|
| E1 | 1:1 预览 | P0 | 基本盘 |
| E2 | **"游戏里看起来多大"预览** | P1 | 物品在 UI 里约等于 32 px 图标；方块是"铺满 size 格" —— 用户不知道这个比例就画不准 |
| E3 | **平铺预览**（同一张图重复铺开） | P1 | 画墙 / 地板 / 传送带时，"接缝对不对"只有平铺才看得出 |
| E4 | **丢进蓝图 / 地图预览里看** | P2 | ★ §80 已经有像素级蓝图渲染（真贴图、和游戏一样）⇒ 把画好的图**塞进一张现有蓝图**里看效果，这条**几乎白拿**，而且是最有说服力的预览 |
| E5 | 与相邻方块拼接预览（autotile） | ❌ | §82 已定案：**游戏自己的蓝图预览根本不融合邻居** ⇒ 我们也不做（做了反而不像游戏） |

### F. 保存 / 导出

| # | 功能 | 级 | 依据 |
|---|---|---|---|
| F1 | 保存到当前槽的**目录形态模组**（`.part` + rename；同名先问；游戏在跑先拦） | P0 | zip 不能原地改（重写 zip 已否决）；且真机实测：含 `classes.dex` 的模组解包成目录会直接坏掉 |
| F2 | 导出到用户选的位置（SAF） | P1 | 给"我只想画一张图拿去电脑上用"的用户一个出口 |
| F3 | 另存为（从已有贴图改完另存一个新名字） | P1 | 改原版贴图不可能写回 APK ⇒ 必须有"另存" |

### G. 面板形态（一屏怎么排）

| # | 功能 | 级 | 依据 |
|---|---|---|---|
| G1 | **全屏画布 + 底部工具条**（工具条不许盖住画布） | P0 | 画布是主角 |
| G2 | 工具条**可折叠** | P1 | 手机竖屏高度紧张 |
| G3 | 独立二级页面（Activity） | P0 | 与现有导航一致（槽页 → 模组页 → …） |
| G4 | 顶部一行：**目标 + 尺寸 + 游戏里的名字** | P0 | 见 D1；⚠️ **要有字数预算**（§85.16.2 的教训：超了会挤成三行） |
| G5 | 颜色面板做成**弹出层**（不占常驻高度） | P1 | 色板只在换色时需要 |
| G6 | 保存向导做成**分步弹窗**（选模组 → 选名字 → 确认尺寸） | P0 | 与"添加游戏"那个二选一弹窗同族（§84） |

## 二、明确不做（每条都写理由，避免以后反复讨论）

| 不做 | 理由 |
|---|---|
| **帧动画** | 原版 units 里 **`-N.png` 帧后缀 0 个**；动画是运行时靠零件旋转做的 |
| **单位零件拼装**（`-cell`/`-leg`/`-blade`） | 一个单位 5~10 张图 + 部件坐标，是"捏模型"不是"画贴图" |
| **effects / ui / rubble 贴图** | 不是内容贴图 |
| **图层 / 蒙版 / 选区 / 复制粘贴** | 一期不做；32×32 的画布上用手点更快 |
| **抗锯齿 / 曲线 / 渐变工具** | 像素画风本来就**不要**这些（实测原版 alpha 只有 1 档 = 硬边） |
| **半透明（alpha 滑块）** | 基础贴图用不到（实测）；留给二期叠加层 |
| **autotile 拼接预览** | §82 定案：游戏自己的预览也不融合邻居 |

## 三、两个必须先定下来的交互决策

| # | 决策 | 选项 | 我的建议 |
|---|---|---|---|
| **I1** | **单指是画还是移动？** | ① 单指画 + 双指移动（标准做法）② 工具条切"画笔/手"模式 | **①**：像素画要密集落笔，模式切换很打断；双指移动是手机上的通用直觉 |
| **I2** | **画布与"目标"的先后** | ① 先选目标（模组+内容名）→ 才知道尺寸 ② 先画 → 保存时再问落点 | **①**（尺寸是画布的前提，A1 锁死尺寸）；但**"从已有贴图起稿"要能反向预填**目标 |

## 四、要你拍板的（功能层面）

| # | 问题 | 建议 |
|---|---|---|
| **Q1** | C4「明度梯度一键生成」做不做 | **做**（P1）—— 原版画风就是"3~4 档同色系"，这一条最能决定"画出来像不像" |
| **Q2** | E4「塞进蓝图预览看效果」排一期还是二期 | **二期**（一期先把画板跑通），但它**性价比最高**，落地时优先 |
| **Q3** | B8「镜像绘制」要不要 | **不进一期**（实测物品 0% 对称），等做状态图标时再看 |
| **Q4** | 状态图标的"蒙版模式"要不要一期就带 | 如果一期内容类型**不含 statuses** ⇒ 二期；含 ⇒ 必须带（否则用户白画） |

## 五、证据与复现

| 路径 | 是什么 |
|---|---|
