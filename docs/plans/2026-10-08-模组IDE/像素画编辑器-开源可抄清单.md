## 0. 结论摘要

1. ✅ **有，而且比预想的好**：最佳目标是 **`com.ansdoship.pixelarteditor`**（上游 `kgultrt/PixelArtEditor` /
   `DereckySany/PixelArtEditor`）—— **Java + Android 原生 + GPL-3.0（与我们完全相同）**，
   里面有**我们正缺的那几块**：命令式撤销池、调色板模型、调色板/取色器 View。
2. ✅ **依赖几乎为零**：那一层的"第三方"只有 **`androidx.annotation` 的 `@NonNull/@Nullable` 注解**
   （删掉即可）+ 一个 63 行的 AmbilWarna 取色方块 ⇒ **能整块搬进我们"纯 framework、无 Gradle"的工程**。
3. ❌ **但"画布"那块谁也给不了**：它的 `CanvasView` 只有 101 行、是个 `SurfaceView` 壳，
   **触摸→像素、缩放平移、绘制循环全在 183 KB 的 `MainActivity` 里**。
   ⇒ **我们最缺的那块仍然要自己写**，只能抄它的**设计决策**。
4. ⚠️ **别碰 `Novix`（Anuken 自己写的）**：许可相同、想法值得读，但**架构是 libGDX**（112 处），
   而且作者自己在 README 里写明**已归档、"代码古老、用的库我不想再碰"**。
5. ⚠️ `MISTER-CHAN/icon-editor` 的架构**最漂亮**（Layer/LayerTree/Frame/Project/History），
   但**没有 LICENSE 文件 ⇒ 代码不能抄**（只能当思路参考）。

## 2. ★★ 最佳目标：`com.ansdoship.pixelarteditor`（GPL-3.0）

**规模**：60 个 Java 文件 / **10,394 行**。但**别被总数骗了** —— 它有一个 183 KB 的 `MainActivity`，
而**真正值得抄的那一层只有一千多行**：

| 文件 | 行 | 是什么 | 能抄吗 |
|---|---:|---|---|
| `editor/ToolFlag.java` | 68 | **工具枚举**：`PAINT / SHAPE / ERASER / FILL / SELECTION / COLORIZE`，含 `ShapeFlag`(LINE/CIRCLE/ELLIPSE/SQUARE/RECTANGLE)、`PaintFlag`(**REPLACE / OVERRIDE**)、`SelectionFlag`(NONE/SELECTED/**CUT/COPY**) | ✅ 直接抄（当需求清单用） |
| `editor/buffer/*`（14 个文件） | **~900** | ★★ **命令 / 快照池式撤销**：`ToolBuffer` 抽象 + `PointBuffer` / `PaintBuffer` / `FillBuffer` / `ClearBuffer` / `RotateBuffer` / `FlipHorizontal` / `FlipVertical` / `MultiBuffer` / `SelectionBuffer` + **`ToolBufferPool`（289 行，带 `maxSize` 上限与 `cache/current` 双位图）** | ✅ 架构可搬；⚠️ 用了 `com.tianscar.simplebitmap` 小工具（换成 `Bitmap.getPixels/setPixels` 即可） |
| `editor/palette/*` | 352 | **调色板模型 + 工厂**（`Palette` / `PaletteFactory` 用 `JSONObject` 存盘 / `PaletteFlag`） | ✅ 可搬（格式自己定） |
| `ui/view/PaletteView.java` | 192 | 调色板 View | ✅ 只依赖注解 |
| `ui/view/ColorPickerView.java` | 222 | 取色器 View（HSV 方块那类） | ✅ 只依赖注解 |
| `ui/view/CanvasView.java` | **101** | ⚠️ **只是个 `SurfaceView` 壳**：`lockCanvas()` → 回调 `OnInvalidateListener.onInvalidate(canvas)`；**不含触摸** | ⚠️ 只能抄"用 SurfaceView 当画布"这个决定 |
| `ui/view/CheckedImageView.java` | 65 | extends `androidx.appcompat.widget.AppCompatImageButton` | ❌ 不需要 |
| `MainActivity.java` | **183 KB** | 🔴 **触摸→像素、缩放平移、绘制循环、全部 UI 接线都在这里** | ❌ 别抄 |
| `colorpicker/`（子模块） | 63 | AmbilWarna 取色方块（一个文件） | ✅ 极小 |

### 2.1 依赖体检（决定能不能进我们"零依赖"的工程）

| 依赖 | 落在哪 | 处置 |
|---|---|---|
| `androidx.annotation.{NonNull,Nullable}` | `BitmapBuffer` / `ToolBufferPool` / `Palette` / `PaletteFactory` / `CanvasView` / `PaletteView` | ✅ **只是注解** ⇒ 删掉 import 即可 |
| `androidx.appcompat.widget.AppCompatImageButton` | `CheckedImageView`（不抄） | —— |
| `com.tianscar.simplebitmap.{BitmapChanger,BitmapUtils}` | `ToolBufferPool` | ⚠️ 换成 Android 原生 `Bitmap.getPixels/setPixels`（几十行） |
| `app/libs/commons-io-2.5.jar`（208 KB） | 文件操作 | ✅ 用不着 |
| `io.noties.markwon`（Markdown） | "关于/帮助"页 | ✅ 用不着 |
| 其余 androidx（appcompat / constraintlayout / preference / cardview） | 界面壳 | ✅ 我们用 `Activity` + `LinearLayout`，不需要 |

⇒ ★ **结论：`editor/` + `ui/view/` 这一层实际上只依赖 `androidx.annotation`** ⇒ **可以整块搬进来**。
✅ 每个文件头**自带 GPL-3.0 声明 + `Copyright (C) 2021 AnsdoShip Studio`** ⇒ 搬的时候**保留文件头**即可（同许可，合规）。

### 2.2 它的"设计决策"（★ 比代码更值钱，尤其画布那块）

因为它把画布逻辑写在了 `MainActivity` 里，**代码抄不动、但决定可以照抄**：

| 决策 | 它的做法 | 对我们的意义 |
|---|---|---|
| **画布载体** | `SurfaceView` + `SurfaceHolder.lockCanvas()` + 回调式重绘（**不是** `View.onDraw` + `invalidate()`） | ⚠️ 两者都行；我们的画布小（≤160×160），`View`+`invalidate()` 更简单，且不吃 Surface 生命周期 |
| ★ **缩放** | **整数倍**：`IMAGE_SCALE_MIN=1` / `MAX=64`，用 `Matrix` 平移 + 整数缩放 | ★ **很有价值的先例**：像素画就该整数倍缩放（避免分数缩放糊掉）；`1~64` 这个量级也印证了我评估稿里"32×32 每格约 30px、不用怎么缩放"的判断 |
| ★ **手势** | **不用 `ScaleGestureDetector`**，而是裸 `MotionEvent` 的 `ACTION_POINTER_DOWN/UP` + `getPointerCount()` 自己判 | ⇒ **双指不是必需的**；真要双指，也只需要判 pointerCount，不必引手势库 |
| **撤销** | 快照池 + **`maxSize` 上限**（不是无限） | ✅ 与我的判断一致；⚠️ **我们要按字节设上限**（160×160 一张快照 100 KB，200 步 = 20 MB） |
| **工具体系** | 工具 = 枚举 + **每个工具一个 Buffer 类**（策略模式）；`SHAPE` 再分 5 种 | ✅ 干净，直接照搬分层 |
| **画笔语义** | `PaintFlag.REPLACE` / `OVERRIDE` 两种 | ★ 我们功能清单里没写这条 —— **要补**：落笔遇到已有像素是"替换颜色"还是"连透明度一起覆盖" |
| **调色板** | 自己的 JSON 格式（`PaletteFactory` + `JSONCodec`） | ✅ 我们也可以用 JSON（还能白拿"从贴图取色板"） |

## 3. `rjmarsan/Pixelesque`（BSD-3，63★）—— 许可最宽松，但画布抄不到

**规模**：36 个 Java 文件 / **5,737 行**；Eclipse 时代工程（`.classpath`/`project.properties`），
**`minSdkVersion=8` / `targetSdkVersion=10`**（2010 年），依赖 `libs/processing15.jar`（**190 KB**）。

| 能抄 | 说明 |
|---|---|
| `History.java`（1.9 KB） | **快照式撤销**：`int[]` 全量拷贝 + `MAX_HISTORY=200`，模型/视图靠 `Drawer` 接口解耦 ⇒ 设计可抄，⚠️ **上限要改成按字节** |
| `PixelArtState.java`（0.5 KB） | 工具枚举 + 当前色 |
| `Drawer.java` | 2 方法接口（`scheduleRedraw`/`scheduleUIRedraw`）——**模型不该知道视图** |
| ★ `shapes/Shape.java` + `SuperShape.java` | **工具生命周期**：`update()`（拖动预览）→ `commit()`（落盘 + 压历史）→ `cancel()`（回滚），带 `isCalculating`/`commitOnFinish` 处理**异步计算** |
| `shapes/Bucket.java` | 洪水填充 —— ⚠️ 是**朴素 BFS**（`Queue<Point>` + `HashSet<Point>` + 预分配 `Point[]`）⇒ **我们写扫描线版更好**（它那个在 160×160 上会造 2.5 万个对象） |
| `shapes/Line.java` | **Bresenham 直线**（源码注释自己写着 "From wikipedia"）⇒ 教科书算法，照写即可 |

| 抄不到 | 为什么 |
|---|---|
| 🔴 **画布 / 触摸 / 坐标映射** | `PixelArtEditor **extends PApplet**`（Processing）+ `TouchListener`；坐标映射函数签名是 `getDataCoordsFromXY(PApplet p, float x, float y)` ⇒ **绑死在 Processing 上** |
| 工具类本身 | 全部 `import processing.core.PApplet` + `com.rj.processing.mt.Cursor` ⇒ **只能抄算法、不能抄文件** |
| 取色器 | 它自己没用，导的是第三方 `de.devmil.common.ui.color`（AmbilWarna 系） |

## 6. 结论：能抄多少？

| 我们的功能块 | 能抄吗 | 从哪 |
|---|---|---|
| **命令式撤销 / 重做** | ✅ **能**（架构 + 类划分） | `com.ansdoship` 的 `editor/buffer/*`（~900 行）+ Pixelesque 的 `Shape.update/commit/cancel` 生命周期 |
| **调色板模型与 UI** | ✅ **能** | `editor/palette/*`(352) + `ui/view/PaletteView`(192) |
| **取色器 UI** | ✅ **能**（很小） | `ui/view/ColorPickerView`(222) + `:colorpicker`(63，AmbilWarna) |
| **工具枚举 / 分层** | ✅ **能** | `ToolFlag`(68)（还顺手补上我们漏掉的 `REPLACE/OVERRIDE`） |
| **洪水填充 / 直线 / 形状算法** | ✅ **能抄思路**（代码要自己写：一个绑 Processing，一个是朴素实现） | Pixelesque `shapes/*` |
| 🔴 **画布：触摸→像素、缩放平移、绘制循环** | ❌ **抄不到** | `com.ansdoship` 把它写在 **183 KB 的 `MainActivity`** 里；Pixelesque 写在 **`PApplet`** 里；Novix 写在 **libGDX Actor** 里 |
| 写盘 / 槽 / i18n / insets / 自检 | ❌ 谁也没有 | **本工程独有**，本来就得自己写 |

★ **一句话**：**能抄的约占 30~40%（撤销、调色板、取色器、工具分层、算法思路），
而我们唯一完全没有的那块（画布手势）恰好谁也没给** —— 但**它的设计决策可以照抄**（整数缩放 1~64、`Matrix` 平移、
双指只判 `pointerCount`、快照池带上限）。

### 6.1 三个坑（照抄前必读）

1. **`MainActivity` 183 KB 是反例，不是样板** —— 只抄 `editor/` 与 `ui/view/`，**别抄它的组织方式**。
2. **文件头必须保留**：它每个文件都带 `GPL-3.0` 声明 + `Copyright (C) 2021 AnsdoShip Studio`
   （同许可可搬，但**署名不能抹**）；同理 Pixelesque 是 BSD-3，搬它的设计要注明出处。
3. **快照撤销按字节设上限**：它用 `maxSize`（步数），我们要按**像素数 × 步数**算
   （32×32 = 4 KB/步，160×160 = 100 KB/步）。

## 7. 对我们的功能清单的**修正/补强**（依据别人的真实选择）

| # | 修正 | 依据 |
|---|---|---|
| 1 | **补一个"画笔语义"开关**：`替换颜色` / `覆盖（含透明）` | `ToolFlag.PaintFlag.REPLACE/OVERRIDE` |
| 2 | **缩放用整数倍（建议 1~64，2 的幂更省心）**，不必做连续缩放 | `IMAGE_SCALE_MIN=1 / MAX=64` + `Matrix` |
| 3 | **双指不是必需**：只判 `pointerCount` 就能做双指平移/缩放，不必引手势库 | 它没用 `ScaleGestureDetector` |
| 4 | **撤销做成"池 + 上限"**，且每个操作一个类（策略模式），不要一个巨型 `undo()` | `editor/buffer/*` 十四个类 |
| 5 | **调色板落盘用 JSON**（而不是自定义二进制），顺便能白拿"从贴图取色板" | `PaletteFactory` 用 `JSONObject` |
| 6 | ⚠️ 洪水填充**不用抄** Pixelesque 的 BFS —— 用**扫描线**（少两个数量级的对象） | `Bucket.java` 的 `Point[]` + `HashSet<Point>` |
| 7 | ⚠️ 它把 `SELECTION`（含 CUT/COPY）做进了主工具集 —— 与我们功能清单"选区放二期"的判断一致 | `ToolFlag.SELECTION` + `SelectionFlag` |
