## 0. 定位 + 受众

**手机上从零造出一个能玩的 Mindustry 模组，并且当场跑起来。**

受众 = **没有电脑的学生，手机是唯一设备** ⇒ ① **闭环速度 > 编辑能力**（"改完立刻进游戏看""崩了能说清哪个模组干的"比"功能多"值钱）；② **不能假设"回头在 PC 上改"**（工程/文件管理必须应用内闭环，不能靠 MT 管理器）；③ 逻辑能力靠**游戏自带的 Rhino（JS）**，不靠 Java（手机端做不了 javac/d8，社区路线 Termux）。
★ **差异化**：编辑器 + 运行环境 + **崩溃归因（`CrashAnalysis`，F23 已落地）**在同一个 App 里；调研过的同类（mindmod 等）**没有"启动器 + 模组编辑器"二合一**。

## 一、冻结层（**已定，不再讨论**）

| # | 定案 | 为什么 / 依据 |
|---|---|---|
| **I-1** | **形态 = IDE**（工程 + 文件树 + 文本 + 贴图 + 概览 + 预览）；**模板降级为"起步器"**（模板 → 骨架 → 进 IDE 编辑） | schema **机器生成**（418 文件 / 1386 `doc` / 2177 `default` / 反射真实键表）；"常用字段表"要**人**维护、作者本人不写 JSON 模组 ⇒ 判不了"常用"。**补全 = schema 字段 ∩ 当前槽版本真实存在的字段** |
| **I-2** | **工程的家 = 丙（独立工坊 + 双向搬运）**：`hub/projects/<名>/`（与 `backups/` `cas/` `previews/` 并列） | zip 才是有用的那 96%（真机 **23/24 是 zip**）；给"从零造"一个地点；**不碰正在玩的槽** |
| **I-3** | `ModProject` 的**读**两来源一视同仁（槽里模组 / 工坊工程）；**写**只管工程内部；**写槽只有一条路 =［安装到槽］** | 全结构最值钱的一条：一期"改正在玩的槽"**根本不存在** ⇒ 风险降到"弄坏自己的一份工程" |
| **I-4** | 工程元数据 = 工程根 **`.mdt-project.json`**（`{schema,name,from,created}`，点开头）；🔴 `schema` **只加不改** | 一有用户数据就得写迁移 |
| **I-5** | 工程目录名 = **内部名口径**（`Mods.internalNameOf`）；**重名不静默覆盖**（追加 `-2`/`-3`） | 目录名 = 用户的工程身份 |
| **I-6** | ［安装到槽］同名 ⇒ **先问**（覆盖/换名/取消）；覆盖 ⇒ 旧件**完整进中转站** | §86：少一问 = 静默丢东西 |
| **I-7** | 删除文件 ⇒ 复用既有中转站（**新增 `Trash.DIR_PROJECTS` 常量 + 对应恢复路径** —— ⚠️ `Trash` **没有 `Kind` 枚举**，用的是 `DIR_MAPS`/`DIR_MODS`/`DIR_SAVES`/`DIR_SLOTS` 那套常量），不另造回收站 | 一套机制一份实现 |
| **I-8** | 槽里的模组（含 zip）**一律只读**；**zip 读取不解包**（条目引用直读：`ModSprites.Hit={pack,entry,directory}`） | `writable=false`；解包要产临时目录 + 管生命周期 |
| **I-9** | 🔴 **含 `classes.dex` 的模组拒绝复刻/解包**（**硬拦**，不是警告、不是"让用户决定"） | 真机 A/B（Android 16/API 36 + 官方 **159.7**，唯一变量 = 形态）：目录 `{mod.hjson,classes.dex}`（dex 已 `chmod 444`）⇒ ❌ `ClassNotFoundException`（从 `ModClassLoader.findClass` 抛）；**同一份 dex** 打 zip ⇒ ✅ `Loading mod:` + 构造器跑通。机制：`AndroidLauncher.loadJar` 把路径原样交给 `DexClassLoader`，**它不接受目录**。判据 = `Mods.Info.parts()` 的 `JAVA_DEX`。⚠️ 口径 = 159.7 + API 36，老版本未逐个验 |
| **I-10** | **只报不改**：C1/C2/C4 只提示，不做"一键修"（自动改名/自动缩放） | 自动改用户文件的风险远大于收益 |
| **I-11** | 判据**只有一份实现**（`issues()`）；🔴 **不做 C3「孤立贴图」** | 后缀是开放集合（`-top`/`-glow`/`-team`/`-heat`/`-cell`/`-leg`/`-blade`），枚举必漏（§45.9）⇒ 噪声淹掉真问题（§85.16）；将来要做也只能是"信息"级 |
| **I-12** | 口径各自**只一处实现**：注册名 = `ModSprites`；尺寸 = `expectedSize`（**32 px = 1 格**，方块 `size×32`）；内部名 = `Mods.internalNameOf`。**派生量只许在模型层算** | 反复吃"同一判据两处实现必分岔"（§77/§111/§115） |
| **I-13** | ★ **导入进来再编辑，绝不编辑外部文件** ⇒ **不做** SAF 目录树授权（`ACTION_OPEN_DOCUMENT_TREE` + `takePersistableUriPermission`）、**不做**"外部改动检测" | 我们成为唯一写入者 ⇒ provider 差异/半写坏/权限/并发**整类消失**；也绕开 Android 11+ "Download 根/内部存储根不可选" |
| **I-14** | **语言服务由 Java 侧供给**（`Hjson` 报错位置 + schema 补全候选）；视图侧只负责**显示与输入** | 守住"同一判据只有一份实现"：HJSON 语义**只有 `Hjson` 那一份**，编辑器不许再实现一套 |
| **I-15** | 模型层（`ModProject`/`ModWriter`/`ProjectStore`/`FileOp`）**不许 import `android.view.*`/`android.widget.*`** | 能在 PC 单独编译 + 单测（同 `SettingsBin`/`Msch`） |
| **I-16** | 工程根判据**复用 `Mods` 那套，不另写一份**：候选名表 = **`Mods.META_FILES`**（`mod.json`/`mod.hjson`/`plugin.json`/`plugin.hjson`，按下标取首个存在的）+ **`Mods.resolveRootPrefix`**（允许套一层目录） | 否则"我们解出来的工程根"与"游戏认的模组根"会分家 = 同一判据两处实现 |
| **I-17** | 🎯 **一期范围 = 纯数据模组**（`mod.hjson` + `content/**` + 贴图 + `bundles/`）：**不做** `scripts/*.js` 的编辑、**不碰**含 `classes.dex` 的模组（后者按 **I-9** 硬拦） | 用户 2026-10-08 明确「不想折腾 JS 和 Java 模组」⇒ 一期"手机造出一个能玩的东西"靠 JSON + 贴图**就成立**（脚本只是加逻辑，后加是加法，见 §五） |
| **I-18** | 🖊 **文本视图引擎 = 原生**：`EditText`（可写）+ **`Spannable` 高亮** + **符号键条**（`{}[]":,` 一排）+ **schema 补全弹层**。🔴 **不引 WebView / CodeMirror** | 用户 2026-10-08 拍定。不引 **JS 构建链**（本机 `CodeMirror`/`typescript`/`esbuild` 全无 ⇒ 要么加 npm，要么把编好的 JS 当**黑盒生成物**入库，与"生成物必须留生成器"冲突）+ 无"安卓 IME 在 WebView 里"的组合输入风险 + 体积零增量；代价 = 查找替换 / 多光标 / 折叠**要自己写**（一期不做，属免责层） |

🔴 **引用纪律（本轮新规矩）**：文档与代码注释里**一律不写行号**，引用产品代码一律用**标识符**（类 / 方法 / 常量名）；
确需提到行号时**必须紧跟**「（当时行号；仓库有并行会话，可能已漂）」。理由：行号会漂（旧稿引用的那个候选名表位置**早就漂了**，现在得按 `Mods.META_FILES` 去找），
且本仓库**常有第二个会话**在改同一批文件 ⇒ 行号是"一写就过期"的引用。

**体积纪律**：

| 项 | 规则 |
|---|---|
| schema 落点 | **`res/raw/mod-schemas.deflate`**（418 文件 / 395 592 B → deflate **60 972 B**） |
| 🔴 禁止 | **Base64 Java 常量** —— javac `CONSTANT_Utf8` **上限 65535 字节**（81 296 B 一坨直接编不过；`MapStatsTable.java` 那种 4 KB 没事）；生成器与版本写进文件头注释 |
| 🔴 判据 | 看 **`build/dex/classes.dex`**，**别**用 APK 总大小 —— `apksigner` 把 zip 中央目录对齐到 4096，小于边界的变化**总大小一个字节都不变** |
| 本轮实测（参考） | 发布包 **709 741 B**；`classes.dex` **985 560 B**（压缩 456 681 B）；`resources.arsc` **193 584 B**；`SelfTest.java` = 源码 **26.3%**（发布形态裁剪的另一议题） |

## 二、结构

### 2.1 分层与数据流

```
入口层  主页工具卡［模组工坊］→ ProjectsActivity（工程列表）
        模组详情弹窗 → ［打开…］（看槽里的模组，只读）｜［复刻到工坊…］（→ 可写工程）
        ★ 分享 intent（ACTION_VIEW / ACTION_SEND）+ hub/inbox/（收件箱）
                              │
模型层  ProjectStore  工程的"家" hub/projects/<名>/：create / list / dirOf / rename / delete(⇒Trash)
(冻结)                ★ 导入三入口 fromSlot · fromZipOrFiles · fromUri(分享/inbox)
                      ★ installToSlot = 唯一写槽路径（复制成 slot-<槽>/mods/<名>/，目录形态）
        ModProject    只读快照（两种来源）：Meta / List<Entry> / List<Content> /
                      List<Sprite> / List<Issue> / notes() + issues()
        ModWriter     唯一写**单个文件**的入口（文本/PNG；Result 码；不弹窗；不 import UI）
        FileOp        工程内增删改（内部走 ModWriter；模板见 2.4）
                              │ 复用（不重写，清单见 §三）
视图层  ①文件（工程首页）②概览（内容/贴图/问题）③文本 ④贴图 ⑤预览 —— 只吃 ModProject
(免责)  不许自己算注册名 / 尺寸 / 路径
```

**主数据流**：导入（槽 / zip·散文件 / 分享 intent / inbox）→ `hub/projects/<名>/` → 编辑（文件树/文本/贴图）
→［安装到槽］→ 一键启动 → 看 `last_log.txt` + **崩溃归因**（`CrashAnalysis`）。

### 2.2 新类

| 类 | 角色 |
|---|---|
| `ProjectStore` | 工程仓库 + 导入三入口 + 收件箱 + **唯一写槽路径** |
| `ModProject`（`Source`/`Meta`/`Content`/`Sprite`/`Issue`/`Entry`） | 只读快照 + 判据（`issues()`） |
| `ModWriter` | 唯一写单文件入口（`OK/NEED_CONFIRM/BUSY/IO/VERIFY`） |
| `FileOp` | mkdir / 写文本 / 从模板 / 改名 / 复制 / 删除 |
| `ModIdeText` | `Issue.code` → 资源 key 的**唯一映射** |
| `ProjectsActivity` / `ModIdeActivity` | 工程列表 / 工作台（**［文件］默认 +［概览］**两标签） |
| `ModSpriteActivity` / `ModTextActivity` / `ModPreviewActivity` | 贴图（画板）/ 文本（**一期即写**）/ 预览 |
| `tools/ide-check.py` | 门禁 IDE-01~04（与 `i18n-check.py` 同族） |

★ **Activity 定案 = 5 个**：`ProjectsActivity`（工程列表）+ `ModIdeActivity`（工作台 · 两标签）+ `ModSpriteActivity` + `ModTextActivity` + `ModPreviewActivity`。
⚠️ 旧"视图稿"写「4 个」，是**漏了 `ProjectsActivity`**（旧"模型稿"的数据流里本来就有它，而"工程是一等公民"与块 A 都依赖它）⇒ **以 5 个为准**。

★ **入口统一方案（定案，取代两稿各自的"唯一措辞"）**：① 主页**工具卡**「**模组工坊**」→ `ProjectsActivity`（工程列表 = **可写工程**的工作台入口）；
② **模组详情弹窗**里两行、职责分明：只是在槽里**看**这个模组（只读）用「**查看…**」、要变成可写工程用「**复刻到工坊…**」。
⇒ 不再有两个"唯一措辞"：工具卡那条只管"**进工坊**"，弹窗那两条只管"**就地看 / 就地复刻**"。

★ 每个新 Activity 的**五件套**（漏一条 = "编译过、自检绿、真机不对"）：① manifest 注册；② `SelfTest.PAGES`；
③ ㉛ 骨架名单；④ 根节点 `@+id/root` + `Util.applySystemInsets(root)`；⑤ 文案走 `Trans` + `values/`、`values-zh/`
**两边都加** + `SRC-02` 台账新行。

### 2.3 判据（只读、不碰盘、一份实现）

```
C1 缺贴图 ERROR : 每条 content 的 expectedRegion(c) 在 sprites 里找不到 ⇒ I_NO_SPRITE(stem)
                  ⚠️ dir != "blocks" 也照样判（物品/液体/状态/单位都有贴图）
C2 尺寸不符 ERROR: 仅方块且 size>0；缺图由 C1 报、不重复；s.w/h != size*32 ⇒ I_SIZE_MISMATCH
C4 size 缺失 WARN: 仅方块且 size<=0 ⇒ I_SIZE_MISSING

另有三条（不属 C 族，是"读不出来"类）：
I_SPRITE_NOT_SQUARE  WARN : 贴图非正方形 ⇒ 瓦片数取 min(w,h)/32
I_META_UNREADABLE    ERROR: meta 解不开（parseOk == false）
I_CONTENT_UNREADABLE WARN : 某条内容解不出来（args 带原始诊断）
```
🔴 `Issue` 码**共 6 条**（上面 3 + 上面 3）—— 门禁 **IDE-04** 要拿这 6 条与 `ModIdeText` 的资源 key **双向**对账，**少一条 = 界面上显示不出来**。
`Issue` = **码 + 参数**（`level/code/where/args`），**不放成品句子**（文案走 `ModIdeText`；§78/§85.16）。

**读侧边界**：`ModProject.readAt` 对**单个文本文件**设 **256 KB 上限**（超了返回 null，视图说"太大" —— 不许把手机拖死）；`ModProject` **不缓存**（每次 `load()` 重扫：工程小，缓存换来的是"两份真相"的风险，不划算）。

**与既有功能并列，不搬**：冲突体检（`Mods`）· 蓝图缺件 · 地图统计 · 模组类型 **继续待在原处**，**不搬进 IDE**；`ModProject` **不许**重写"冲突体检"的判据。将来若要共用，**只准把判据挪进模型层，不准把视图搬来搬去**。

### 2.4 写路径

**`ModWriter` 八步**（两个写方法共用）：① `Data.gameAlive` ⇒ `BUSY`（不弹窗）→ ② 父目录不存在则建 →
③ 目标已存在且 `!overwrite` ⇒ **立刻 `NEED_CONFIRM`（一个字节都不写）** → ④ 写同目录 `<名>.part` →
⑤ **写后自证 = 只提示**（✅ **Q-B 已拍 2026-10-08：只给提示**）：解析不过 / 尺寸异常之类**一律只进问题列表**（例："这个文件现在解不开"），**不阻塞保存、不自动还原** —— "编辑到一半不合法"是**正常状态**。
⚠️ 唯一例外是 **IO 层失败**（写不进 / 读不回 / 字节数对不上）：那不算"提示"，仍返回 `VERIFY` / `IO`，且**原件保持不动** →
⑥ 覆盖时旧件 `Trash.move`（**不是裸 `renameTo`**，跨卷会静默失败）→ ⑦ `.part` → 目标名（同目录 ⇒ 必然同卷）→ ⑧ `OK`。
★ **不弹窗**：同名先问由**调用方**拿到 `NEED_CONFIRM` 后弹，再带 `overwrite=true` **重调一次**（§86.8）。
🔴 **工程在 `hub/projects/`、游戏不读 ⇒ 不需要 `gameAlive` 门禁**（写进注释，否则有人"顺手"加上会变成"游戏开着就不让编辑工程"）。

**模板**：`T_CONTENT_JSON`（`content/<复数类型>/<名>.json` 骨架）· `T_MOD_META`（`mod.hjson`，名字=工程目录名）·
`T_BUNDLE`（`bundles/bundle.properties` + `item.<名>.name=` —— **没有它游戏里显示内部名**，实测）· `T_EMPTY_TEXT`。

### 2.5 不变量 / 门禁

视图层**不许**出现：`internalNameOf` / `"-" +` / `* 32` / `.part` / `renameTo` / `compress(` / `slot-` 写入（V1/V2/V4/V9）。
模型层**不许** import UI 包（V6，编译期判死）· `internalName` 必须逐字符等于 `Mods.internalNameOf`（V3，拿大小写混合 + 空格样本对）·
`.part` 永不进清单/备份（V5）· `load()` 前后目录清单 + 每文件 md5 完全一致（V7）· `Issue` 里没有成品句子（V8）。
**门禁 `tools/ide-check.py`**：IDE-01 模型层出现 `android.view`/`android.widget` ⇒ ERROR · IDE-02 视图层出现派生量/落盘动作 ⇒ ERROR ·
IDE-03 **元断言**（故意塞一行 `x * 32` 要求当场判死）· IDE-04 `Issue.code` ↔ `ModIdeText` key **双向**对账。

| 零件 | 规模 | 提供 → 用在哪 |
|---|---|---|

| `Mods` | 119 KB | `internalNameOf` · 扫描 · `importPackage`/`copyMods` · 启停 · `Info.parts()`/`JAVA_DEX` → 模型 + 导入/安装 + 解包硬拦 |

| `MapLoad` | 11.4 KB | APK 取图 · `BitmapFactory` · **`bmp.compress(PNG,100)`** → 贴图视图（编码已实测） |
| `ListQuery` | 8.8 KB | ★ "判据收进一个类、多页共用"的先例 → C1/C2 的组织方式 |
| `Util` / `Trash` / `Data` | —— | `atomicWriteText` · `Trash.move` · `dirOf` / `gameAlive` → 写路径纪律 |
| `CrashAnalysis` / `LogActivity` | —— | 崩溃归因（四层判据）· 日志页 → ★ **闭环的另一半** |
| `BlockTable` / `ClassRotateTable` | 生成表 | 方块表 · 朝向 → 尺寸/朝向提示；配色可读 APK 的 `sprites/block_colors.png` |

★ **"IDE"不是从零造**，而是把这批零件装进"一个模型 + 五个视图"。**真正全新的只有两处**：**画布手势**
（全仓库 `extends View`/`onTouchEvent`/`onDraw` **零命中**）与**视图层**；文本侧已定走**原生**（**I-18**）⇒ 真正全新的**仍只有画布手势一处**。

### JS 脚本（逻辑能力的唯一路线；依据 `docs/backlog/04 §2.3`）

- ★★ **真机已验**：脚本能注册事件、访问全部内容。链：`run()` 来自 `core/assets/scripts/global.js` 的
  `new java.lang.Runnable(){run: method}` → Rhino **JavaAdapter** → 运行时生成字节码 →
  `AndroidRhinoContext.BaseAndroidClassLoader.defineClass()` 用 `com.android.dx` 翻 dex → `InMemoryDexClassLoader`
  （源码：`AndroidRhinoContext.BaseAndroidClassLoader.defineClass()`；API ≥ O 全程内存不落盘）。
  真机日志：`MDTJS-T3 OK adapter+dx, class=$Proxy4` / `T4 event fired: ClientLoadEvent` / `T5 content ok, blocks=446`。
- 🔴 `T5` 的 **`items=22` 是原版基线，不是"内容注册成功"的证据**（评估稿 §11）：脚本跑在 `mods.load()` 阶段、
  早于 `createModContent()` ⇒ 要问"注册成功了吗"必须在 **`ClientLoadEvent`（或更晚）**问（那时 `items=25`）。
- 硬规则（**`Mods.loadScripts`**）：触发 = **`scripts/` 目录存在**（`mod.json` **不需要** `hasScripts`）·
  只有 **1 个** `.js` ⇒ 用它（不必叫 `main.js`）· **≥2 个只认 `main.js`**，找不到就打 `No main.js found for mod` 并**跳过该模组** ·
  报错**不致命**（`[E] [<mod>/<script>]: …` 后继续）· `print()` 落 `<数据根>/last_log.txt`，行首带 `[<mod>/<script>]`。
  ⇒ **生成器永远输出 `scripts/main.js`**。⚠️ 包内条目名含反斜杠（`scripts\main.js`）⇒ 游戏当目录看 ⇒ 找不到 `main.js`（我们与游戏同判）。

## 五、明确不做（**每条带理由**）

| 不做 | 理由 |
|---|---|
| Git 集成 | 与"给 MDT 用户造模组"无关 |
| 脚本编辑器（JS/Java） | **一期不做**（范围见 **I-17 = 纯数据模组**）；JS **可后加**（文本视图换个后缀就能编辑 `scripts/*.js`）；**Java 手机端做不了**（要 d8 + 完整 SDK，社区路线 Termux） |
| 通用构建系统 | 模组的"构建"= **打 zip**，`Mods.importPackage` 已有 |
| 同屏分栏（文本 + 画布） | 手机竖屏上"看清 JSON"与"画准像素"互相打架 |
| "一键修"（自动改名/自动缩放） | 自动改用户文件的风险远大于收益；**一期只报不改** |
| 孤图判据（C3） | 后缀开放式，枚举必漏 ⇒ 噪声淹掉真问题 |
| 帧动画 / 单位零件拼装 | 原版 units 的 `-N.png` 帧后缀实测 **0 个**；动画靠运行时零件旋转 |
| HSV 色轮 | 手机上不如"色板 + hex"；一期给 16 格 + 最近用色 + hex |
| alpha 滑块（基础贴图） | 实测基础贴图 alpha **只有 1 档**；留给二期 `-heat`/`-glow`（实测 238 档） |
| 抗锯齿 / 曲线 / 渐变工具 | 像素画风本来就**不要**（硬边） |
| 图层 / 蒙版 / 选区 / 复制粘贴 | 一期不做；32×32 上用手点更快 |
| autotile 拼接预览 | 游戏自己的蓝图预览**根本不融合邻居**（§82 定案）⇒ 做了反而不像游戏 |
| effects / ui / rubble / teams 贴图 | 不是"内容贴图" |
| **SAF 目录树授权 + 编辑外部文件 + 外部改动检测** | **本轮**：导入进来再编辑 ⇒ 不需要（I-13） |
| schema 走 Base64 Java 常量 | `CONSTANT_Utf8` 65535 上限，编不过（走 `res/raw/*.deflate`） |

## 七、风险（照实列，不粉饰）

| 风险 | 影响 | 缓解 |
|---|---|---|
| **画布手势**（单指画 / 双指平移缩放抢手势） | **高 —— 体验崩了整块废** | 整数缩放 `1..64` + `pointerCount` 判双指（**不引 `ScaleGestureDetector`**）；**S3 第一件事就是真机手感验证** |
| 原生文本编辑的**体验天花板**（查找替换 / 多光标 / 折叠 都要自己写） | 低~中 | 一期不做（免责层）；先保"能写 + 高亮 + 补全 + 符号键条"。⚠️ **中文输入法与符号键条同屏时的候选栏行为要真机看一眼** |
| 大画布（160×160）重绘 + 撤销内存 | 中 | 只在脏时 `invalidate()`；撤销**按字节**上限 `≤ max(8MB, 画布字节 × 64)`（32×32 = 4 KB/步，160×160 = **100 KB/步**） |
| zip 模组**不能改**（`writable=false`） | 中（体验落差） | ✅ 能看（清单照读）；摘要卡接「（只读）」+ 给出口（复刻/导出） |
| **含 dex 的模组完全不能编辑** | 中 | ✅ 硬拦 + **说清理由**（不是一句"不支持"） |
| 文本可写"暂时不合法"（Q-B） | 中 | 解析不过只警告不阻塞；原子写 + 备份 + 撤销 |
| 与**并行会话**改同一批文件 | 中 | 动手前 `git status` + 读最新文件（本仓库常有第二个会话） |
| `ModIdeText` 码表 ↔ 资源**漂移** | 中 | 门禁 IDE-04 双向对账 |
| 尺寸/颜色静默错（游戏**不校验**） | 中 | 只能我们自己校验（`size:2` 配 32×32 照收不报错；无贴图兜底 = `error` 张 **48×48 花图**） |
| 中文界面的"解释质量" | 中 | 🔴 那 1386 条英文 `doc` 在中文界面**一条都用不上** ⇒ 中文说明表**按频率慢慢补**（先 `mod-meta` 18 键 + 最常改的几十字段）；`stat.*` 98 条里能白拿的 **59 条**先白拿 |

**造夹具的坑**（都会造成假阴性）：`Compress-Archive` 在 Windows 写**反斜杠条目名** ⇒ 用 `ZipArchive.CreateEntry("content/items/x.json")`
手写正斜杠 · `adb push <文件> <远端目录>/` 会把远端文件名**截断**（实测成 `mdtd`，内容对名字错）⇒ 推完 `test -f` 复核 ·
pwsh 里 `java -Dfile.encoding=UTF-8` 必须**加引号**、javac 报错是 **GBK**（`iconv` 重读）· 原版图名是 `item-copper.png`（先 `ls` 再写代码）。
