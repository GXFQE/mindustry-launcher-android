## 1. 导航与入口（**精确到点哪里**）

```
主页 →「存档与备份」→ 槽列表 → 点槽 → SlotActivity →「模组」→ ModsActivity
                                                              └ 点某个模组 ⇒ showDetail(弹窗)
                                                                   └ ★ 新增一行：「打开工程…」
                                                                        ⇒ ModIdeActivity（工程视图）
```

| 项 | 定案 | 依据 |
|---|---|---|
| 入口落点 | **模组详情弹窗里加一行**（`ModsActivity.showDetail` 那个弹窗） | §115 定案手法：**零宽零高**，不碰列表行宽度预算；不改常用动作的层数 |
| 传参 | 只传 **`slot` + 模组定位**（`fileName` + `directory` 布尔）；目标页用 `Mods.scan` 找回 `Info` | §109：跨页只传定位信息，**派生量本页重算** |
| 四个视图 | **各是一个 Activity** | 与既有导航一致（槽页→二级页）；避免自造 tab 框架；每个 Activity 自己 `load()` |
| 返回 | 子视图返回到**上一页**（不串成一条长链） | 减少"退不出来"的路径 |

### 1.1 Activity 清单（4 个，都要交"工程税"）

| Activity | 角色 | 一期 |
|---|---|---|
| `ModIdeActivity` | **工程视图**（首页：元数据 / 内容清单 / 贴图清单 / 问题列表） | ✅ |
| `ModSpriteActivity` | **贴图视图**（像素画板） | ✅ |
| `ModTextActivity` | **文本视图**（先只读：高亮 / 悬浮 / 诊断） | ⏳ 二期 |
| `ModPreviewActivity` | **预览视图**（复用 §80 像素渲染） | ⏳ 二期 |

★ **每个新 Activity 的五件套**（漏一条 = "编译过、自检绿、真机不对"）：
① `AndroidManifest.xml` 注册；② `SelfTest.PAGES`；③ ㉛ 骨架名单；④ 根节点 `@+id/root` + `Util.applySystemInsets(root)`；
⑤ 文案走 `Trans` + `values/` 与 `values-zh/` **两边都加** + `SRC-02` 台账新行。

## 2. 工作台 `ModIdeActivity`（一期核心）—— **两个标签：文件 / 概览**

> 🔴 **结构增补（用户 2026-10-08）**：工程首页**不是**"内容+贴图清单"，而是
> **文件视图（文件管理器）** —— 因为语义清单只覆盖我们建模过的文件，
> 而 `bundles/` `scripts/` `sprites-override/` `patches/` 音效音乐这些**照样要能看、能改、能建**。
> ⇒ 一个 Activity、**顶部两个标签**：**［文件］**（默认）/ **［概览］**（语义清单 + 问题）。

### 2.0 标签「文件」= 文件视图（**首页**）

```
┌ 顶行：工程名 ｜ ［文件］［概览］ ｜ ⋯（改名/删除/安装到槽）    ≤ 30 字
├ 面包屑：hub/projects/<名> / content / items            ← 可点每一段回退
├ 开关行：［全部文件］［显示隐藏］                         ← 两个 toggle
└ 列表（当前一层）：
     📁 blocks                          文件夹
     📄 铜.json   1.2 KB   内容 JSON     ← 徽标：内容 JSON / 贴图 / bundle / 脚本 / 未识别
     📄 说明.txt  0.4 KB   未识别
```

| 交互 | 行为 |
|---|---|
| 点目录 | 进目录（面包屑加一段） |
| 点文件 | **按扩展名分派**：`.json`/`.hjson` → 文本视图；`.png` → 贴图视图；其余 → 只读文本（或"没有能打开的编辑器"） |
| 长按条目 | 动作表：**改名 / 复制 / 删除 / 导出**（删除 ⇒ 中转站，先问） |
| 顶行 ⋯ | 新建文件夹 / 新建文件（**从模板**：内容 JSON / `mod.hjson` / `bundle.properties` / 空文本）/ 安装到槽… |
| 「全部文件」 | 切成**平铺 + 搜索**（找文件时比一层层点快） |
| 改名之后 | **立刻重算问题列表**（§109 口径：本页重算）—— 改 `content/blocks/x.json` 的瞬间就会看到 C1 报"贴图失配" |

★ 空态：目录为空 ⇒ 一行「这个文件夹是空的」+ **不给空框**（本工程纪律）；
★ 未识别的文件**照样列出**（IDE 要"诚实"：我们没建模的东西也得看得见）。

### 2.1 标签「概览」= 语义视图（内容清单 / 贴图清单 / 问题）

### 2.2 摘要卡的"结论行"（**只有一句，且必须是能算 false 的判据**）

| 情况 | 结论行（zh） |
|---|---|
| 有 ERROR | `有 N 处需要修` |
| 只有 WARN | `有 N 处提醒` |
| 都无 | `没发现问题` |
| `!writable` | 在前一句后面接 `（只读）` |

★ 依据 §85.16.1：**界面上任何"结论"都必须有能算出 false 的判据**；不写 `pass = true` 那种常量。

### 2.3 交互

| 点哪里 | 发生什么 |
|---|---|
| 内容行 | 弹层（复用两层弹窗纪律）：第一层 = 这条内容的结论（缺图 / 尺寸不符 / 正常）；第二层「技术细节」= `type` / `size` / 期望注册名 / 实际贴图 / 原始 JSON |
| 贴图行 | 进 `ModSpriteActivity`（带上 `region`）⇒ **直接打开这张贴图** |
| 「看贴图…」 | 进 `ModSpriteActivity`（不带 region）⇒ 显示贴图列表供挑 |
| 问题行 | 跳到对应的内容行 / 贴图行（**滚动 + 高亮**，不弹窗） |

★ 内容行**不新开页面**（一期只读，弹层够）；避免"点一下跳一层"的深链。

## 3. 贴图视图 `ModSpriteActivity`（像素画板）

### 3.1 布局（**画布是主角：工具条不许盖住它**）

```
┌ 顶行：目标（模组名 · 贴图名）｜尺寸 WxH｜[保存] ──────────  ≤ 40 字
├ 画布：PixelCanvasView（占满剩余高度）────────────────────
└ 工具条（固定 2 行，可折叠）：
   行1：铅笔 · 橡皮 · 填充 · 取色 ｜ 撤销 · 重做
   行2：当前色 ▨ · 上一个色 ▨ · 色板（弹出） · 网格开关 · 适应屏幕
```

| 项 | 定案 | 理由 |
|---|---|---|
| 画布载体 | **`PixelCanvasView extends View`** + `onDraw` + `invalidate()`（**不用** `SurfaceView`） | 画布 ≤160×160，`View` 更简单且不吃 Surface 生命周期；开源那个用 SurfaceView 只是它的选择 |
| 缩放 | **整数倍 `1..64`**，默认 = "适应屏幕"（算出来的最大整数倍） | 像素画必须整数倍（避免分数缩放糊）；开源那个也是 `1..64` |
| 平移 | 整数像素偏移 `offX/offY`（**不引入 `Matrix`**） | 整数缩放 + 整数偏移就够，少一层抽象 |
| **手势** | **单指 = 用当前工具画**；**双指 = 平移/缩放**（判 `event.getPointerCount()`） | 像素画要密集落笔；切模式很打断。**不引 `ScaleGestureDetector`**（开源那个也没用） |
| 重绘 | 只在"画布脏了"时 `invalidate()`；工具条状态变化只改按钮态 | 避免整屏重绘 |
| 网格 | 可开关；**≥8 倍**时才画（低倍画了反而糊） | —— |
| 棋盘底 | 常开（透明/白必须分得清） | 实测原版物品 ~50% 是透明的 |

### 3.2 工具集（一期 = 6 个 + 2 个动作）

| 工具 | 行为 | 实现 |
|---|---|---|
| **铅笔** | 单像素；拖动连续；**只在颜色真的变化时写** | `PointBuffer`（逐点） |
| **橡皮** | 擦成**透明**（`PorterDuff.CLEAR` 或直接写 0） | `PointBuffer` 的 variant |
| **填充** | 洪水填充，**4 连通**、**精确匹配**（不做容差） | **扫描线版**（⚠️ **不抄** Pixelesque 的 `Queue<Point>+HashSet<Point>`） |
| **取色** | 把点到的像素色设为当前色（**不改画布**） | 不产生 buffer |
| 撤销 / 重做 | 快照池 | `ToolBufferPool` 风格；**上限按字节**：`≤ max(8MB, 画布字节 × 64)` |
| 色板（弹出） | 16 格预设 + **最近用色** + hex 输入 | 一期**不做 HSV 色轮**（手机上不好用；开源那个也用了第三方色轮） |

★ **每个工具 = 一个"操作类"**（策略模式）：`update()`（拖动预览）/ `commit()`（落盘 + 压历史）/ `cancel()`。
依据：Pixelesque 的 `Shape.update/commit/cancel` + ansdoship 的 `editor/buffer/*`。

### 3.3 保存

```
[保存] → ModWriter.writePng(目标, bmp, overwrite=false)
        ├ OK            → Toast「已保存」+ 返回工程视图（问题列表已经变了）
        ├ NEED_CONFIRM  → 弹「同名贴图已存在」：覆盖（旧的进中转站）/ 换名 / 取消
        │                  选"覆盖" ⇒ 用 overwrite=true **重调一次**
        ├ BUSY          → 「游戏正在运行，先关掉它」
        └ IO / VERIFY   → 走 Util.ioReason 翻白话；**原文进 Log**
```

### 3.4 起稿来源（一期两种，都**不依赖模组编辑器**）

| 来源 | 流程 |
|---|---|
| **从现有贴图** | `ModProject.sprites()` 列出来 → 点一张 ⇒ `ModSprites.bytes(hit)` → `BitmapFactory` → 画布尺寸 = 该 PNG 的 `WxH` |
| **新建空白** | 用户选尺寸：`32 / 64 / 96 / 128 / 160`（= 1~5 格）⇒ 全透明画布 |

★ 一期**不做**"新建内容"（那要写 JSON ⇒ 属于文本视图 / 模组编辑器那条线）。

## 7. 实施顺序 + 每步验收判据（DoD）

| 步 | 交付 | DoD（**不满足就不算完**） | 碰用户数据 |
|---|---|---|---|
| **S1** | `ModProject` + `ModWriter` + `ModIdeText` + 门禁 `tools/ide-check.py` + 自检 1~16 里能做的 | 自检全绿；PC 上能单独编译这两个类；门禁的元断言（#13）**当场判死** | ❌ 只读 |
| **S2** | `ModIdeActivity`（工程视图） | 真机打开一个**真模组**：内容/贴图/问题三节都对；空态成对 `GONE`；截图核对**没有悬空分割线**；返回不串链 | ❌ 只读 |
| **S3** | `ModSpriteActivity`：从现有贴图起稿 + 6 工具 + 撤销 + 保存 | 真机改一张真贴图 ⇒ **一键启动游戏看见变化**；覆盖路径旧的进中转站；转屏不丢画布 | ✅ 写 |
| **S4** | `ModTextActivity`（只读文本 + 高亮） | 打开 `mod.hjson` 与 `content/blocks/x.json` 都正确渲染；大文件不卡 | ❌ |
| **S5** | 文本可写（无损 AST） | 改一个值 ⇒ 注释/未知字段/重复键**全在**；写坏能自动还原 | ✅ |
| **S6** | `ModPreviewActivity` | 本模组贴图铺出来的预览与游戏里一致（拿游戏当对照） | ❌ |

★ **S1/S2 零写入**却独立可用（"这个模组有什么、哪里不对"）；
★ **S3 是唯一"全新且无先例"的部分**，所以它排在最前面几刀里 —— **越早把不确定性打掉越好**。

---

## 8. 明确不做（一期）

| 不做 | 理由 |
|---|---|
| 同屏分栏（文本 + 画布） | 手机竖屏上"看清 JSON"与"画准像素"互相打架 |
| 新建内容（写 JSON） | 属于文本视图那条线；一期画板只做"起稿 + 存回" |
| HSV 色轮 | 手机上不如"色板 + hex"；一期给 16 格 + 最近用色 + hex |
| 直线 / 矩形 / 椭圆 / 选区 / 图层 | 都是**加法**（每个工具一个类），二期加不改架构 |
| "一键修"（自动改名 / 自动缩放） | 自动改用户文件的风险远大于收益 |
| 孤图判据（C3） | 后缀开放式，必然误报 ⇒ 噪声淹掉真问题（详见 1/2 的 §4） |
| 帧动画 / 单位零件拼装 | 原版 units 的 `-N.png` 帧后缀实测为 **0** |

## 9. 风险（**照实列，不粉饰**）

| 风险 | 影响 | 缓解 |
|---|---|---|
| **画布手势**（单指画 / 双指平移缩放抢手势） | 高（体验崩了整块废） | 整数缩放 + `pointerCount` 判双指；**S3 第一件事就是真机手感验证** |
| 大画布（160×160）**重绘 + 撤销内存** | 中 | 只在脏时 `invalidate`；撤销**按字节**设上限（1/2 §3.2） |
| zip 模组**不能改**（`writable=false`） | 中（体验落差） | ✅ **能看**（两种形态都不解包，清单照读，见 1/2 §3.2）；摘要卡接 `（只读）`，并对可做的事给出口（导出） |
| 与**并行会话**改同一批文件 | 中 | 动手前先 `git status` + 读最新文件（本仓库常有第二个会话） |
| `ModIdeText` 的码表与资源**漂移** | 中 | 门禁 `IDE-04` 双向对账 |
