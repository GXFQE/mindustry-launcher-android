## 附录 B：全阶段都要守的"向上兼容"纪律（Android 版）

对齐桌面版的第一约束，Android 侧的落点：

| 约束 | Android 落点 |
|---|---|
| 老用户换新版本**必须不报错、不丢数据、不用手动清** | `Config.load` 加新键要有默认值；未知键原样保留；**绝不判"配置损坏"去重建** |
| 用户数据**只增不毁** | 槽/备份/`.msav` 删除前列清单 + 两次确认（已有）；`settings.bin` 改前备份 + 原子写 |
| 坏值退默认 + **明确日志点名键名** | 沿用桌面版的纪律，别静默 |
| 一次性迁移必须**幂等 + 可回滚** | F0 的槽目录迁移、`Paths.migrateFromLegacy`（已有，照它的写法） |
| 交付前 | 确认 `build/`、`.build-trash/`、`.spike-backup/`、`*.apk` 都被 `.gitignore` 覆盖 |
| 🔴 **资源里要留空白** | **`aapt2` 会剥掉 string 资源两端的空白** —— **前导**（早已实测）**与尾随**（2026-10-04 真机抓到现行：`已导入 · ` ⇒ 渲染成 `已导入 ·imported`）。⇒ **不许用"前缀/尾巴串 + 拼接"来留空白**，一律写成**整句资源 + `%1$s`**（`\u0020` 转义仍然可用，但整句写法不会忘、也不用记转义）。**Java 字符串字面量不受影响** ⇒ 两处行为不一致且**毫无症状**。⇒ 判据见自检 **㉞**（每个 `·` 两侧必须是空格 + 元断言），详见 REF **§43 / §65.4** |
| 🔴 **描述 `\uXXXX` 本身** | **Java 的 Unicode 转义发生在【词法分析之前】** ⇒ 在 Java 注释/字符串里写 `\u0020` 会**被编译成真空格**（注释自己变形）⇒ 要写 `U+0020` 这种拆字形式 |
| ★ **同一条显示规则只留一处实现** | 又栽一次：选槽对话框的 `slot_entry_suffix_fmt` 与存档页的 `slot_entry_fmt` 只差前导空格 ⇒ **两处实现改一边另一边静默不跟**。合并成一条 + 删掉 `Data.Slot.title()/subtitle()`（**全工程 0 调用者**）。口径见 §35.11/§35.12 |
