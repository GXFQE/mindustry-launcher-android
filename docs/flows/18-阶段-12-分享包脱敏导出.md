## F25.6 第二轮（第 143 轮，2026-10-13）：再丢日志与可重建的缓存 + 两处文案

用户四句话落地：**分享包**从丢「一个文件」变成丢**五类**
（`SharePack.DROP_TOPS = { server_list.json, crashes, last_log.txt, previews, assetCache }`）——
前三个是「会指向你的」（服务器列表 + 故障证据），后两个是「可重建的缓存」（收包方那边游戏会重建）。

* **只认根级**：命中 = 名字相等 **或** 以 `名字/` 开头（不是 `contains`/`endsWith`）⇒
  `mods/x/crashes/`、`previews.bak`、`maps/crashes.msav` 一律不动。
* **目录也问一次钩子**（`Exporter.addTree` 的目录分支）⇒ 空目录不漏、整棵子树剪掉。
* **本地备份一个字不动**：`crashes/` + `last_log.txt` 在 `Data.SLOT_EXCLUDE` 里是有意保留的。
* **真机**：普通包 56 条 / 262083 B → 分享包 16 条 / 57469 B（**体积 22%**），
  只在普通包里的 40 条正好是那五类，共有条目 **0 处字节差异**。
* **整槽导出（原件）**的确认框加泄露提示（写进 `export_slot_msg_fmt` 的格式串，不动调用点）。
* **分享包提示里「服务器列表」只说一遍**（删掉重复的条件句与它那条资源 —— 该 key 还没随正式版发出过）。
* ⚠️ 真槽里 `maps/saves/mods/schematics/assetCache` 两包都 0 条 = **空壳不算内容**（不是 bug）。

## F25.7 第三轮（第 144 轮，2026-10-13）：「尽可能小」+ 修一个真泄露

用户：「**分享包主要是想着尽可能小（毕竟大概需要网络传输）**」。

## F25.8 第四轮（第 145 轮，2026-10-13）：定位与文案长度

用户：「**换机为什么要用分享包，原样导出更好用啊**」＋「**尽量不要大段文本**」。

* **定位错位**：界面里「整槽导入导出」那行的副标题本来就写着「换机迁移用（zip）」，
  而分享包确认框却说「这是给换机或分享用的包」⇒ **抢了另一个出口的用途**。
  换机要的是「一个字不删」（设置的历史备份/预览/资产缓存对恢复都有用）⇒
  新首句把换机的人**指回**「导出整槽」。
* **字数预算**：分享包确认框 ~230 字/11 行 → **72 字/3 行**（≤100）、整槽导出 → **97 字**（≤105）。
* **两条新断言**：定位（不许「给换机」、必须指向「导出整槽」）＋ 字数预算。
* ★ 老断言跟着口径改：`countOf(shareMsg, "服务器列表") == 1` → 量「身份信息」
  （那串品类清单收文时并被了，量到 0 次当场红）—— **跟着口径改，不是改松**。

## F25.5 坑（都是本轮真踩/真定下来的）

1. 🔴 **"已脱敏"是承诺** ⇒ `settings.bin` 读不出来就**拒绝导出**（界面不启动 SAF、dev 口不打包），
   别做"原样塞进去 + 小字提示"。
2. 🔴 **逐条目钩子的参数必须是相对路径**（`rel`）而不是 `File` —— 给 `File` 会被写成
   `getName().equals(…)` = **任意深度都命中**（会改到模组目录里的同名文件）。
3. **别为分享包另写一份目录遍历**：整槽导出那条路上有三处口径（打什么 / 跳过什么 / 条目名怎么拼）。
4. `Values` 的**删除也要保序** —— 否则"本来没有敏感键 ⇒ 字节差 0"这条元断言立不住。
5. 弹窗新项**加在最后**：老两项的下标（0/1）一个都不动，任何"按下标点第几项"的老断言不受影响。
6. 分享包**仍然能被游戏导入**（根上有 `settings.bin` 是游戏 `importData` 的硬要求）。
