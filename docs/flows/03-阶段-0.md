## 阶段 0

### F1 —— 接上 `res/`（资源系统落地）★ 所有美化的地基

> ✅ **已完成（2026-10-01）**：`build.sh` 已接上资源链，`strings/colors/themes` + `values-night/` 全部落地，
> 三个页面的文案已迁完。产物基线 **57747 → 74131 B**。
> ★ **实测修正了两处原文**（照本文原样做会踩）：① `aapt2 compile --dir` **不吃非 ASCII 目录**（硬失败）；
> ② theme **只能挂自有 Activity，不能挂 `application`**（游戏会被套上 ActionBar）。
> 完整证据与配方见 `REFERENCE-android-adaptation.md` **§20**。
> 本节保留原始规划 + 修正，作为"再加资源类型（layout/drawable）"时的参照。

**目标**：能用 `R.string.*` / `R.layout.*` / `R.drawable.*` / `res/values-night/`；界面从代码手搓迁到 XML。

**前置**：无。

**改动面**

| 文件 | 做什么 |
|---|---|
| `build.sh` | ★ **核心改动**：`aapt2 link` **之前**插一步 `aapt2 compile --dir <res 的 ASCII 镜像> -o <tmp>/res.zip`（★ 工程路径含中文时**必须**先 `cp -r` 到 `/tmp`，见坑①）；<br>link 命令追加该 zip（**位置参数**）、`--java build/gen`（生成 `R.java`）；<br>javac 的源文件列表里加上 `build/gen/**/R.java`（★ 收集动作要放在 **link 之后**） |
| `app/res/values/strings.xml` | 新建，把 `MainActivity`/`SavesActivity`/`GameSlot` 里**所有硬编码中文**搬进来 |
| `app/res/values/colors.xml`、`themes.xml`、`app/res/values-night/themes.xml` | 新建，定义主题与深色主题 |
| `app/AndroidManifest.xml` | ★ **theme 挂在三个自有 Activity 上**（`MainActivity`/`SavesActivity`/`GameSlot`），**不要挂 `application`**（见坑③）；`android:label="@string/app_name"` |
| `app/res/layout/*.xml`、`app/res/drawable/*.xml` | 列表行、圆角/卡片、`<shape>` |

**步骤**

1. **先只做一件事**：建 `app/res/values/strings.xml` 放一个 `app_name`，改 `build.sh` 让它编过。
   跑 `./build.sh`，确认产物**尺寸变大**（res 进去了）且 APK 能装、能启动。
   —— 这一步单独验证，**别和后面的迁移混在一起**，否则出错时分不清是 build.sh 还是资源写错。
2. `aapt2 compile` 的坑**有三个**：**输入必须是目录**（`--dir`），输出是 **`.zip`**（不是目录）；
   link 时把那个 zip 当**位置参数**传，不要用 `-R`（`-R` 是 overlay 语义，不是"资源目录"）；
   ★ **非 ASCII 目录直接打不开**（见坑①，必须镜像到 ASCII 路径）。
3. `--java <dir>` 生成 `io.mdt.launcher.R`。javac 需要它 ⇒ 把 `build/gen` 下的 `.java` 加进 `SRC` 数组，
   ★ 且**收集动作必须在 link 之后**（`R.java` 是 link 生出来的，收早了捡不到 ⇒ `cannot find symbol: class R`）。
4. `aapt2 link` 显式补 `--min-sdk-version 26 --target-sdk-version 36`（与清单 `uses-sdk` 保持一致）。
5. 迁移文案：先 `strings.xml`（纯机械），再逐个页面把 `setText("中文")` 换成 `setText(R.string.xxx)`。
   每迁完一个页面就 `./build.sh install` 跑一次。
   - **迁**：`setText` / `setTitle` / `setMessage` / `setButton` / `setHint` / `Toast` / `ProgressDialog` / `android:label`。
   - **不迁**：写 `hub/report-*.txt` 的取证文本；`Data.Slot.title()/subtitle()` 这类**无 Context 的数据层显示串**
     （留给 F2 重写槽显示时一并处理，避免同一份文案迁两遍）。
6. 最后加主题：`themes.xml` 里继承 `android:Theme.Material.Light`（framework 自带，**不需要 Material Components**），
   `values-night/` 里继承 `Theme.Material`（深色）。colors 用语义名（`bg`/`fg`/`accent`），
   这样深色模式只换 `values-night/colors.xml` 一份。
   ★ **挂到三个自有 Activity 上，不要挂 `application`**（见坑③）。
   刻意不设 `colorPrimary`/`statusBarColor`：浅色下与接入前逐像素一致，观感改动留给 F2/F3。

**验收**
- `./build.sh install` 后 APK 能启动，界面文字与迁移前**逐字相同**（对照截图）。
- 系统切深色模式后界面跟着变（`values-night` 生效）。
  ★ **adb 驱动方式看 ROM**：`cmd uimode night yes|no` 在这台测试机的 ROM 上**无效**（实测两种设置下背景都是 `#121212`），
  要用 **`settings put secure ui_night_mode 1|2`**；判据取背景像素（夜 `#121212` / 昼 `#FFFFFF`），别靠肉眼。
- **`ls -la mdt-launcher.apk` 记下新尺寸**，作为后续构建的对照基线。
- ★ **游戏侧必须回归一次**：`dev_launch_key io.anuke.mindustry` 启动官方包，
  确认全屏无多余 ActionBar（这是 theme 挂错位置的唯一显性症状）。
- **已实测结果（2026-10-01）**：57747 → **74131 B**；`sources: 16`；
  `dev_m3_selftest` **36 项全过**；主界面/存档页/带参弹窗逐字一致；
  深色切换正常且浅色与改动前逐像素相同；游戏 159.7 全屏正常。

**坑**
- ⚠️ 一开始就把所有页面一起迁 ⇒ 出错范围不可控。**一个步骤一次构建**。
- ⚠️ `aapt2 compile` 也需要**原生 Windows 路径**（`wpath`），和 link 一样；用 `jpath` 会静默不产出。
- ⚠️ 加 `res/` 后 `R.java` 的包名由清单 `package=` 决定 ⇒ `io.mdt.launcher.R`，别 import 错。
- ⚠️ **坑① `aapt2 compile --dir` 不吃非 ASCII 目录**：报 `failed to open directory: 系统找不到指定的文件 (2)`，
  目录明明存在。**8.3 短路径救不了**（示例里那两层中文目录名没有短名）。
  ⇒ res 先 `cp -r` 到 `/tmp/<名字>`（与 manifest/assets 同一套镜像思路）。
- ⚠️ **坑② XML 资源注释里不能有连续两个减号**：注释写 `--java` ⇒
  `xml parser error: not well-formed (invalid token)`，**行号显示 0**（别去数行）。
- ⚠️ **坑③ theme 不能挂 `application`**：官方 theme（`@style/ArcTheme`）挂在 application 上，
  游戏 `AndroidLauncher` 自己没声明 theme ⇒ **继承 application 的**。我们把 `AppTheme` 挂到 application
  会给游戏套上 `Material.Light`（多出 ActionBar）；而照抄 `ArcTheme` 又**编不过**（资源在官方包里）。
  ⇒ 只挂自有 Activity。
