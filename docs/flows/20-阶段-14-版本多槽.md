# 阶段 14：F4③ 一个版本绑多个槽（多存档，不复制 APK）

> **需求原文（2026-10-24）**：「能不能搞克隆游戏版本（就是同一个版本有可能有玩家需要两个不同存档，
> 每次启动换槽很麻烦，但是复制一份又占地方）」
>
> **结论**：不复制 APK、不复制存档 —— 只让一个版本**多绑几个槽**，每绑一个槽 = 列表里多一行启动项。
> 两行点下去是同一个游戏包（同一份 dex / 资产），但存档 / 设置 / 模组各在自己的槽里。
>
> 与 F4②「克隆此槽」不是一件事：那个复制的是**一个槽的数据**；这里复制的是**入口**，数据一个字节不复制。

---

## 20.1 心智模型

```
         （一份 APK，0 额外空间）
      ┌─────────────┴─────────────┐
 Mindustry 159.7  [default]   Mindustry 159.7  [存档B]
      │ 主行（version_slots）        │ 附加行（version_extra_slots）
      └────────→ slot-default      └──────→ slot-存档B
```

- 列表行 = **一个 (版本, 槽) 绑定**。摘要卡那句「N 个版本」按**版本数**算，不按行数
  （`Versions.distinctVersions`）—— 否则一个版本绑两个槽会报成"2 个版本"。
- 行的区分靠**槽徽标**（已有的 chip）。槽名可以改（存档页 → 重命名），所以"给它起个名"不需要新功能。
- 点哪一行 = 用哪个槽启动。这一句的实现从头到尾只有一处：`Versions.slotFor`。

## 20.2 数据形状（为什么另起一个键）

| 键 | 形状 | 谁写 |
|---|---|---|
| `version_slots`（原有） | `{ "<版本key>": "<槽名>" }` | 主行换槽 / 删槽回落 |
| `version_extra_slots`（新） | `{ "<版本key>": ["<槽名>", ...] }` | 「再加一个槽…」/ 换附加行 / 移除这一行 |

**为什么不把 `version_slots` 的值改成数组**：老版本启动器用 `optString` 读它，数组会被读成
`["x"]` 这种**非法槽名** ⇒ 注入不了数据根 ⇒ 存档"看起来没了"。新键对老版本是**未知键**
（`Config` 原样保留、不解析）⇒ 降级安全。⚠️ 两个存储位都在 `Config` 里收口（`extraSlotsOf` /
`addExtraSlot` / `removeExtraSlot` / `replaceSlotBinding` / `retargetSlots` / `clearBindings`），
别在别处直接碰键名。

## 20.3 判据只许有一处

| 问题 | 唯一实现 | 谁在用 |
|---|---|---|
| 这一行用哪个槽 | `Versions.slotFor` | 列表徽标 / 启动 / 模组页版本要求 / 详情 / 冲突分组 |
| 这一行是不是显式指定过槽 | `Versions.explicitSlot` | 冲突"拦不拦"（全隐式只提示） |
| **行身份** | `Versions.rowKey` = `(版本 key, 槽)` | 同槽冲突表 `mConflict`（见 20.5 ③） |
| 这个版本还绑了哪些槽 | `Config.extraSlotsOf` | 展开 / 加槽去重 / 换槽拒绝 |
| 这个版本绑没绑这个槽 | `Config.hasSlotBinding`（**版本级**：实际主槽 + 全部附加绑定） | 加槽列表过滤 / 换槽拒绝 |
| 有几个版本 | `Versions.distinctVersions` | 摘要卡 |
| 行怎么展开 | `Versions.expandBindings` | `scanAll`（模组页 / 插件清单 / 存档计数全走它） |

`expandBindings` 抽了 `ExtraLookup` 接口，只为让自检能喂假查表 —— 否则"展开"只能靠真实
config + 真机已装包才测得了。

## 20.4 界面流程

```
版本行 ─「管理」按钮（或长按那一行）─→ 版本页（VersionActivity）
                                        ├─ 换槽…      只换这一行
                                        ├─ 克隆…      用另一个槽再加一项（已绑的不出现 + [新建一个槽…]）
                                        ├─ 详情…      只读（来源 / 校验 / ABI）
                                        ├─ 命名…      版本显示名（已装版也允许）
                                        ├─ 资源…      导出游戏包资源
                                        └─ 删除…      还有别的行 ⇒ 只删这一行；最后一行 ⇒ 删整个版本
```

★★ **2026-10-25 用户定案**：不要再在行上弹"槽选择"弹窗了 ——「槽操作和长按后的版本操作有点乱
（应该把页面彻底整理下）」「把槽这个接口改成二级页面，里面可选各种功能（换槽 克隆 资源 删除 详情 命名）」。
⇒ 行上的按钮从「槽」改成「管理」，点它和长按**都进同一个版本页**；换槽从"弹窗里一步"变成
"页面里一步"（用户原话：「现在可以克隆以后应该不会有人需要频繁换槽」）。

删除的语义（同一句话定的）：
- **行就是实例**，主行也能删（删了自动把另一条附加绑定提升成主行，见 `Config.removeBinding`）；
- 还有别的行 ⇒ 只删这一行；这是最后一行 ⇒ 删整个版本；
- **已装版本的最后一行不许删**（那份在系统里，删了就成"删版本"了）⇒ 弹窗说明"要删请到系统里卸载"；
- 槽里的存档 / 设置 / 模组：任何删除都不动。

- **换槽是行级的**：改的是"这一行"的绑定（主行改 `version_slots`，附加行原地改数组）。
  以前那句 `setSlotOf(e.key(), …)` 会永远改到主行 —— 在附加行上点就是"点了没反应"。
  ★ 主行与附加行**写路径不同**：主行可能从来没有显式分配过槽（一直在用默认槽），
  拿 `(key, 旧槽名)` 去 `replaceSlotBinding` 会返回"找不到" ⇒ 界面报"改不动"。
  主行一律 `setSlotOf`，附加行才替换。
- 换到**这个版本已经绑着**的槽 ⇒ 拒绝 + Toast「这个版本已经在用槽「X」了」。
  允许的话会得到两行一模一样的启动项（点哪行都一样），那是骗人的。
  ⚠️ "已经绑着"要算**实际主槽**：没分配过时它是默认槽 —— 只比 `slotOf` 的话，
  "还没分配过 + 新建一个叫 default 的槽"会存进一条**看不见的附加绑定**
  （展开时按"与主槽重复"跳过），而 Toast 还说"已加一行"。
- 移除一行**不删槽、不删存档、不删版本**；加一行**不复制存档**（新槽从空开始；要带存档用「克隆此槽」）。
- ★ **入口只有一条**：行上的「管理」与长按那一行都走 `MainActivity.openVersion`。
  别再给行里塞第二个版本级按钮 —— 这一行的横向宽度一点余量都没有（见 20.7 的布局注）。

## 20.5 坑（真机 / 自检抓到的，别重犯）

**① `setMessage` + `setItems` 并存 ⇒ 列表整块不渲染。**
本机 HONOR / Android 16 实测：对话框只剩正文 + 取消按钮，`uiautomator dump` 里**连 ListView 都没有**。
⇒「再加一个槽」那个列表弹窗**不许放正文**；说明改由 Toast 承载。（这条是 `AlertDialog` 的系统行为，
不是我们的布局问题。）

**② Toast 只有一行。**
文案里带 `\n` 的第二行会被系统截成「…」（真机截图抓到「已加一行：…」后面直接省略号）
⇒ Toast 只放"加了哪一行 / 移除了哪一行"，"不占额外空间"这种解释放文档。

**③ 同槽冲突表必须按行身份存。**
`mConflict` 原来按 `e.key()` 存 —— 同一个版本绑两个槽时，两行可能各自跟不同的版本抢各自的槽，
按 key 存会**互相覆盖**（A 行跟 B 抢槽、C 行跟 D 抢槽 ⇒ 最后只剩一份），
徽标/拦截张冠李戴且不报错。⇒ `Versions.rowKey(e)` = `(key, 槽)`。
真机验收：Mindustry(159.7) 多绑到 MindustryX 的 `test` 槽后，**只有那一条附加行**亮警告，
主行（default）不亮；点附加行启动会弹「这两个版本共用同一个槽」。

**④ 「继续上次」必须按 `currentSlot` 选回那一行。**
`last_version` 只记"哪个版本"（导入版记文件名），同一个 key 有多行时全都会命中第一行 ⇒
从"存档B"那行启动、点「继续上次」会落回主行的槽（界面看着一样、进去是另一套存档）。
`Data.currentSlot()` 就是上次启动写下的槽（唯一写入点是 `Data.prepareSlot`）⇒ 用它消歧。
真机验收：从 m3b 行启动 → 回启动器点「继续上次」→ `mdt-slot.txt` 仍是 `m3b`。

**⑤ 删槽的两种语义要分开说。**
主分配被删 = 「回落到默认槽」（那一行还在）；附加绑定被删 = 「那一行直接消失」
（它存在的理由就是那个槽）。`Config.Retarget` 分开计数，Toast 分开说
（真机：「已把槽「m3b」挪进中转站（1 个只绑了这个槽的启动项已移除）」）。
⚠️ 改名那条**也要计数** —— 第 236 轮自检当场抓到：只在"删槽"分支里 `++`，改名时 extras 恒为 0。

**⑥ 摘要卡计数按版本数。**
`mEntries.size()` 在有多行时会虚报（1 个版本 2 行 ⇒ "2 个版本"）。

**⑦ 删导入版本要连附加绑定一起清。**
`Config.removeImport` → `clearBindings`（否则留一行指向不存在版本的启动项）。

**⑧ 绑定清空后别留空对象。**
第一版真机验收后 `config.json` 里留下 `"version_extra_slots": {}` —— 无害，但会让人以为"这里有东西"。
`Config.storeExtra` 在空时把整个键删掉。

**⑨ "这个版本还绑着哪些槽"只能按**版本**算，不能按行算。**
`Versions` 里曾另写一个 `hasBinding(Entry, slot)` = "这一行的槽 + 附加绑定" —— 在**附加行**上打开
「再加一个槽…」时，**主行**正在用的那个槽照样出现在列表里（因为附加行的 `slotFor` 不是主槽），
点了才被 `Config.addExtraSlot` 拒掉、弹「这个版本已经在用槽「X」了」。
⇒ 删掉那个按行的版本，列表过滤与写入都走 `Config.hasSlotBinding`（版本级：实际主槽 + 全部附加绑定）。
真机复现：`只是一个测试` 的附加行（`测试专用`）打开加槽列表，`预览验收`（= 它的主槽）被列了出来。

## 20.6 验收

**自检** `SelfTest.versionBindings`（30 条，总量 1541 → **1571 / 0**）：
增 / 重加去重 / 换（主行与附加行两条路）/ 目标已占 / old 不存在 / **reload 落盘往返** /
改名与删槽两种语义（含 `Retarget` 两个计数）/ 移除 / 删导入版本清理 / **未分配主槽时默认槽不许重复加** /
**展开**（顺序、字段照抄 = 同一份 APK、与主槽重复的不展开）/ `rowKey` 唯一 /
`explicitSlot` / `distinctVersions`，外加三条元断言（查表为 null、无绑定、两个不同版本）。

**真机清单**（dev 变体，验完装回产品版）：

| 步骤 | 判据 |
|---|---|
| 主行「槽」→「再加一个槽…」→ 新建 `m3b` | 列表出现第二行，徽标 `m3b`；摘要仍是「3 个版本」 |
| 点第二行启动 | `app_hub/mdt-slot.txt` = `m3b`；`slot-m3b/` 里出现游戏写的 `settings.bin` 等 |
| 回启动器点「继续上次」 | 仍是 `m3b`（不是主行的 `default`） |
| 第二行「槽」→「移除这一项」 | 行消失；`slot-m3b/` 42 个文件原样还在；config 里 `version_extra_slots` 整个键消失 |
| 重新加回 `m3b`，再从主行启动一次 | `mdt-slot.txt` = `default`（行级换槽两个方向都通） |
| 存档页删掉 `m3b` | Toast 两句分开；回主页那行已消失；`config.json` 里没有残留 |
| 把 Mindustry 多绑到 MindustryX 的 `test` 槽 | 只有附加行亮「⚠ 与「MindustryX…」共用此槽」；点它启动弹拦截框 |
| 清场 | 测试槽 `m3b` 从「中转站」彻底删除（槽目录确认不存在） |

## 20.8 版本页（2026-10-25，第 237 轮）

| 文件 | 做什么 |
|---|---|
| `VersionActivity.java` | 页面本体。传参只给**定位信息**（`v_key` + `v_slot`），`onResume` 里 `Versions.scanAll` 找回来；找不到就 `finish()`（那一行已经不在了）|
| `VersionOps.java` | 六个动作的**唯一实现**（换槽 / 克隆 / 详情 / 命名 / 资源 / 删除），每个改状态的都收 `Done` 回调 |
| `activity_version.xml` | 身份卡（点开 = 只读详情）+ 六行 `row_action` |
| `Config.removeBinding` | 行级删除：主行被删时把第一条附加绑定提升成主行（提升后必须从附加里摘掉，否则两行一样）|
| `Versions.rowCount` | 删除范围**唯一判据**：1 + 附加绑定数 |
| `Versions.subtitleLine` | 行的紧凑副标题（来源 · 大小 · 存档 N 份）—— 列表行与版本页标题卡共用 |

★ 页面副标题**不许**用 `Entry.subtitle()`：它带整条 `/data/app/~~…/base.apk` 路径，真机上占三行
（2026-10-25 第一版就这么印出来了）。紧凑那份在 `Versions.subtitleLine`。

★ 已装版的「删除…」仍然显示（不隐藏），副标题写「已装版本至少留一项，不能删」，点下去弹说明。
理由：藏起来用户会问"为什么这个版本没有删除"，而那正是本轮要消灭的那种"两套按钮"。

**仍未做（下一步）**：导入版本删掉最后一行时，**本体进中转站**（可放回）—— 现在还是直接删副本
（原文件不受影响）。落地设计见 `docs/plans/2026-10-24-版本页与删除模型.md`。
