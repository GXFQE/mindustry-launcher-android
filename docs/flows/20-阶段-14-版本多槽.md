# 阶段 14：F4③ 一个版本绑多个槽（多存档，不复制 APK）

> **需求原文（2026-10-24）**：「能不能搞克隆游戏版本（就是同一个版本有可能有玩家需要两个不同存档，
> 每次启动换槽很麻烦，但是复制一份又占地方）」
>
> **结论**：不复制 APK、不复制存档 —— 只让一个版本**多绑几个槽**，每绑一个槽 = 列表里多一行启动项。
> 两行点下去是同一个游戏包（同一份 dex / 资产），但存档 / 设置 / 模组各在自己的槽里。
>
> 与 F4②「克隆此槽」不是一件事：那个复制的是**一个槽的数据**；这里复制的是**入口**，数据一个字节不复制。

---

## 20.1 心智模型

```
         （一份 APK，0 额外空间）
      ┌─────────────┴─────────────┐
 Mindustry 159.7  [default]   Mindustry 159.7  [存档B]
      │ 主行（version_slots）        │ 附加行（version_extra_slots）
      └────────→ slot-default      └──────→ slot-存档B
```

- 列表行 = **一个 (版本, 槽) 绑定**。摘要卡那句「N 个版本」按**版本数**算，不按行数
  （`Versions.distinctVersions`）—— 否则一个版本绑两个槽会报成"2 个版本"。
- 行的区分靠**槽徽标**（已有的 chip）＋**每一项自己的名字**（2026-10-26 起，见 §20.10）；
  槽名也可以改（存档页 → 重命名）。
- 点哪一行 = 用哪个槽启动。这一句的实现从头到尾只有一处：`Versions.slotFor`。

## 20.2 数据形状（为什么另起一个键）

| 键 | 形状 | 谁写 |
|---|---|---|
| `version_slots`（原有） | `{ "<版本key>": "<槽名>" }` | 主行换槽 / 删槽回落 |
| `version_extra_slots`（新） | `{ "<版本key>": ["<槽名>", ...] }` | 「再加一个槽…」/ 换附加行 / 移除这一行 |

**为什么不把 `version_slots` 的值改成数组**：老版本启动器用 `optString` 读它，数组会被读成
`["x"]` 这种**非法槽名** ⇒ 注入不了数据根 ⇒ 存档"看起来没了"。新键对老版本是**未知键**
（`Config` 原样保留、不解析）⇒ 降级安全。⚠️ 两个存储位都在 `Config` 里收口（`extraSlotsOf` /
`addExtraSlot` / `removeExtraSlot` / `replaceSlotBinding` / `retargetSlots` / `clearBindings`），
别在别处直接碰键名。

## 20.3 判据只许有一处

| 问题 | 唯一实现 | 谁在用 |
|---|---|---|
| 这一行用哪个槽 | `Versions.slotFor` | 列表徽标 / 启动 / 模组页版本要求 / 详情 / 冲突分组 |
| 这一行是不是显式指定过槽 | `Versions.explicitSlot` | 冲突"拦不拦"（全隐式只提示） |
| **行身份** | `Versions.rowKey` = `(版本 key, 槽)` | 同槽冲突表 `mConflict`（见 20.5 ③） |
| 这个版本还绑了哪些槽 | `Config.extraSlotsOf` | 展开 / 加槽去重 / 换槽拒绝 |
| 这个版本绑没绑这个槽 | `Config.hasSlotBinding`（**版本级**：实际主槽 + 全部附加绑定） | 加槽列表过滤 / 换槽拒绝 |
| 有几个版本 | `Versions.distinctVersions` | 摘要卡 |
| 行怎么展开 | `Versions.expandBindings` | `scanAll`（模组页 / 插件清单 / 存档计数全走它） |

`expandBindings` 抽了 `ExtraLookup` 接口，只为让自检能喂假查表 —— 否则"展开"只能靠真实
config + 真机已装包才测得了。

## 20.4 界面流程

```
版本行 ─「管理」按钮（或长按那一行）─→ 版本页（VersionActivity）
                                        ├─ 详情…      只读（来源 / 校验 / ABI）
                                        ├─ 换槽…      只换这个启动项（已绑别的槽不出现 + [新建一个槽…]）
                                        ├─ 克隆…      用另一个槽再加一个启动项（同上，也带新建）
                                        ├─ 命名…      这一项自己的显示名（已装版也允许；同版本其他项不受影响）
                                        ├─ 资源…      导出游戏包资源
                                        └─ 删除…      还有别的启动项 ⇒ 只删这一项；
                                                      最后一项 ⇒ 删整个版本（导入版 ⇒ 本体进中转站）
```

★★ **2026-10-25 用户定案**：不要再在行上弹"槽选择"弹窗了 ——「槽操作和长按后的版本操作有点乱
（应该把页面彻底整理下）」「把槽这个接口改成二级页面，里面可选各种功能（换槽 克隆 资源 删除 详情 命名）」。
⇒ 行上的按钮从「槽」改成「管理」，点它和长按**都进同一个版本页**；换槽从"弹窗里一步"变成
"页面里一步"（用户原话：「现在可以克隆以后应该不会有人需要频繁换槽」）。

★ 顺序（第 237b 轮按用户「这个顺序可以考虑重排一下」调整）：**信息 → 动作 → 危险**：
详情 / 换槽 / 克隆 / 命名 / 资源 / 删除。
★ 术语（用户「行又是啥」）：界面上一律叫**启动项**，不再出现"行"；删除的副标题说**结果**
（「只删这个启动项，其他还在」），不写"还有 N 行"那种要用户自己算的句子。

删除的语义：
- **一个启动项就是一个实例**，主项也能删（删了自动把另一条附加绑定提升成主项，见 `Config.removeBinding`）；
- 还有别的启动项 ⇒ 只删这一项；这是最后一项且是**导入**版 ⇒ 删整个版本，
  **APK 副本先进中转站**（`versions-trash/<戳>__<名字>__<文件>/`：`base.apk` + `entry.json` + `state.json`），
  确认框里必须写明"会进中转站、之后能放回来"（用户 2026-10-25：「这个删除时要给个提示」）；
- 这是最后一项且是**已装**版 ⇒ **不许删**（那份在系统里）⇒ 弹窗说明"要删请到系统里卸载"；
- 槽里的存档 / 设置 / 模组：任何删除都不动。

★ **中转站 → 放回去**（`Importer.restoreVersion`）：副本回 `app_hub/import/`，登记重加，
名字与槽绑定一起恢复（槽已经不存在的绑定跳过）。列表里它显示成「游戏版本」而不是「其他文件」。

★ **中转站可以按类型筛选**（2026-10-25 用户：「能不能给中转站加一个分类」）：
动作卡第二行「按类型筛选」（`row_trash_filter`，副标题 = 当前分类 · 份数），点开是单选弹窗，
只列**真有东西**的那几类（顺序 `TrashText.filterOrder()`：存档 / 地图 / 蓝图 / 模组 / 整个槽 /
游戏版本 / 卸载的插件 / 其他文件）+ 全部。分类**只改显示**（`mAll` 是底稿、`mItems` 是筛过的），
表头的份数与体积跟着筛出来的算。
⚠️ 「清空中转站」**永远清整个站**，所以确认框的份数必须取 `mAll` 而不是 `mItems` ——
否则筛到 2 份时对话框会说"删 2 份"、实际删 10 份（这一版就是这么写的，真机对着 dump 抓出来的）。
★ **保留份数按「整个槽」算**（2026-10-25 用户：「游戏本体保留个数按照整个槽算」）：
`Trash.keepFor(VERSION)` 走 `keepSlots()`（默认 3，设置页那一项的标题已改成「整个槽 / 游戏版本」）；
`Importer.trashVersion` 里**真的会 prune** —— 以前漏了这一步，站里的旧版本会无限堆积（每个几十 MB）。

- **换槽是行级的**：改的是"这一行"的绑定（主行改 `version_slots`，附加行原地改数组）。
  以前那句 `setSlotOf(e.key(), …)` 会永远改到主行 —— 在附加行上点就是"点了没反应"。
  ★ 主行与附加行**写路径不同**：主行可能从来没有显式分配过槽（一直在用默认槽），
  拿 `(key, 旧槽名)` 去 `replaceSlotBinding` 会返回"找不到" ⇒ 界面报"改不动"。
  主行一律 `setSlotOf`，附加行才替换。
- 换到**这个版本已经绑着**的槽 ⇒ 拒绝 + Toast「这个版本已经在用槽「X」了」。
  ★ 2026-10-25 用户：「不能光在创建时拦截啊，切换页面也要删掉已有」⇒ **列表里根本不再出现**
  这个版本绑过的槽（`slotList` 用 `Config.hasSlotBinding` 过滤；换槽时只保留**当前这一项**的槽并标 [当前]）。
  拒绝那条 Toast 仍然留着 —— 它是"两个入口同时改到同一个槽"时的兜底。
  允许的话会得到两行一模一样的启动项（点哪行都一样），那是骗人的。
  ⚠️ "已经绑着"要算**实际主槽**：没分配过时它是默认槽 —— 只比 `slotOf` 的话，
  "还没分配过 + 新建一个叫 default 的槽"会存进一条**看不见的附加绑定**
  （展开时按"与主槽重复"跳过），而 Toast 还说"已加一行"。
- 移除一行**不删槽、不删存档、不删版本**；加一行**不复制存档**（新槽从空开始；要带存档用「克隆此槽」）。
- ★ **入口只有一条**：行上的「管理」与长按那一行都走 `MainActivity.openVersion`。
  别再给行里塞第二个版本级按钮 —— 这一行的横向宽度一点余量都没有（见 20.7 的布局注）。

## 20.5 坑（真机 / 自检抓到的，别重犯）

**① `setMessage` + `setItems` 并存 ⇒ 列表整块不渲染。**
本机 HONOR / Android 16 实测：对话框只剩正文 + 取消按钮，`uiautomator dump` 里**连 ListView 都没有**。
⇒「再加一个槽」那个列表弹窗**不许放正文**；说明改由 Toast 承载。（这条是 `AlertDialog` 的系统行为，
不是我们的布局问题。）

**② Toast 只有一行。**
文案里带 `\n` 的第二行会被系统截成「…」（真机截图抓到「已加一行：…」后面直接省略号）
⇒ Toast 只放"加了哪一行 / 移除了哪一行"，"不占额外空间"这种解释放文档。

**③ 同槽冲突表必须按行身份存。**
`mConflict` 原来按 `e.key()` 存 —— 同一个版本绑两个槽时，两行可能各自跟不同的版本抢各自的槽，
按 key 存会**互相覆盖**（A 行跟 B 抢槽、C 行跟 D 抢槽 ⇒ 最后只剩一份），
徽标/拦截张冠李戴且不报错。⇒ `Versions.rowKey(e)` = `(key, 槽)`。
真机验收：Mindustry(159.7) 多绑到 MindustryX 的 `test` 槽后，**只有那一条附加行**亮警告，
主行（default）不亮；点附加行启动会弹「这两个版本共用同一个槽」。

**④ 「继续上次」必须按 `currentSlot` 选回那一行。**
`last_version` 只记"哪个版本"（导入版记文件名），同一个 key 有多行时全都会命中第一行 ⇒
从"存档B"那行启动、点「继续上次」会落回主行的槽（界面看着一样、进去是另一套存档）。
`Data.currentSlot()` 就是上次启动写下的槽（唯一写入点是 `Data.prepareSlot`）⇒ 用它消歧。
真机验收：从 m3b 行启动 → 回启动器点「继续上次」→ `mdt-slot.txt` 仍是 `m3b`。

**⑤ 删槽的两种语义要分开说。**
主分配被删 = 「回落到默认槽」（那一行还在）；附加绑定被删 = 「那一行直接消失」
（它存在的理由就是那个槽）。`Config.Retarget` 分开计数，Toast 分开说
（真机：「已把槽「m3b」挪进中转站（1 个只绑了这个槽的启动项已移除）」）。
⚠️ 改名那条**也要计数** —— 第 236 轮自检当场抓到：只在"删槽"分支里 `++`，改名时 extras 恒为 0。

**⑥ 摘要卡计数按版本数。**
`mEntries.size()` 在有多行时会虚报（1 个版本 2 行 ⇒ "2 个版本"）。

**⑦ 删导入版本要连附加绑定一起清。**
`Config.removeImport` → `clearBindings`（否则留一行指向不存在版本的启动项）。

**⑧ 绑定清空后别留空对象。**
第一版真机验收后 `config.json` 里留下 `"version_extra_slots": {}` —— 无害，但会让人以为"这里有东西"。
`Config.storeExtra` 在空时把整个键删掉。

**⑨ "这个版本还绑着哪些槽"只能按**版本**算，不能按行算。**
`Versions` 里曾另写一个 `hasBinding(Entry, slot)` = "这一行的槽 + 附加绑定" —— 在**附加行**上打开
「再加一个槽…」时，**主行**正在用的那个槽照样出现在列表里（因为附加行的 `slotFor` 不是主槽），
点了才被 `Config.addExtraSlot` 拒掉、弹「这个版本已经在用槽「X」了」。
⇒ 删掉那个按行的版本，列表过滤与写入都走 `Config.hasSlotBinding`（版本级：实际主槽 + 全部附加绑定）。
真机复现：`只是一个测试` 的附加行（`测试专用`）打开加槽列表，`预览验收`（= 它的主槽）被列了出来。

## 20.8 版本页（2026-10-25，第 237 轮）

| 文件 | 做什么 |
|---|---|
| `VersionActivity.java` | 页面本体。传参只给**定位信息**（`v_key` + `v_slot`），`onResume` 里 `Versions.scanAll` 找回来；找不到就 `finish()`（那一项已经不在了）|
| `VersionOps.java` | 六个动作的**唯一实现**（详情 / 换槽 / 克隆 / 命名 / 资源 / 删除），每个改状态的都收 `Done` 回调；`slotList` 是换槽与克隆共用的清单（过滤已绑 + 末尾「新建一个槽…」）|
| `activity_version.xml` | 身份卡（点开 = 只读详情）+ 六行 `row_action`（顺序：信息 → 动作 → 危险）|
| `Config.removeBinding` | 项级删除：主项被删时把第一条附加绑定提升成主项（提升后必须从附加里摘掉，否则两项一样）|
| `Versions.rowCount` | 删除范围**唯一判据**：1 + 附加绑定数 |
| `Versions.subtitleLine` | 行的紧凑副标题（来源 · 大小 · 存档 N 份）—— 列表行与版本页标题卡共用 |
| `Trash` / `TrashText` | 新种类 `VERSION`（`versions-trash/`，按目录判类型）、保留份数同整槽、列表标题用版本名 |
| `Importer.trashVersion` / `restoreVersion` | 删版本 = 副本 + 登记 + 名字/绑定一起进站；放回来逐样还原（槽已不存在的绑定跳过）|

★ 页面副标题**不许**用 `Entry.subtitle()`：它带整条 `/data/app/~~…/base.apk` 路径，真机上占三行
（2026-10-25 第一版就这么印出来了）。紧凑那份在 `Versions.subtitleLine`。

★ 已装版的「删除…」仍然显示（不隐藏），标题写「删除这一项…」、副标题写「已装版本至少留一项，不能删」，
**整行灰掉（`enabled=false` + alpha 0.45），点不动**。理由：藏起来用户会问"为什么这个版本没有删除"，
而那正是本轮要消灭的那种"两套按钮"；但"照常可点、点开才弹说明"也不好 —— 真机反馈「到底能不能删」
（2026-10-25 第 238 轮改的：按钮本身就说"不能"，不用点一次才知道）。
判据只有一处 **`VersionOps.deleteScope(rows, imported)`**（三态：只删这一项 / 删整个版本 / 不许删），
版本页画按钮与灰掉、`VersionOps.delete()` 真动手**共用这一份**。

★ **标题一行放得下就一行、放不下断成两行**（2026-10-25 用户四轮反馈后的定案）：

## 20.9 主界面返回后保持滚动位置（2026-10-25 第 238 轮）

- 起因：`next/49` 真机两次误点 —— 版本页返回后主列表回顶部，用户拿旧坐标点「管理」，
  结果点到行本体，**直接启动了游戏**。
- 做法：`MainActivity.onPause()` 记 `ScrollView.getScrollY()`，`onResume()` 在 `rescan()` 之后
  `restoreScroll()`（`post` 到这一帧布局完成再 `scrollTo`；立刻滚会被旧高度 clamp）。
- 列表变短时 ScrollView 自己夹到最大范围；`mKeepScrollY <= 0` 不恢复（首次进入无副作用）。
- 真机：展开状态卡 + swipe 后第一行 y=1264；进版本页再返回 ⇒ y=1321（**没有回顶**；
  差 57 px 来自内容高度变化，整体位移一致）。

## 20.10 命名按「项」，不按版本（2026-10-26，第 257 轮）

> **用户原话**：「让游戏命名跟随实例而不是跟随文件」。

- **以前**：名字存 `version_names: {版本key: 名字}` ⇒ 一个版本绑两个槽时两行共用一个名字，
  给第二项改名会把第一项也改掉（只能靠槽徽标区分 —— 这正是第 236 轮"每行不单独命名"那条边界）。
- **现在**：**每一行各叫各的**。存储拆两个键（形状见 `ref/42` 2026-10-26 那节）：
  - `version_names`（原有，形状不变）= **主项**的名字（主项的槽会变 ⇒ 按**版本 key** 存才跟着项走）；
  - `version_row_names: {版本key: {槽名: 名字}}`（新）= **附加项**的名字（附加项的身份就是那个槽）。
  - 读写唯一入口 `Config.rowNameOf` / `setRowNameOf`（`boundSlot == null` = 主项）。
- **名字要跟着这一项搬**：换槽（`replaceSlotBinding`）、槽改名 / 删槽（`retargetSlots`）、
  删行（`removeBinding`，删主项时把提上来那一项**自己的**名字带上去）、删版本（`clearBindings`）。
  漏一处 = "换个槽回来名字没了"，静默且只有用户自己会发现。
- **没起名的附加项不继承主项的名字**（回落 APK 自己的 label）—— 否则「恢复原名」点下去会显示
  另一项的名字，同屏自相矛盾。
- **老数据迁移**（`CONFIG_VERSION` 1 → 2，`Config.migrateRowNames()`）：老名字**抄给每一行**
  （不抄 = 用户升级后第二行悄悄少一个名字）。幂等：只补空位。
- 中转站 `state.json` 同时写 `names`（按项）与老格式 `name`；放回来时老格式算主项的名字。
- 命名框标题 / 正文改口径：「给这个启动项命名」「只改这一项的名字…同一个版本的其他启动项不受影响」。
- 尺子：自检 ⑫（三项各叫各的 / 不继承 / 换槽搬名字 / 槽改名 / 删槽 / 删行 / 提升主项 / reload /
  迁移两条）＋ ㉟（展开**不抄**名字、`fillRowNames` 按项填）＋ ㊱（中转站按项还原）。
  真机：同一版本两行分别叫「滚木」「滚木testrow」，另一行不受影响（`evidence/round257/`）。
