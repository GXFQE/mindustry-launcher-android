### F9.1 ★★ 订正：filter **不许**挂在游戏那个 Activity 上

计划稿说改动面就是 `<activity android:name="mindustry.android.AndroidLauncher">` 那一节。
**照抄会闪退**：那个类**不在我们的 APK 里** —— 它是 `:game` 进程跑完 `Injector` 六步、把游戏 dex
**追加进那个进程的 base ClassLoader** 之后才存在的（`Injector#injectDex` 里那句
`Class.forName(GAME_ACTIVITY, false, baseCl)` 就是这一步的自证）。冷启动的深链会新起一个**干净的**
`:game` 进程 ⇒ `ActivityThread` 用自己那份 `PathClassLoader` 去实例化它 ⇒ `ClassNotFoundException`
（"Unable to instantiate activity"）：用户看到**闪退**，连"卡在哪一步"的提示都没有。

⇒ **正确形状**：filter 挂**我们自己的** `MainActivity`（主进程 / 本来就 `exported=true` + `singleTop`，
天然有 `onNewIntent`），由 `DeepLink` 分派到四个内容页；游戏那个 Activity **一个 filter 都不加**
（自检里有一条 `queryIntentActivities` 门禁钉着它）。

### F9.2 清单（最终形状）

挂在 `.MainActivity` 上，两组（`MAIN + LAUNCHER` 本来就有）：

```
filter A：VIEW + DEFAULT + BROWSABLE
          scheme="content" + mimeType=application/octet-stream   ← 官方原样
                          + mimeType=application/x-msav          ← 官方原样
                          + mimeType=application/zip             ← 我们加的
filter B：VIEW + DEFAULT + BROWSABLE
          scheme="file" host="*" mimeType="*/*"                  ← 官方原样
          pathPattern=".*\.msav"                                 ← 官方原样
          pathPattern=".*\.msch" / ".*\.zip"                     ← 我们加的
```

🔴 **XML 源里必须写 `.*\\.msav`（两个反斜杠）**：`aapt2` 会把属性值里的 `\.` 当转义吃掉 ——
写一个反斜杠时编译产物变成 `.*.msav`（与官方 dump 的 `.*\.msav` 不一致），而
**aapt2 / javac / 门禁 / 自检全都不响**。判据：`aapt2 dump xmltree` 官方 APK 是 `.*\.msav`；
自检用 `queryIntentActivities` + `xmsav` / `xXmsav` 两条反方向当尺子。

### F9.4 判据表（照这张表改代码就不会跑偏）

`DeepLink.kindFor(name, mime, head)` —— **纯函数**，自检直接喂三样东西：

| 输入 | 进哪一页 |
|---|---|
| 后缀 `.msch` / `.msav`（大小写无关） | 蓝图页 / 地图页 |
| 后缀 `.zip` | **先读内容**（`PROBE`）：可能是整包，也可能是"一个模组包" |
| 后缀 `.jar` | 模组页（页内还会再探一次是不是整包） |
| 头 4 字节 `PK\x03\x04` / `msch` / zlib / gzip | 压缩包 / 蓝图 / 地图或存档 / 地图或存档 |
| mime 含 `msav` | 地图页 |
| 都不是 | `UNKNOWN` ⇒ 弹「认不出这个文件是什么。支持：…」 |

★ 两种"不知道"**必须分开**：`UNKNOWN`（认不出）vs `PROBE`（是压缩包，得读一遍内容）。
★ 头 4 字节读不到（没授权 / 文件没了 / scoped storage 挡着）⇒ 直接给「读不到这个文件」，别硬往下走。
★ `.msav` 是**地图与存档同一个容器** ⇒ 整包靠文件名 `mdt-<类>-<日期>-<时间>.zip`（我们导出器的规则）
分；分不出**一律按地图页**（那页自己会认出"这其实是一份存档"）。

`BatchIo.guessKind(ctx, doc)`（只对压缩包）：包根有 `mod.hjson` ⇒ 模组 · 按命中条目
（`.msch` > `.jar`/`.zip` > `.msav`，与顺序无关）· 一条没命中再看"一堆模组**文件夹**" ·
都不是 ⇒ `-1`（界面说「这个压缩包里没有能导入的东西」）。

### F9.5 验收（2026-10-11 真机实跑，六条）

| # | 怎么发 | 判据（实测） |
|---|---|---|
| 1 | 冷启动 `.msav`（file://，我们自己的外部目录） | `top=MapsActivity`，文件落进**当前槽** `maps/`（同大小） |
| 2 | 热路径 `.msch`（先起界面再发） | `am start` 回 "delivered to currently running top-most instance" ⇒ 走 `onNewIntent`；`top=BlueprintsActivity` |
| 3 | 整包 zip（`mdt-maps-…zip`：`甲.msav` + `sub/乙.msav`） | `top=MapsActivity`；弹「共处理 2 份 / 导入成功：2 / 从 …zip 里解出 2 份」；`sub/乙.msav` 落成 basename |
| 4 | `unknown.bin`（文本） | 「认不出这个文件是什么。支持：…」 |
| 5 | `file:///sdcard/Download/public.msav`（公共目录） | 「读不到这个文件：…」（scoped storage） |
| 6 | **走系统选择器真的点一次**（`content://…` + octet-stream） | 系统弹 `HwResolverActivity`；第 2 页我们与官方 Mindustry 并排；点我们 → 「仅此一次」⇒ `top=MainActivity` |

⚠️ 第 6 条**自动化不了**：`adb shell am start --grant-read-uri-permission` 对真 content URI 会
`SecurityException`（shell 没有那个 URI 的权限）⇒ content:// 那条只能 `query-activities`（清单侧）
+ 手点（路由侧）两侧夹住；本机 HONOR 选择器是**先点应用（出现选中圈）→ 再点「仅此一次」**。
