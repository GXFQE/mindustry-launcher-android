## F22 —— 蓝图（`.msch`）

### 它是什么

游戏里"复制一段建筑布局、贴到别处"的那种文件；存在 **`<槽>/schematics/**.msch`**
（外加**已启用模组包**里 `schematics/` 的直接子文件）。启动器把这两处列出来、
说清"**这份蓝图用到哪些方块、本槽缺哪些**"，并支持导入 / 导出 / 删除。

### 步骤（照这个顺序做，每一步都有判据）

1. **先钉口径，再写代码**：拿游戏自己的读取器当神谕（配方在 `_lab/msch/`），
   `labels` 那种"看着像 JSON"的东西**造探针试**，别按严格格式实现（§74.2 的八条）。
2. **解析内核**：纯 Java、**只出「码 + 参数」**（界面文案在 Android 侧的 `MschText` 里映射）。
3. **数据层清点**：两个来源的游戏行为**故意不同**（本槽 `walk` 递归 / 模组 `file.list()` 不下潜），
   模组那侧**复用 `Mods.scan` 的结果**（别自己再写一份启用判据）。
4. **内容表（"缺件"判据的来源）**：前缀一律用**游戏注册名**，照 `Mods.java:1253`
   小写化 + 空格→`-`（我们的 `Mods.internalNameOf` 逐字相同）；meta 里**原样**那个写法只当别名。
   ⚠️ **判据要钉在决策点上**：自检必须端到端跑 `MapStatsMods.contentFor(槽)`（真扫盘 → 真叠加），
   手工 `new Pack()` 设好前缀再测"查得到吗"**永远抓不到"前缀挑错了"**。§77.1
5. **列表 / 详情页**：新页面必须继承 `BaseActivity` + 根节点 `@+id/root` + `applySystemInsets`，
   并在清单、`SelfTest.PAGES`、㉙ 的名单三处登记。
6. **"拿不准"要自己声明**：内容表只读 `content/blocks/**` 的 JSON ⇒ 用代码/脚本加方块的模组
   （`Pack#hasCode` + 没方块 JSON + **非 hidden**）我们看不见 ⇒ 缺件文案降级为"没认出来（可能认错）"，
   依据进「技术细节」；**判据本身不动**，标记只影响文案。§77.5
   ★★ **2026-10-08 真修（同一条的第 4 种处理：真的把误报消掉）**：模组**自己的 bundle** 里
   `block.<名字>.name` 就是"这个模组注册了哪些方块"的**权威清单** ⇒ 拿它当「这个名字**存在**」的
   旁证（`MapStats.bundleBlockNames` → `MapStatsMods.SlotContent#bundleBlocks` →
   `Blueprints.rows(..., bundleBlocks)`）。
   ⚠️ 两条硬约束：① **只改"缺不缺"这一句判断**，绝不往内容表加行（地图统计必须保持"认不出的格子"）；

   不许抑制，否则会把真缺件说成不缺（漏报）。

   内容表没多一行）。
7. **写侧**：导入 = 先 `.part` + 验 + 同名先问（判据字段 `nameTaken`，**不看文案**）；

### 坑（都真踩过）

* ⚠️ **别把 APK 里的 `assets/baseparts/*.msch` 当成"游戏自带蓝图"** —— 那是 **AI 的基地模板**，
  游戏的蓝图列表不列它（地图页有"游戏自带"那一组是另一回事）。§75.1
* ⚠️ **两侧口径不同**：本槽**递归**、模组**只认直接子文件**（游戏 `file.list()`）。§75.2
* 🔴 **跨 Activity 只传定位信息**：详情页曾读列表页填的派生字段 ⇒ 显示"0 种"（不崩不报错）。§75.5
* 🔴 **"搬家"别用裸 `renameTo`**：中转站与槽可能不在一个卷上（内部 vs 外部存储）⇒
  用 `Trash.move`（复制 + 校验 + 删源）。这条是自检㊹当场抓出来的。§76.2
* ⚠️ **我们比游戏严一档**：游戏对读不出来的 `.msch` 是**静默跳过**，导入时我们**直接拒**（免得进槽后"看着在、贴不出来"）。§76.1
* ⚠️ **中转站的类型由目录名定**（不是扩展名）—— 存档与地图是同一个 `.msav`，猜错就放错地方。§69
* 🔴 **模组内容前缀必须照游戏小写化**：`name: BpCase` 的模组，它的方块在游戏里叫 **`bpcase-wall2`**；
  拿 meta 原样当前缀（大小写敏感的精确匹配）⇒ 含该模组方块的蓝图**误报"本槽没有"**、
  地图误报"认不出的格子"。★ 反面教训：第 82 轮拿 **VE** 当试金石时它恰好全小写 ⇒
  两种口径**输出相同**、错误口径被"验过"了 —— **要拿一个能区分两种解释的样本去试**。§77.1/§77.3
* 🔴 **拿不准的判断不许说成结论**：只要有一个"我们看不见"的来源（代码/脚本加方块的模组），
  这条判断就必须**自己声明不确定性** —— 宁可说"没认出来"，也不要把可能错的结论说得像事实。§77.5
* 🔴 **"参数个数对"≠"参数类型对"**：资源里 `%2$d` 而调用点传的是 `MapStatsMods.num(tiles)`
  （**字符串**）⇒ 真机 `IllegalFormatConversionException`、**主进程崩**；而"实拼"自检
  **全绿**（它自己挑了参数）。⇒ 收口成共用函数 + 元断言"字符串喂 `%d` 必须抛"。
  ⚠️ **症状识别**：主进程崩溃后 Android 会把任务栈恢复成上一页 ⇒ 用户看到的是
  「**点一下某行，结果回到了上一页**」，**长得像导航 bug** —— 遇到这种描述**先抓 logcat**。§77.6

## 列表的搜索 / 排序（第 122 轮，2026-10-07，细则 REF §83）

蓝图页现在与地图 / 存档 / 模组三页一样，顶上有一行「**筛选与排序**」+ 一个搜索框：

* 搜索匹配 **蓝图名 + 文件名**两个字段（蓝图内名可以重复，文件名才唯一）。
* 排序三档：**按名称**（默认）/ **有问题的在前** / **按大小（大的在前）**；
  「只看有问题的」= **解析不了 或 有本槽认不出的方块**（`Blueprints.isProblem`）——
  拿不准的那些（`softMissing`）**照样算**，判据不改、变的只是行里那句话。
* 判据全在**纯函数** `ListQuery`（`Blueprints.KEY` 提供"一条蓝图怎么答那几个问题"），
  四个列表页共用 ⇒ 不会出现"改了一页另三页不改"。
* ⚠️ 「只看缺件的」依赖**后台已经算好的** `missingKinds`（`Blueprints.summarize`）⇒
  重排列表必须在 summarize **之后**（顺序反了会把所有条目都筛掉）。
* ⚠️ 缩略图是**按全部清单的下标**后台渲染的 ⇒ 显示到筛过的列表上要过一层映射
  （`thumbReady(allIdx,bm)`：先写主数组、再 `shownIndexOf` 刷那一行）；
  「导出蓝图…」那个对话框列的仍是**全部**（筛过的列表只管显示，不管"能导出哪些"）。
