> 2026-10-13 第 142 轮。**起因**：用户「说实话应该搞一个脱敏崩溃报告导出（倒是隐私泄露相对还好）」。

## F26.1 为什么是这一份（而不是别的）

`LogActivity` 的「导出全部日志」（F20）把**游戏 `last_log.txt` + 六份 `report-*.txt` + 全部崩溃报告**
拼成**一个文件** —— 那正是用户报 bug 时会**发出去**的东西。实测那一份里有：
**21 处**数据根绝对路径（含用户起的槽名）· 7 处内部数据根 · 表头机型 · 每份报告头的 **GL 驱动串**
与**模组清单** · 7 处 `/data/app/…apk`（判为**非**个人数据）。

⇒ 隐私风险比 `usid` 低（**没有凭据**），但**外流概率高得多**。

## F26.5 坑（都是本轮真踩的，细则 §92.4）

1. 🔴 **"返回了原件"最难发现**：`Result.text` 写成 `final` 照抄输入 ⇒ 判据表全红，
   **而「结论不变」白过**（拿没剥过的副本比原件）。尺子必须**两条同时有**：
   **"剥完真的变了"** ＋ **"该留的一个没少"**。
2. 🔴 **已知值替换要有标识符护栏**：昵称撞上 `java.lang.NullPointerException` ⇒
   会把**异常类名**改掉、**把归因弄坏** ⇒ 紧邻 `[A-Za-z0-9_$]` 或 `.` 的那一处不换。
3. 🔴 **同一件事的两种写法都要认**：报告头 `GL Version: …` vs 游戏日志 `[I] [GL] Version: …`
   （只认前者 ⇒ 真机产物里还剩 1 处 `Adreno`）；改写时**前缀要原样留着**。
4. **收紧规则要照"反方向夹具"收**：两个前缀都写成可选 ⇒ 退化成裸 `Version:`，
   吃掉报告头的 `Version: unknown build 0`。
5. **承诺要照承诺验**：说好"ABI / API / 页大小留下"，`<device>` 就不能把 `· Android 16 (API 36)` 一起吃掉。
6. **读设置失败不算失败**：`readSecrets` 一律吞异常 —— 绝不能因为 `settings.bin` 损坏就让用户导不出日志。
