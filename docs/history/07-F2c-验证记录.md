## F2c 验证记录（2026-10-01，真机 <测试机型> / Android 16）

**问题**：这东西可以横屏，但是横屏以后没有滚动条，底下按钮点不到。
真机复现 → 定位 → 修复 → 回归，全程 adb 取证。

### 复现（修复前，横屏 2700×1224）

| 观察 | 数值 |
|---|---|
| 内容区可用高 | 945px（291dp）＝ 屏幕 1224 − ActionBar 279 |
| `ver_list` | **完全不在 UI 树里**（高度被压成 0） |
| `row_saves` | 85px（正常 204px） |
| `row_saves` 内的 `act_title` | **7px**（文字被裁成一条线，点击热区几乎为零） |

### 根因

「根 `LinearLayout` ＋ 顶部区 `wrap_content` ＋ `ListView 0dp/weight=1`」这个结构
**只在高度够用时成立**：顶部区不可收缩，`weight` 子视图在剩余空间为负时被夹到 0，
而且差额沿 `AT_MOST` **逐层下传**，最深的子视图独自承受全部压缩。

### 修法（XML-only，Java 逻辑一行没动）

`activity_main.xml` / `activity_saves.xml`：根改 `ScrollView`（`fillViewport`）→ 内层 `LinearLayout(wrap_content)`
→ `ListView` 改 `wrap_content`；`Util.applySystemInsets()` 补 left / right（横屏导航栏在右侧）。

| 用例 | 结果 |
|---|---|
| 横屏滚动 | ✅ `input swipe` 可一路滚到底 |
| `row_saves` 滚动后 | ✅ 恢复完整 204px，文字完整可读 |
| `ver_list` 滚动后 | ✅ 出现，三个版本行（徽标 / 冲突警告 / 「槽」按钮）齐全 |
| 点击「存档与备份」 | ✅ `mCurrentFocus` 命中 `io.mdt.launcher/SavesActivity` |
| 存档页横屏 | ✅ 三个操作行 204px 完整，`slot_list` 可见 |
| 竖屏回归 | ✅ 内容 2265px < 视口 2395px，**不产生滚动**，观感与 F2b 一致 |
| 右侧导航栏避让 | ✅ 内容 x 123~2571，未伸进导航栏（导航栏自 2571 起） |
| M3 自检 | ✅ **36 项全过 / 0 失败** |

★ **三个必须记住的坑**（详见 `FLOWS.md` F2c 坑 与 `REFERENCE` §23）：
① `weight` **不是防压缩开关** —— 剩余为负时被夹到 0，且压缩**逐层下传**、最深的视图独自承受全部差额；
② **`uiautomator dump` 的 bounds 是「被父容器裁剪后的可见区」**，不是视图真实尺寸，
   且完全不可见的节点不上报 ⇒ 查"看不见 / 点不到"必须**先滚动再 dump**（本轮据此误判过一次）；
③ 横屏**三键导航栏在窗口右侧**（本机 129px）⇒ 四边 inset 都要算，且 base 必须存档防重复派发累积。

证据：`evidence/f2c-{main-land-before-scroll,main-land-scrolled,saves-land}.png`。

> ⚠️ **F2c 的结论有一条被 F3b 推翻了**：本节当时写"`ScrollView` 里放 `ListView` 并给 `wrap_content`

> 而那个分支**只按单行估高** ⇒ 能滚，但**滚不到底**。详见下面的 F3b。
