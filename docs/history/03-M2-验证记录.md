### ★★ 重大发现：游戏会搬运 `files/` 目录（探针工程未发现）

Mindustry 的 `AndroidLauncher.onCreate` 里有（源码在 `android/src/mindustry/android/AndroidLauncher.java`，已核实 v159.7）：

```java
Fi data = Core.files.absolute(getExternalFilesDir(null).getAbsolutePath());
Core.settings.setDataDirectory(data);          // 数据根 = 外部
if(!Core.files.local("files_moved").exists()){
    Fi src = Core.files.absolute(Core.files.getLocalStoragePath());   // = getFilesDir() = files/
    for(Fi fi : src.list()) fi.copyTo(data);                          // 逐个 copy，不删源
    Core.files.local("files_moved").writeString("files moved to " + data);
    Core.files.local("files_moved_103").writeString("files moved again");
}
```

**四条精确语义**（缺一条都会踩坑）：

1. 搬运源是 `getFilesDir()`（`files/`），**只列一层**，目标是数据根 `getExternalFilesDir(null)`；
2. 是 **copy 不是 move** —— 源不删，所以内部还留着一份；
3. 标记 `files_moved` 写在**内部** `files/`，所以正常只搬一次；**标记被清就会再搬一次**；
4. 同一方法里还会**删掉数据根的 `cache/`**
   （`Core.settings.getDataDirectory().child("cache").deleteDirectory()`）——
   这正是探针实测到"官方 159.7 跑完把 MindustryX 的 cache/ 整个删掉"的原因。

⇒ **HUB 的私有数据绝不能放 `getFilesDir()`**，否则会被复制进**游戏数据根（= 存档槽）**，
污染存档 + 占双倍空间（导入整包 70+ MB）。本工程改用 `getDir("hub")` = `/data/user/0/<pkg>/app_hub`：
**仍是内部存储**（dex 照样能加载，满足"导入的 APK 必须放内部"的硬约束），
但不在游戏 copy 的范围内。详见 `Paths.java` 头注释。

**实测验证**（可证伪）：把 HUB 数据迁到 `app_hub` 后，**删掉 `files_moved` 标记**强制游戏重搬一次 ——
结果外部数据根只新增了 `files_moved_103`（内部 `files/` 里当时唯一的文件），
`app_hub` 三项（config.json / import / natives）时间戳原封不动、无一被搬。✅

**已产生的历史残留**（首次搬运把误放的数据复制进了数据根，需清理）：

```
<数据根>/config.json   301 B   ← HUB 配置副本（内容含 imports 数组，可识别）
<数据根>/import/       ~75 MB  ← 导入的 APK 副本
<数据根>/natives/      ~1.2 MB ← 解出的 libarc*.so 副本
```

这三项是 HUB 数据的**冗余副本**（原件已在 `app_hub`），清理不影响任何数据；
但不清理会**跟着槽交换走**，污染存档槽。

**清理已执行**（2026-09-30，M3 的"数据根体检"）：
删除前先逐项比对过原件 —— `app_hub/import/official-159.apk` 78354755 B（只读）、
`app_hub/natives/arm64-v8a/` 两个 `.so` 大小逐一相同；删除后复跑体检 **0 项**，
数据根只剩游戏自己的东西，`app_hub` 一个字节没动。
