## F15b 验证记录（2026-10-01，真机 <测试机型> / Android 16）

**触发（需求）**：**去掉这里重复的 UI** —— 附两张截图：存档页顶部操作卡 ↔ 槽菜单。

**重复的精确来源**：F15 的「进 / 出口对称」是**只加不减**的 —— 它在槽菜单里补了
「导入存档（.msav）」「导入整槽（zip）」，却**原样保留**了存档页那两个入口
（当时的理由是"两条路各管一种直觉"）⇒ 同一界面上出现两组语义相同的入口。

**裁决**：删存档页那两条，**保留槽菜单那条** —— 导入的落点必然是某个槽，
从槽进去目标已知、**少一次"选槽页"**。⇒ 存档页操作卡只剩「无槽语境」的两项。

**改了什么**

| 文件 | 做什么 |
|---|---|
| `activity_saves.xml` | 删 `row_msav` / `row_zip` 两个 include 及间隔线 |
| `SavesActivity.java` | 删两处 `bindAction` + `pickMsavTarget()` / `pickZipTarget()` / `pickSlotDialog()` / `OnSlot` 接口（连带清掉死代码） |
| **删** `app/res/layout/dialog_pick_slot.xml` | 选槽页整份布局，唯一调用者已移除 |
| `strings.xml` | 删 6 条：`saves_act_msav_*` / `saves_act_zip_*` / `pick_msav_slot_title` / `pick_zip_slot_title` |

### 续：槽菜单四条文案的**介质标注对称**（同日追加需求：导入存档标了 `.msav`、导出却没标）

**问题**：槽菜单按介质成对排了四条，但**只有三条标了格式**：

| 文案键 | 修正前 | 修正后 |
|---|---|---|
| `slot_op_import_save` | 导入存档（.msav）… | 不变 ✅ |
| `slot_op_export_save` | **导出存档…** ❌ | **导出存档（.msav）…** ✅ |
| `slot_op_import_slot` | 导入整槽（zip）… | 不变 ✅ |
| `slot_op_export_slot` | 导出整槽（zip）… | 不变 ✅ |

**核实结论：功能本身没有问题** —— `promptExportSave()` 取的正是 `saves/` 下的**原始文件**
（`fs[w].getName()` 作 SAF 建议名，`application/octet-stream`），F6 已真机验过产物
`Download/困难模式.msav` **md5 与源逐字节相同**（见上面 F6 记录）。缺的**只是文案上的介质标注**。

**证据**：`evidence/f15b-slot-menu-symmetric.png`（真机 dump 九项，四条标注齐全）。

> ★ **纪律**：**不对称的文案 = 让人怀疑功能不对称**。四条成对的入口里只要有一条漏标介质，
> 用户第一个念头就是"这两个导出的不是同一个东西吧？" —— 一个符号的疏漏，代价是一整轮追问。
> ⇒ 凡是**成对出现的入口**，文案模板必须逐字段对齐（介质、省略号、语序）。
>
> ⚠️ 本轮产物仍是 **158459 B** —— **改文案不改体积**（第九次实测"大小不变"，
> 见产物基线那节的告警）。⇒ **验内容别验数字**：用
> `aapt2 dump resources mdt-launcher.apk | grep -A2 slot_op_export_save` 读回才知道改没改进去。

> ⚠️ **本条推翻 F15 的一处设计判断**：F15 以为"双入口各服务一种使用顺序"值这个重复，
> 定案是**重复 > 便利** ⇒ **一件事在 UI 上只留一个入口**；
> 若真有两种使用顺序，应体现在**同一条流程内**（比如让选槽页可跳过），而不是并列两个入口。
