## F16 验证记录（2026-10-01，真机 <测试机型> / Android 16）

**触发（需求）**：**先实现 CAS 存储**；旧备份的迁移方式定案为**自动迁移、不维护双格式并存**。

**做了什么**：把桌面版 `MDT-Dev/launcher/storage.py` 的 `CASStore` 移植成 `Cas.java`
（`sha256` 寻址 + 两级分片 `objects/<前2>/<后62>`），并改造 `Backup.java` 让每份快照
只留**清单**、正文进共享对象池。四个照抄的核心方法：`put` / `getTo` / `garbageCollect` / `scan`。

**与桌面端有意偏离的三处**（都是 Android 上的必要适配，详见 REF §33.2）：

| 偏离 | 桌面版 | Android 版 | 原因 |
|---|---|---|---|
| 哈希计算 | 先算 md5 再算 sha256（两遍 I/O） | **一遍流式同时算 sha256** | 移动端存储慢，省一遍读 |
| 恢复校验 | 只校验清单里的 md5 | **边写边校验 sha256** | 池里对象可能被外部改坏，写入即验 |
| 池落点 | `<backups>/cas/` | **`<hub>/cas/`（与 `backups/` 平级）** | 池跨槽共享；放 `backups/` 里会被"清空备份"连带删掉 |

**本轮五个坑**（细节 → REF §33.5）

1. 🔴 **`adb shell` 改不了应用外部存储文件的 mtime**（跨 UID）⇒ 想制造"过期孤儿"必须在
   **应用进程内**调 `File.setLastModified()`；`adb shell touch` 会报 `Operation not permitted`。
2. 🔴 **对象池是跨轮持久的** ⇒ 测试不能用绝对量断言，必须用**增量** + **每轮唯一内容（nonce）**。
   （首轮 3 条失败全是这个根因：固定内容第二次跑时对象已在池里，本是 CAS 正常行为。）
3. ⚠️ **对合运算会制造"静默假阳性"**：`data[len/2] ^= 0x5a` 翻两次就复位 ⇒
   负例可能"上一轮已翻过、本轮翻回正确内容"，于是恢复反而成功。**篡改前必须先自证对象有效**。
4. ⚠️ **节省率公式写反过一次**（`100/25` 写成 `25/100`）⇒ 补 `savedFormula` 用例用合成数字钉死四种情形
   （含"实占 > 逻辑 ⇒ 夹到 0"和"逻辑 = 0 ⇒ 不除零"）。
5. ⚠️ **外部存储的 mtime 不可全信**（FUSE 层会让同一 sha 对象的 mtime 变化）⇒
   GC 的宽限期判据只会"少删"，不会"误删"——这个方向是对的，别去"修"它。
