## 第 43 轮验证记录（2026-10-02，真机 <测试机型> / Android 16）

**问题（截图）**：选槽对话框里一行渲染成

```
default[当前]52 文件 · 208.3 KB
```

槽名、`[当前]` 标记、统计**三项粘成一坨** ⇒ 要求**换行或者加个空格**。

### 根因：🔴 `aapt2` 会剥掉 string 资源的【前导空白】

`strings.xml` 里写的就是**两个字面空格**，**编译后一个不剩**。

> ★ **关键区分**：**Java 字符串字面量里的空格不受影响** —— 差别只在"**经不经过 aapt2**"。
> 所以同一份代码里两种行为并存，而**看代码看不出任何区别**（两边都写着空格）。
> 这正是它难查的原因：用 Java 那处的人会觉得"空格明明有效"。

**修法**：资源里改用转义 —— `<string name="slot_current_suffix">\u0020\u0020[当前]</string>`。

> ⚠️ **套娃坑**：**Java 的 Unicode 转义在【词法分析之前】处理** ⇒
> 在 Java 注释里写 `\u0020` 去描述这个坑，**注释自己会被编译成空格**（本次就栽了一次）
> ⇒ Java 文件里要描述它必须写 `U+0020`。

### 顺手清掉两处「两个入口」

- **合并重复资源**：选槽对话框的 `slot_entry_suffix_fmt` 与存档页的 `slot_entry_fmt`
  **内容只差前导空格** ⇒ 删前者，两处共用一条（同一显示规则只留一处实现）。
- **删死代码**：`Data.Slot.title()` / `subtitle()` 经全工程调用点核对 —— **0 个调用者**。
  ⚠️ 留着它比多几行更糟：字符串里写字面空格**能生效**（不经 aapt2），
  一旦有人用它就会与资源被剥空格的行为不一致、**而且没有任何症状**。

### 验收：两条路互证

| 手段 | 读的是 | 局限 |
|---|---|---|
| `aapt2 dump resources <apk>` | 编译后的资源值 | ⚠️ 是"**逻辑视图**"，可能按原字面值显示 ⇒ **不能单独当验收依据** |
| 真机渲染文本 / 应用内 `getString()` | **终端用户看到的字** | 需设备 + dev 变体 |

- ✅ 资源实得 `「  [当前]」`（前导两个空格真的在）；实拼
  `default  [当前]  52 个文件 · 208.3 KB`。
- ✅ **自检 234 通过 / 0 失败**（228 + ⑥f 6 条）。⑥f 把"三段边界是否都有空白"
  抽成纯函数后配**元断言** —— 拿**用户截图里那个真实坏形态**喂进去要求**判死**，
  并额外验证"**只补前半段**（`[当前]` 后仍缺空白）也不放过"。
  > ★ 先修再写断言 ⇒ 断言会永远通过、无法证伪 ⇒ **必须拿"已知是坏的输入"喂它要求判死**。
- ✅ 设备已装回**产品版**（sha256 与设备 `base.apk` 逐字节相同；`flags` 无 `DEBUGGABLE`）。
