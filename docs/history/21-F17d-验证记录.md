## F17d 验证记录（2026-10-02 第三十一轮，真机 <测试机型> / Android 16）

**触发（需求，两条）**：

> **需求：共用提示在只有一个版本时措辞不合适**（要是共用的太多也可以用类似 XXX 等多个版本的样子写）
> **需求：自检的截图判断方式要改 —— 在开头显示总体情况，出问题了再翻**

两件独立的小事，共同点：**信息没错，但"给的位置"错了**。

### 一、冲突提示：说出"一共有几个"

原实现 `other = l.get(i == 0 ? 1 : 0)` —— **永远只取第一个对手**，组内 3 个版本时
每一行都只报同一个对手 ⇒ 容易误以为只有两个版本在抢槽。

改法：抽成类级纯函数 `Versions.conflictPeerDesc(firstName, total)`：

| 组内数 | 输出 |
|---|---|
| 2 | `⚠ 与「A」共用此槽，存档会互相覆盖` |
| 3 | `⚠ 与「A」等 3 个版本共用此槽，存档会互相覆盖` |

⚠️ `total` **含自己**（中文"等三人" = 共三人）。
⚠️ **书名号必须由 desc 带、fmt 不带** —— 否则"等 N 个版本"会掉到书名号**外面**。

### 二、自检报告：结论前置（**判读成本从 5 张图降到 1 张**）

**原样**：结论在报告**最后一行** ⇒ 要滚 5 屏、截 5 张图才知道过没过（这正是要消除的判读成本）。

**现在（两层保险）**

1. **报告重排**（`runM3` 收尾，明细一行不删）：抬头 → **汇总** → 失败项（若有）→ 原有全部明细。
2. **结论进弹窗标题**：AlertDialog 的标题**不随正文滚动** ⇒ 任何滚动位置都能看到。

```
M3 自检结果 · 通过 102 项，失败 0 项        ← 标题（不滚动）
MDT M3 自检   Fri Oct 02 …
===== 通过 102 项，失败 0 项 =====           ← 第 3 行，第一屏可见
无失败项。下方依次是环境信息、逐项明细、清理与用时。
数据根 = …
```

⚠️ `summaryOf()`（从报告捞汇总行给标题用）**只为显示**；**永不据此判断通过与否**（真判据只有 `stat`）。
⇒ `runHealthReport` 同样把"有多少要处理的"提到第一屏。

### 三、🔴 我自己引入的缺陷：中文串接多了空格

```xml
<!-- ❌ 我写的（"给插入值加个分隔更清楚"—— 中文不需要） -->
<string name="row_conflict_fmt">⚠ 与 %1$s 共用此槽，存档会互相覆盖</string>
```

真机 dump 回读 ⇒ `⚠ 与 「MindustryX…」等 3 个版本 共用此槽…`（**两处都空着**）。
**不崩不报错**，靠"改完文案习惯性 dump 回读"才发现。已改为 `⚠ 与%1$s共用此槽…`。

### 四、★★ 新纪律：**先修再写断言 ⇒ 断言必须自证有分辨力**

修完空格再补断言会掉进陷阱：**断言永远通过、无法证伪**。
（这是 F17b「断言写宽了把好数据判死」的**镜像**。）

⇒ 补**元断言**：拿"真实写错过的那一行"喂给判据，**要求它必须判死**：

```java
ok(stat, L,  hasCjkSpace("⚠ 与 「A」等 3 个版本 共用此槽…"), "元断言：错误文案会被判死（证明判据有分辨力）");
ok(stat, L, !hasCjkSpace("⚠ 与「A」等 3 个版本共用此槽…"), "元断言：正确文案不被误杀（判据不是恒真）");
```

★ **可迁移规则**：**"先修好、再补断言"时，必须给断言喂一个"已知是坏的输入"** ——
  否则那条断言可能只是恒真的装饰，而 **"看着有自检、其实什么都没验"比没有自检更危险**（给的是虚假信心）。

判据刻意**不用 `contains(" ")`**（会在 fmt 将来真需要空格时误杀），
而是锚定四处**具体紧邻组合**：`与 「` / `」 ` / ` 共` / `版本 等`。
