## F3b 验证记录（2026-10-01，真机 <测试机型> / Android 16）

**问题**：列表拖不到最底下。真机复现 → 定位 → 修复 → 回归，全程 adb 取证。

### 复现（修复前，横屏 2700×1224，滚到底后）

| 观察 | 数值 |
|---|---|
| `ver_list` 实测高度 | **342px** = 39px(`paddingBottom`) + 303px（**一行** item） |
| 3 个版本的真实内容高 | 3×303 + 39 = **948px** |
| 少算 | **606px（64%）** ⇒ 滚动范围只有真实值的 1/3 |
| 现象 | 只露出第一行；第二张卡片的顶边被屏幕底边切断，再也拖不动 |

### 根因

`ListView.onMeasure` 在 **`heightMode == UNSPECIFIED`** 分支下不测量全部条目，
只用 `padding + 单个 item 高` 估整体高度。而 `ScrollView` 给子级的约束**恰好就是 UNSPECIFIED**。

### 修法

两页的列表容器由 `ListView` 改为 **`LinearLayout`**，条目在 `rebuildList()` 里逐个 inflate 后 `addView`
（条目本来就要求全展开，AbsListView 的回收机制从未被用上）；整行的单击 / 长按直接挂到行根上，
空态改为手工控制 visibility；删掉 `Adapter` / `setEmptyView` / `OnItemClickListener`。

### 顺带修掉的第二个缺陷

`slotOps` 与 `pickMsavTarget` 两个对话框**列表项一个都不渲染**
（四个槽操作全点不到；`.msav` 导入实质不可用）。
根因：**同一对话框里 `setMessage` + `setItems` 并存时 list 被吞掉**。
对照：`pickSlot()` 用 `setSingleChoiceItems` 且无 `setMessage` ⇒ 列表正常。
修法：说明文字并进 `setTitle`。

| 用例 | 结果 |
|---|---|
| 横屏滚到底 | ✅ `ver_container` 948px，**3 个版本条目全部完整可见** |
| 点击整行 | ✅ 真的启动游戏（`mCurrentFocus` 命中 `mindustry.android.AndroidLauncher`） |
| 长按整行 | ✅ 详情弹窗（标题 / 路径 / MD5 / 存档槽） |
| 点「槽」按钮 | ✅ 槽选择弹窗，且**不**触发整行点击 |

| 点「导入 .msav」 | ✅ `default [当前]` / `test2` 可见 |
| 存档页横屏滚到底 | ✅ `slot_container` 内两个槽完整可见 |
| 竖屏回归 | ✅ 内容 2265px = 视口，**不产生滚动**；`ver_container` = 3×358+39 = 1113px |

★ **三个必须记住的坑**（详见 `FLOWS.md` F3b 坑 与 `REFERENCE` §24）：
① **`ScrollView` 里不要放 `ListView` 并指望它展开** —— `UNSPECIFIED` 分支只按单行估高，
   症状是"滚不到底"而不是"显示不全"；
② **`AlertDialog` 的 `setMessage` 会吃掉 `setItems` 列表** —— 且症状极具欺骗性
   （对话框正常弹出、标题说明都在，看起来没坏）；
③ **产物字节数可能改完一行都不变**（F2c / F3b 两次都恰好相同），别拿它当"有没有编进去"的判据。
