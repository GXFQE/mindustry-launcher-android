## F17 验证记录（2026-10-01，真机 <测试机型> / Android 16）

**触发（需求）**：**版本号里的 8-official 没必要保留，全部统一命名规则，继续上次也显示版本号**

三个诉求：① 去掉 `8-official-` 前缀；② 界面上同一个版本只有一种叫法；③「继续上次」也带版本号。

**根因（改动前的事实）**：`versionName` 是 **APK 里的原文**，我们改不了：

```
io.anuke.mindustry               versionName = 8-official-159.7
com.github.tinylake.mindustryX   versionName = 8-official-2026.09.X37
```
而那截前缀还有两个**实际害处**：① 把真正的版本号挤到行尾，正好落进 ellipsize 的裁剪区
（F7 那个"版本号被折叠了"的 bug，诱因就是它太长）；② 「继续上次」只有一行，带着它更容易被截断。

**改了什么**

| 文件 | 做什么 |
|---|---|
| `Versions.java` | 新增 `BUILD_PREFIX` 正则 + `rawVersion()` / `displayVersion()` / `versionTrimmed()` / **`displayName()`**；`title()` 改为 `displayName() + （导入）` |
| `MainActivity.updateContinue()` | `e.label` → **`e.displayName()`**（「继续上次」终于有版本号） |
| `MainActivity.buildTitle()` | `e.versionName` → **`e.displayVersion()`**（见下方那个坑） |
| `MainActivity.showDetail()` | 剥过前缀时追加 `原始版本名: …`，保住可追溯性 |
| `strings.xml` | 新增 `detail_raw_ver_fmt` |
| `activity_main.xml` | `continue_text`：`singleLine` → **`maxLines="2"`** |
| `SelfTest.java` | 新增 **⑥b**（12 条断言），钉住"宁可漏剥不许误剥" |

**★ 关键设计：显示的规范化只有一处实现。** 抽出 `displayName()` 作唯一入口，
于是**冲突提示也顺带对齐了**（它复用 `title()`）—— 若各处自己拼字符串，就得逐个去改、漏一个就又不统一。

**🔴 本轮最容易踩的坑**：`buildTitle()` 用 `plain.indexOf(ver)` 定位染色区间。
若只改 `Versions` 而忘了同步这里，就会拿**带前缀的原文**去 `indexOf` 一个**已剥前缀的串** ⇒
恒返回 -1 ⇒ **染色静默失效**（不崩、不报错、文字也没错，只是版本号不再是弱化色，极难发现）。
已在 javadoc 里写明"取值的唯一入口是 `Entry.displayVersion()`"。

### ★★ 顺带查明：`158459 B` 之谜（推翻了历史解读）

本轮加了正则 + 2 个方法 + 12 条断言 + 布局改动，APK **仍是 158459**，
但 `build/dex/classes.dex` 如实从 **205316 → 207856**。物理上说不通，于是查穿：

| 步骤 | 事实 |
|---|---|
| ① 排除"没构建" | 新字符串在 `aapt2 dump`、新方法在 dex ⇒ 内容确实是新的 |
| ② 分离变量 | 上一轮 `unsigned.apk` 148147 → 本轮 **149449**（+1302），**签名后却都是 158459** |
| ③ 复现 | 两个 `unsigned` 各自重签 ⇒ 都 158459（条目真差 1303 B：dex +1210、arsc +76…） |
| ④ 定位 | 两者**中央目录起点完全相同 = 155648**，差异全落在"签名块+填充"（5616 ↔ 4316） |
| ⑤ 猜想 | `155648 % 4096 == 0` |
| ⑥ 证死 | 追加 300 B 再签 ⇒ `cd_off` 跳到 **159744**（`%4096=0`、`%8192≠0`）⇒ **粒度确为 4096** |

**结论**：`apksigner` 把 **zip 中央目录起点对齐到 4096**；条目区变化量小于"到下一个 4096 边界的
剩余空间"时，差异被填充**完全吸收** ⇒ **签名后的 APK 总大小一字不变**。

⇒ **历史上那些"怪事"全是同一个机制**，不是巧合：F2c / F3b / **F6c 连改四轮 146177** /
**F6 改三轮 129492** / F15 / F16 / **F15b 与第 27 轮 158459** / **F17 158459**。
（"dev 与产品同尺寸"的**结论碰巧对，理由不对** —— 真因是同一个对齐。）

⇒ ✅ **想用一个对改动敏感的数字，看 `build/dex/classes.dex`**，别用 APK 总大小。
详见 `REFERENCE` §35.5。
