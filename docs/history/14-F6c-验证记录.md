## F6c 验证记录（2026-10-01，真机 <测试机型> / Android 16 / 1224×2700 @520dpi）

**触发（需求）**：数据根体验是什么；导入 msav 要放具体槽的编辑页面；再加上个导入 zip
（还有与游戏原生导入导出的兼容情况 —— 原生好像只打包部分文件，我们可以加个全部文件）。

⇒ 四件事：① 「数据根体检」这一行看不懂（内部黑话）② 导入 `.msav` 要能**选槽**、能看到槽状态
③ 新增**导入 zip**（F6 只做了导出）④ 说清与**游戏原生「导出数据 / 导入数据」**的兼容，
并把我们的导出口径从"备份白名单"升级成**全部文件**。
（★ **F19（2026-10-02）把这条路和备份收口成同一份实现** —— 备份也从白名单改成了同一个口径，
见下文「口径改动」与 M3 设计要点。）

**先做的源码核实**（探针工程外的第二手证据，Mindustry 160.4）：

| 原生行为 | 源码位置 | 对我们的意义 |
|---|---|---|
| 导出打包 `settings.bin` + `maps/` + `saves/` + `mods/` + `schematics/` + `assetCache/` | `SettingsMenuDialog.exportData()` | 条目名 = 相对数据根路径 ⇒ 我们的 zip **天然同构** |
| 导入要求**根目录必须有 `settings.bin`**，否则抛 `Not valid save data.` | `importData()` | 所以"认不认得出是原生包"的判据就是这个文件 |
| 导入会先**删 `saves/` `assetCache/` `tmp/`** 再解包，最后 `Core.app.exit()` 重启游戏 | `importData()` | 原生导入是**破坏性**的 ⇒ 我们的"先清空"复选框默认**不勾** |
| `saveExtension = "msav"`，`saveDirectory = dataDirectory.child("saves/")` | `Vars.java` | `.msav` 落点确认 |
| 每次启动 `getDataDirectory().child("cache").deleteDirectory()` | `Vars.setup()` | ⇒ `cache/` **必然**下次启动被删，从导出里排除 |

**口径改动（`Data.java`）**

| 常量 | 值 | 说明 |
|---|---|---|
| `SLOT_EXCLUDE` | `config.json, import, natives, tmp, cache` | 前三项是 HUB 自己的东西被游戏抄进数据根的残留；`tmp` 是游戏临时目录；`cache` 见上表。★ **F19 起「备份」也用这张表**（原 `EXPORT_EXCLUDE` 已并入），另加通用跳过 `Data.contentSkipped`（`.` 开头 / `*.part` / `*.tmp`） |
| `WIPE_DIRS` | `saves, maps, schematics, assetCache` | 对齐原生删的三个 + 补同族的 `maps`/`schematics`。★ **`mods` 刻意不清** —— 跨存档共享，清了是纯破坏 |

★ **导出口径现在是原生口径的超集**：原生 6 项 ⊂ 我们（数据根全部内容 − 5 项排除），

★ **F19 起备份也是这个超集**（与导出**共用** `Data.contentRoots`）—— 两者问的是同一个问题。

### 本轮新坑

- ★★ **`AlertDialog` 的 `setTitle` 独占纪律在本批又救了一次**：zip 确认框要同时放
  「文件数 + 顶级条目 + 包裹目录提示 + 原生格式判语 + 先清空复选框」，**全部**塞进 `setTitle`
  的多行文本 + `setView`，一个字都不敢给 `setMessage`（F3b 实测 `setMessage` 与 `setItems`/`setView`
  同框会互相吞）。
- ⚠️ **弹窗活着的期间 Activity 被重建 = 监听器一起丢**：`.msav` 的 `.part` 靠 `setOnCancelListener`
  回收，但**转屏 / 切深浅色 / 被系统杀掉后回前台**会让 Activity 重建，弹窗连同监听器直接消失，
  `.part` 就成了永久垃圾（对游戏不可见，因为存档列表只认 `*.msav`，所以**最难自查**）。
  ⇒ 修法是**入口清扫**（`Msav.sweepParts` 在 `stage()` 开头把 `saves/` 下所有 `*.msav.part` 删掉），
  而不是补监听器 —— 因为"哪些路径会 dismiss"永远列不全。
- ⚠️ **`input text` 被中文 IME 吃掉的更准确描述**（补充 F6 那条）：字母会被转成**拼音候选**
  （dump 里只剩参与组词的残留），但**数字直接穿透** ⇒ 要用 `input` 验改名时，
  起个**纯数字**的名字（本轮用 `998877`）比切 IME 省事得多。
  另外某个中文输入法会在第一次弹出时插一个**皮肤推广窗口抢焦点**，
  得先点它的「取消」才能继续输入。
- ⚠️ **`.msav` 改名框的预填值必须与提示文案对齐**：原来预填 `st.base`（= 已带 `.msav`），
  而提示写着"`.msav` 后缀会自动补上" ⇒ 用户会以为要自己删后缀。改成 `Msav.baseName()`
  （幂等剥后缀）才对得上。**庆幸的是 `safeName` 本身幂等，所以当时没炸出双后缀，只是文案与界面对不上。**
- ⚠️ **行副标题的长度要按最窄屏幕算**：`saves_act_zip_sub` 原为 26 字
  （`zip 数据包 → 指定槽（含游戏「导出数据」的包）`）⇒ 竖屏折两行、把四行动作卡的节奏撑坏；
  横屏才显示为一行（**所以只截横屏会漏掉**）。改成 20 字 `zip 数据包 → 指定槽（兼容游戏导出）` 后
  四行行高一致（60px）。细节说明挪进确认框的 `zip_tag_*`。
