## F7b 验证记录（2026-10-01，真机 <测试机型> / Android 16）

**问题**：**继续上次必须把启动器重启才能更新**。

### 根因

`Config` 是**进程内单例** + `load()` 幂等（`mFile != null` 直接 return）⇒ 每个进程只在启动时读**一次**盘；
而 `last_version` 由 `GameSlot` 在 **`:game` 进程**写（`GameSlot:84`，游戏启动成功之后）
⇒ 主进程内存里那份 `mRoot` 永远看不到。修复前实测（同一主进程，未重启）：

| 步骤 | 盘上 `last_version` | 「继续上次」 |
|---|---|---|
| 初始 | `official-159.apk` | official-159 |
| 写入 `com.github.tinylake.mindustryX`（等价于 :game 写入） | MindustryX | **official-159** ← 走 2 次 onResume 都不变 |
| force-stop 重开 | MindustryX | MindustryX ✅ |

### 修法

`Config.reload(Context)` —— **不做 mtime 短路**（漏判的后果恰好就是这个 bug）、
**读失败保留内存值**（运行期绝不能把配置清成默认）、**成功整体替换 `mRoot`**；
在 `MainActivity.onResume()` **第一句**调用（先于 `rescan()` 与 `AutoBackup.settle()`）。

|---|---|
| dev：外部写入 → onResume（不重启） | ✅ 立即从 MindustryX 变 official-159 |
| dev：反向再写一次 | ✅ 立即变回 MindustryX（证明是**每次真读盘**，不是首次缓存） |
| dev：**真实链路**（点 official-159 启动游戏 → 回启动器） | ✅ 主进程 pid 16020 不变，界面立即跟上 |
| 产品版：**真实链路**（点 MindustryX → 回启动器） | ✅ 主进程 pid 18479 不变，official-159 → MindustryX |
| M3 自检 | ✅ 36 / 36 |
| 启动管线 | ✅ 六步全过，前置段 40 ms |

### 本轮新坑

- ★★ **跨进程写配置后，另一个进程不会自己知道**（进程内单例 + 幂等 load）。
  表现为「明明改了却有延迟 / 重启才生效」——**判据：重启就好的 bug，先怀疑进程内缓存或单例。**
- ⚠️ **HUB 报告不在私有目录**：`Data.hubDir()` = `Paths.externalHub()`，即**外部**的
  `Android/data/<pkg>/hub`；与私有 `app_hub`（config / import / natives）是两处。找证据别找错地方。
- ⚠️ `am start` 对已在栈中的 `singleTop` Activity 只提示
  "intent has been delivered to currently running top-most instance"，**并不会把它抢到前台**。
  要把被游戏盖住的启动器带回前台，用 `am start -f 0x24000000`（`CLEAR_TOP|SINGLE_TOP`）。
