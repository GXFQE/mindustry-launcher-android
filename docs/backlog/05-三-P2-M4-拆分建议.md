# 三、P2：M4 拆分建议（回应"自动更新放缓"）

**同意放缓，但建议把它拆成两半 —— 难的只有一半。**

| | M4a 游戏版本更新 | M4b 启动器自更新 |
|---|---|---|
| 内容 | 下载游戏 APK → 登记为可用版本 | 换掉启动器自己的 exe（APK） |
| 难度 | **低** | **高** |
| 为什么 | ★ **M1 的 `Importer` 已经做完了 90%**（流式拷贝 + zip/version.properties 校验 + 预热预检 + 只读落盘 + 配置登记）。要新增的只有：下载器 + 版本源表 + 镜像前缀 | PackageInstaller 四道闸门 + 已知的回调坑 |
| 风险 | 低（复用已验证路径） | ★ **必须先换正式签名密钥**（见下） |

⇒ **"自动更新放缓" ≠ "版本更新放缓"**：M4a 可以立刻做，M4b 慢慢来。

⚠️ **M4b 的两个硬约束（别忘）**：
1. **签名密钥必须先换成正式的** —— 四道闸门里有"签名一致"，
   现在还是 debug.keystore，**一旦发布过自更新就换不了了**（换了老用户收不到升级）。
2. **包名 `io.mdt.launcher` 已实质定稿** —— 数据根绑定包名，M1 用户一旦产生数据就改不得。
