# 参考与对照（只收已经进了产品的）

> **收录标准**：只写「已经实现的功能」用到 / 拿来做判据的外部项目。
> 只做过可行性、只讨论过、或功能还没做的 —— **不写**，等它真的进产品再补。
> 用户 2026-10-29 的原话：「只考虑目前已经做了的功能……完全没做的先不写（等做了后再写）」。
>
> 与 Credits 的分工：Credits 回答"用了谁的东西 / 支持谁"，这里回答"拿谁当过判据 / 对照"。

## 加一条之前先答三个问题

1. **哪条已实现的功能**用它当过判据 / 参照？（答不出来 ⇒ 不写）
2. **取用了什么**：代码 / 资源 / 接口层 / 只有行为结论？（决定它该进 Credits 还是这里）
3. **许可**：现场核过没有？（`ref/42` 的教训：arc 的 Apache-2.0 曾被写成 GPL，靠"同一作者 = 同一许可"的推断）

## 纪律

1. **只收已实现的**：没做的不占位；做了再补，补的时候写清"哪条功能拿它当了什么"。
2. **只读思路 / 判据，不取代码**：GPL / AGPL 项目尤其如此。
3. **许可事实现场验**：没核过的一律写"未核"。
