# MDT 启动器 —— 用户自带翻译文件（设计稿 / 成本定案）

> 状态：**只读研究稿，未改动任何产品代码**（2026-10-07）。
> 与 [`i18n-feasibility.md`](i18n-feasibility.md) 的分工：那份是 **2026-10-04 那次改造（P0~P3）的可行性研究**
> （当时的问题是"怎么把默认语言从中文翻成英文 + 应用内可切语言"，已落地）。
> **本文只回答一个新问题：能不能让用户自己传一份翻译文件进来？代价多少、边界在哪。**
> 所有数字都是**本次现场实测**（设备 HONOR ELP-AN00 / Android 16，官方 v159.7 APK，本机源码），
> 不是推算。凡未验证的都标了「未实测」。

---

## 0. 摘要（给决策看的十行）

1. **能做**，但**没有捷径**：Android 的文案资源是**编译期产物**（`resources.arsc`），
   用户给的 `.properties`/`.xml` 是**源码形态**，系统**不认** ⇒ 必须自己造一层"用户包优先、系统资源兜底"的查表。
2. 真实改动面是 **1452 处 `R.string.*` 引用**（不是"1077 条文案"那么少，也不是只有 `getString`）。
3. 其中 **515 处**能被纯正则批量吃下；**其余 ~900 处**要分形态处理，**约三分之一必须手工**。
4. **批量替换之所以危险**：替换错了（键名写错）**编译器和自检都抓不住** —— 自检语言钉在 `zh`，
   而 `Trans` 在"没有用户包"时**完全等价于 `getString`** ⇒ 1097 处全绿。必须有**元断言**兜底（§5）。
5. **不做**的部分要先说清，否则做完用户会问"为什么桌面图标还是英文"：`android:label`（桌面图标名 /
   最近任务 / 系统「应用信息」）由**系统按系统语言**解析，**用户包改不动**。
6. **推动力是"早晚要做，而且越晚越贵"**（用户 2026-10-07 原话：「这东西后面功能多了只会更麻烦」）：
   每加一轮功能就多几十个调用点 —— 第 119~121 轮那三轮就新增了贴图 / 朝向 / 预览相关的成批文案。
7. **性价比的现实建议**：**方案 A（编进 APK 发版）每多一套语言的成本极低**（译文件净 ~107 KB + 发版一次），
   且能覆盖**系统取的那几处**；**方案 B（用户自带）**贵 2 个数量级、覆盖面**反而更小**。
   若目标只是"多支持几门语言"，**A 更划算**；B 的价值只在"**不重新发版就能改文案**"。
8. 若决定做 B：**分两轮**（第 1 轮 `Trans` + dry-run 替换器 + 元断言夹具；第 2 轮真跑 + 修错 + XML 搬家 + 真机验）。
9. 有一条**已经存在**的同类机制可参照：**游戏自己**就支持外部语言包（`<槽根>/bundle`，见 §7），
   它是**运行期读 properties**，所以那边零成本 —— 但那**不是**启动器能直接借用的实现（资源体系不同）。
10. **建议的下一步**：先只做第 1 轮并**把 dry-run 报告贴出来**（每处改法 + 认不出的清单），
    看过再决定要不要真跑批量。

## 1. 现状盘点（全部实测）

### 1.1 机制（现在是怎么工作的）

| 层 | 事实 | 出处 |
|---|---|---|
| 资源 | `app/res/values/strings.xml` = **英文，1077 条**（唯一真源 / 兜底）<br>`app/res/values-zh/strings.xml` = **中文，1076 条** | 两份**键集完全一致**；差的那 1 条就是 `app_default_language`（`translatable="false"`，只放默认目录） |
| 语言从哪来 | `config.json` 的 **`app_language`**：`""` = 跟随系统 / `"en"` / `"zh"` | `Config.java:415`（键缺失 ⇒ 返回 `SYSTEM` = 空串） |
| 怎么生效 | `BaseActivity.attachBaseContext` 里 `LocaleMode.apply(cfg, lang)`（`SYSTEM` 时**一个字节都不改**）⇒ `createConfigurationContext` | `BaseActivity.java:52-62`、`LocaleMode.java:101-110` |
| 🔴 红线 | **不许 `Locale.setDefault()`** —— 会改 `:game` **进程**默认 locale，把玩家的游戏语言带跑 | `LocaleMode` 类注释；§五 |
| 顶栏特例 | `Activity.mTitle` 由**框架按系统语言**解析，我们包的 Configuration 管不到 ⇒ `applyLocalizedTitle()` 重取 | `BaseActivity.java:87-95` |
| 门禁 | `tools/i18n-check.py`（RES-01~13 + SRC-01/02，全查**源码 XML**）+ `i18n-java-budget.txt` | 两者都是**构建期**，运行期**无任何校验** |

## 2. 为什么没有捷径（两条近路都堵死）

| 近路 | 为什么不通 |
|---|---|
| 让 Android 自己认用户文件 | `AssetManager.addAssetPath` 只吃**编译过的资源表**（`resources.arsc`）。用户给的 `.properties`/`.xml` 是**源码形态** —— 要让系统认就得在设备上跑 `aapt2`，而 Android 上没有 |
| 走 `values-xx/` 多语言目录 | 那是**构建期**输入，装完就固定了。多一套语言 = **重新发版**（这就是"方案 A"） |
| 只改 `Util.bindAction` 那类"喂 resId 给 TextView"的点 | 覆盖面只有 31 处。弹窗那 165 处吃不到（`AlertDialog.Builder` 是框架 API） |
| 复用游戏那套（`I18NBundle` + properties） | 游戏的文案**本来就是 properties**，且它有自己的加载器；启动器的文案在 `resources.arsc` 里，**两套体系不通用** |

⇒ **结论：只能自己造查表层**（`Trans.get(ctx, resId)`，顺序 = 用户包 → 系统资源）。

## 3. 方案 A vs 方案 B（成本 / 覆盖面）

| | **A. 把语言编进 APK** | **B. 用户自带翻译文件** |
|---|---|---|
| 谁提供译文 | 我们（收 PR / 自己翻） | 用户 / 第三方 |
| 流程 | 加 `res/values-xx/` ⇒ 门禁 ⇒ 发版 | 用户丢一份文件进去，**不重新发版** |
| 改动量 | **≈ 0**（门禁已有 RES-10 保证名单↔目录一致） | **42 文件 / ~900 处逐点 + 25 处 XML 搬家 + 新门禁 + 防崩层** |
| 体积成本 | 每套语言 **净 ~107 KB 源文**（进 APK 后更小；`i18n-feasibility.md` §2.5 当年实测口径为 **≈11 KB/语言**，**两口径不一致，需复核**） | 0（在用户设备上） |
| 覆盖面 | **全部**，含系统取的那几处（桌面图标名 / 最近任务 / 系统「应用信息」） | **只有界面内部**；`android:label`、25 处 `@string/` 布局、系统「应用信息 → 语言」都够不到 |
| 首次生效 | 装完即时 | 需要"何时重新查表"的口径（见 §5 坑 2） |
| 主要风险 | 要发版 | 占位符类型不符 ⇒ **主进程崩**（§五 第 112 轮真踩过）；批量替换错无法被自检抓住 |

**⚠️ 关键判断**：如果目的只是"**多支持几门语言**"，**A 的成本低两个数量级、覆盖面还更大**。
B 的独特价值只有一条：**不重新发版就能改 / 加文案**。

## 4. 若做 B：落地形态（概念设计）

```
Trans.get(ctx, resId)  →  ① 用户包（properties）按【键名】命中？ → 命中即返回（并 format 参数）
                          ② 否则 ctx.getString(resId)      ← 系统资源兜底（含 values-zh/）
```

必须解决的五件：

1. **resId → 键名**：`getResources().getResourceEntryName(resId)`，**要缓存 + try/catch**
   （1097 处的热路径；且 `0x7f…` 里混着非 string 资源时会抛）。
2. **用户包的加载时机与作用域**：全局（一份）还是按槽（与 mods/存档同口径）？**建议全局一份 + 可切语言**，
   但"何时重新查表"要有明确口径（进程启动时加载一次 vs 每次查询都看）。
3. **占位符防崩（硬需求，不是可选项）**：装包时**逐条比对**英文包同一 key 的占位符形态
   （序号 + 类型 `s/d/f` + 个数），**不匹配就拒绝装**。理由：`%2$d` 收到字符串 = 主进程崩。
4. **门禁**：`i18n-check.py` 查的是**源码 XML**，用户包是**运行期**的 ⇒ 需要新增一个校验器
   （键集 ⊆ 默认目录？占位符一致？），**同时用于装包时和自检夹具**。
5. **"改不动"的边界要写进界面文案**（见 §6）。

## 5. 批量替换的三个真坑（这是"不能一把梭"的原因）

**坑 1：34 个文件里没有 `this` 可用。**
不是 Activity 的那些：`Backup`(34) · `Mods`(48) · `SlotIo`(58) · `SlotOps`(53) · `MapFiles`(24) ·
`Storage`(23) · `MapStatsMods`(17) · `ModsText`(37) · `MsavText`(45) · `MschText`(21) · `SettingsText`(17) ·
`TrashText`(24) · `CasText`(8) …（`getString` 是从**参数传进来的 `ctx`** 调的）
⇒ 正则得分两组模式（`getString(` vs `ctx.getString(`）。

**坑 2：16 个文件里有后台线程 / `runOnUiThread`。**
替换后 `Trans.get` 比 `getString` 多碰一次对象（查表 + 缓存）⇒ 原来的 `Util.dead(a)` 纪律要**重新核一遍**。

**坑 3（最危险）：批量替换的错误编译器和自检都抓不住。**
- 编译器抓得住：类型不符 / Context 不在作用域 ⇒ 报错，好办（**编译错误本身就是免费的定位器**）
- **抓不住**：把 `R.string.x` 换成 `Trans.get(ctx, R.string.y)`（键名写错）⇒ 界面显示**另一句合法文案**。
  而自检语言钉在 `zh`、`Trans` 在无用户包时**完全等价于 `getString`** ⇒ **1097 处全绿**。
- ⇒ **必须有元断言**：夹具塞一个**只提供 `R.string.x` 一个键**的用户包，要求**只改变那一句**、
  其它 1000+ 处**逐字不变**。没有这条，"批量替换"不可验收。（§五「判据对 ≠ 清单全」同族）

### 替换器的强制纪律（§五 事故红线）

2026-10-03 真发生过：脚本搬源码时"找块尾锚点失败 ⇒ `$out` 为 null ⇒ 仍然 `WriteAllText`"⇒
**把 1450 行的 `SavesActivity.java` 写成 0 字节**。⇒ 替换器必须：

1. **默认 dry-run**：逐处输出 `文件:行 → 改法`，并**跳过并列出**所有认不出的形态
2. **先 `Copy-Item $p "$p.bak"`**，落盘前断言：文本非空 / 含预期标记 / **替换处数与 dry-run 对得上**
3. **按文件应用 + 逐文件编译**；编译失败 ⇒ `git checkout -- <该文件>`（**不要**用 `git show > 文件`，会改编码）
4. **永远不要无条件打 ✅**

## 6. 明确不做 / 做不到的（写进报告免得以后反复讨论）

| 项 | 结论 | 原因 |
|---|---|---|
| 桌面图标名、最近任务、系统「应用信息」里的应用名 | 🚫 用户包改不动 | `android:label` 由**系统按系统语言**解析 |
| 系统「应用信息 → 语言」那个入口 | 🚫 目前没有 | 清单无 `localeConfig` + 本工程**纯 framework、零 AndroidX**（拿不到 `AppCompatDelegate.setApplicationLocales`） |
| 25 处布局 XML 的 `@string/` | ⚠️ 要么搬进 Java，要么接受"这 25 处不跟随" | 布局里的引用由 Android 自动解析 |
| `SelfTest.java` 的 188 处 | 🚫 不动 | 自检语言钉 `zh`，且它自己就是"文案当判据"的教训所在地 |
| 游戏侧文案（矿物名 / 方块名 / 剧情） | 🚫 不在本项目范围 | 归游戏自己的 bundle（见 §7） |
| 模组名 / 描述 | 🚫 只透传 | 模组作者自己提供 |
| RTL（阿拉伯语等） | 🚫 建议不做 | `i18n-feasibility.md` §4.4 已有定论 |

## 7. 附：游戏侧已经存在的同类机制（可参照，但**不能**直接借用）

> 游戏是**运行期读 properties**，所以它**原生支持**用户自己塞语言包 —— 零成本。
> 启动器是**编译期资源**，所以这套体验**没法平移到启动器**。放在这里是为了：
> ① 说明"运行期查表"这条路在别处是成立的；② 免得以后有人以为可以照抄。

官方 v159.7 APK 实测：

| 项 | 事实 |
|---|---|
| 语料 | `assets/bundles/bundle.properties`（英文 = 缺省）+ `bundle_<语言>.properties`，**共 36 份 / 6.76 MB** |
| 语言清单 | `assets/locales`（127 B，一行一个码，**不含 en**）：be bg ca cs da de es et eu fi fil fr **global** hu id_ID it ja ko lt nl nl_BE pl pt_BR pt_PT ro ru sr sv th tk tr uk_UA vi zh_CN zh_TW |
| 格式 | `key = value`；占位符 **`{0}`**（不是 `%1$s`）；颜色标记 **`[accent]…[]`** |
| 外部语言包 | `Core.files.local("bundle")`（**数据根目录下名为 `bundle`、无扩展名的文件**）存在即生效；成功提示 `bundle.external` = 「注意：外置语言包已成功加载。」 |
| 落点 | `= <槽根>/bundle`（`Vars.dataDirectory = settings.getDataDirectory()`，Android 上被设为 `Core.files.local("saves/")`）⇒ **天然逐槽隔离** |
| 读不到时 | 回落内置：`settings.bin` 的 `locale`（`"default"` ⇒ `Locale.getDefault()`）+ `Locale.setDefault()` |
| 源码 | 本机副本 `.tmp-msch-lab/_src/Vars.java` 的 `loadLocales()` |

⚠️ 顺带（与启动器红线的因果关系）：游戏在这条路上**自己会调 `Locale.setDefault()`**，
而它的输入是 `Locale.getDefault()` = **进程默认 locale** = 启动器给 `:game` 进程那份 Configuration 的 locale 位。
这正是**启动器不许自己调 `Locale.setDefault()`** 的原因 —— 一调就把玩家的游戏语言带跑。

## 8. 成本定案与分轮建议

| 轮 | 内容 | 交付 / 可验证的东西 |
|---|---|---|
| **1** | `Trans.get`（键名反查 + 缓存）+ 用户包加载 + 装包校验（占位符/键集）+ 改 `Util.java` 6 个函数 + **dry-run 版替换器** | **dry-run 报告**（每处改法 + 认不出的清单）+ 动作行/标题跟着用户包变 + `SelfTest` 仍全绿（855） |
| **2** | 真跑批量（按文件 + 逐文件编译 + 失败即回滚）+ 手工收尾弹窗 165 处与"其余形态"约 1/3 + 25 处 XML 搬家 | 编译通过 + 自检不红 + **元断言**（单键用户包只改那一句） |
| **3**（可并进 2） | 新门禁（包 ↔ 默认目录 键集/占位符）+ 自检断言 + README 两份 + 真机验 | 缺键包 / 错占位符包必须被**拒**（含反证） |

**估算：2 轮（含手工收尾），风险前 60% 集中在第 2 轮。**

> ⚠️ 报成本时必须一起说的两句：
> ① 用户包**只覆盖界面内部**（§6 那几处改不动）；
> ② 若目标只是"多支持几门语言"，**方案 A 便宜两个数量级且覆盖更全** —— 先确认真实目的再动手。

## 9. 待复核 / 未实测（诚实清单）

1. **每套语言的 APK 体积成本，两个口径不一致**：本文现场估"净 ~107 KB 源文"，
   `i18n-feasibility.md` §2.5 当年写"**≈ 11 KB**"。**必须复核**再做"要不要多加语言"的决策
   （复核办法：`aapt2 dump resources` 逐 config 统计 string 池，或构建"只带 en"与"带 en+zh"两个包对比产物大小）。
2. **`Trans` 的加载时机**（进程启动一次 vs 每次查询）对"改完文件要不要重启启动器"的影响 —— 未实测。
3. **用户包与 `values-zh/` 的优先级**：用户包命中即返回，则"用户包 + 中文系统"下用户包优先（**建议如此**，但要写清）。
4. **34 个非 Activity 文件里 `ctx` 的作用域**：dry-run 才能给出真实数字（本文只给了文件清单与处数）。
